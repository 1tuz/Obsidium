# Состав и архитектура Obsidium

Снимок исходников репозитория на 2026-10-10. Это runtime-обзор приложения и основных точек входа; CI, упаковка, документация и поставляемые ресурсы перечислены как контекст, но не разложены на отдельные узлы.

## Обзор

Obsidium — локальное desktop-приложение Tauri v2. UI на TypeScript/Preact общается с Rust через Tauri IPC: команды идут в адаптер `aquilum-app/src-tauri`, который вызывает общий crate `aquilum-core`; события Core возвращаются UI через Tauri event bridge. CLI использует тот же Core напрямую и умеет работать headless, в том числе предоставляя MCP stdio.

`aquilum-core` не зависит от UI-хоста. Он объединяет документы, работу с файлами и watcher, историю, настройки, состояние интерфейса, индекс поиска и графа, MCP, wikixiv и web agent. Markdown-файлы в выбранных пользователем workspace остаются главным хранилищем заметок. Служебные настройки, UI-state, CRDT-реплики и поисковые индексы лежат в app data; версии заметок хранятся в `.aquilum/history` внутри workspace.

## Основные части

| Часть | Ответственность | Основание |
|---|---|---|
| UI | Окно, редактор, workspace, панели и пользовательские функции; загрузчики модулей вызывают native-команды | `aquilum-app/src/main.tsx`, `src/App.tsx`, `src/modules/`, `src/components/` |
| Tauri host | Жизненный цикл окна, плагины и регистрацию `invoke` команд; передача событий Core во frontend | `aquilum-app/src-tauri/src/lib.rs` |
| Core | Хост-независимое ядро, сводящее сервисы и события приложения | `aquilum-app/core/src/lib.rs`, `core/src/app_core.rs` |
| Документы и файлы | CRDT-сессии, безопасная запись Markdown, rename/trash и согласование внешних изменений | `core/src/documents/`, `core/src/files/` |
| Поиск и граф | Индексация workspace, поиск, backlinks, Dataview, граф ссылок и анализ | `core/src/search/` |
| Состояние и история | Настройки и UI-state в app data; версии заметок — в `.aquilum/history` workspace | `core/src/settings/`, `core/src/ui_state/`, `core/src/history/store.rs` |
| MCP и внешние функции | MCP по stdio и loopback HTTP; Wikixiv и получение заголовков страниц | `core/src/mcp/`, `core/src/wikixiv/`, `core/src/link_title/`, `core/src/web_agent.rs` |
| CLI | Headless-команды, обращающиеся к тому же Core без Tauri UI | `aquilum-app/cli/src/main.rs` |

## Ключевые потоки

1. **Запуск desktop:** Tauri получает app-data directory, запускает миграцию, создаёт `Core`, применяет настройки MCP и регистрирует его в состоянии приложения (`src-tauri/src/lib.rs`).
2. **Вызов UI:** UI вызывает зарегистрированные команды через Tauri IPC; host-команда делегирует в `aquilum-core`. Core-события преобразуются в Tauri events и слушаются frontend.
3. **Открытие и сохранение заметки:** файловые операции и `DocumentHub` работают с Markdown в workspace; Yjs/yrs реплика хранится отдельно, а конфликт внешней записи согласуется по sync point/hash и диффам.
4. **Внешнее изменение workspace:** `WorkspaceWatcher` передаёт изменения в `Core`; Core просит документы согласовать пути, сообщает UI об изменениях дерева и отправляет пути в индексатор.
5. **CLI/MCP:** CLI создаёт headless Core и выполняет команды; MCP может обслуживаться через stdio или локальный HTTP endpoint, включаемый настройкой.

## Данные и владение

- Workspace Markdown — пользовательский источник истины для содержимого заметок.
- App data: `settings.json`, `ui-state.sqlite3`, `documents.sqlite3`, `search-v2/` и store CRDT. Путь задаёт хост; Tauri использует системный app-data directory.
- Tantivy индекс и SQLite metadata под `search-v2/` производны от workspace и могут пересобираться.
- История заметок принадлежит workspace и находится в `.aquilum/history`; настройки и UI-state используют app data.
- UI использует backend-хранилища для долговременного состояния; браузерное состояние не является главным хранилищем приложения.

## Hotspots и риски изменений

- `Core` — composition root и центральный координатор событий между watcher, документами, поиском и хостом; изменение его event contract затрагивает оба адаптера.
- Tauri `invoke_handler` и frontend gateway/подписки образуют парный контракт по именам команд и событий.
- Markdown запись, Yjs реплики и reconciliation — граница сохранности данных; изменение должно сохранять минимальные диффы и разрешение конфликтов.
- Search index обслуживает поиск, ссылки, Dataview и граф; изменение схемы/индекса затрагивает несколько UI-функций и фоновые задачи.

В просмотренном runtime-контуре критических или высоких архитектурных проблем не подтверждено. `Core` и search — важные узлы по fan-in и числу функций; сами по себе они не свидетельствуют о дефекте.

## Границы и пробелы доказательств

- Подтверждённые рёбра отражают вызовы в исходниках. Схема не раскрывает внутренние вызовы каждого feature-модуля UI.
- `web_agent` и запросы заголовков страниц имеют HTTP-зависимости, но их удалённые адреса зависят от настроек/входных данных; на диаграмме они сведены к внешнему web.
- Репозиторий содержит vendor `foliate-js`, scripts, knowledge base, GitHub Actions и ресурсы. Это состав исходников и доставки, а не runtime-компоненты схемы.
- Рабочая копия уже содержит многочисленные незакоммиченные изменения пользователя; обзор выполнен чтением файлов и не связывает найденные компоненты с авторством или текущей веткой.

## Проверка схемы

- Logical confidence: High для основных границ UI → Tauri → Core → данные; Medium для сгруппированных внешних web-вызовов.
- Evidence gaps: точные удалённые endpoint'ы `web_agent` зависят от конфигурации; точный состав изменённой рабочей копии не отражён.
- Simplifications: подробные UI-компоненты, внутренние части поиска и хранения объединены по ответственности; CI/release не включены в runtime view.
- Readability review: схема разделена на три зоны и восемь основных связей; геометрическая проверка не нашла пересечений и выходов за границы. Визуальный просмотр в браузере не выполнен: CUA отклонил локальный `file:` URL, а его политика запрещает обход через альтернативные браузеры или локальный HTTP.
