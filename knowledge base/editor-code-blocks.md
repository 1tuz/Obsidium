# Блоки кода в редакторе Obsidium

Статус: актуально на 2026-11-04.

## Назначение

Огороженный блок (` ```lang `) и блок с отступом отображаются подсветкой синтаксиса
прямо в редакторе. Код остаётся обычными строками CodeMirror: каретка, выделение, undo,
Yjs, поиск по странице и навигация работают нативно. У огороженного блока есть отдельная
панель языка и копирования; она не заменяет и не перезаписывает тело блока.

Заборы ` ``` ` и строка языка скрываются по-разному в режимах редактирования и чтения. При редактировании применяется `shouldRevealSyntax`: маркеры показываются, когда каретка стоит на соответствующей строке ограждения. В режиме чтения (`EditorView.editable=false`) непустые ограждения скрываются всегда, чтобы исходные маркеры не оставались видны до клика. Скрытие делает `Decoration.replace({ block: true })` на всю строку в `decorations.ts`; `CodeMark` остаётся владельцем плоских маркеров live preview, а `CodeInfo` на скрытой строке не мешает, потому что строка заменяется целиком. Пустой блок (`contentFrom >= contentTo`) остаётся сырым: в нём нет диапазона содержимого, на который можно перенести каретку.


Отдельная панель для целых файлов кода (`.py`, `.rs`, `.yaml` и другие) описана в
[[editor-code-viewer]]: там тот же набор классов токенов, но другой редактор и другие расширения.

## Основные файлы

- `extensions/codeBlock/blocks.ts` — где в документе блоки (`codeBlocks`), строка языка
  из `CodeInfo`, распознавание забора (`isFenceMark`)
- `extensions/codeBlock/languages.ts` — строка языка → `LanguageDescription`
- `extensions/codeBlock/grammars.ts` — загрузка грамматики и перепарс документа
- `extensions/codeBlock/decorations.ts` — `Decoration.line` на видимые строки, скрытие заборов,
  блочная панель
- `extensions/codeBlock/controls.ts` — выбор языка и копирование тела блока
- `extensions/codeBlock/highlight.ts` — классы токенов для `syntaxHighlighting`
- `extensions/codeBlock/theme.ts` — фон, скругления, цвета токенов
- `extensions/codeBlock/index.ts` — `ViewPlugin` пересобирает декорации и панель, два
  `StateField` держат их в состоянии

## Откуда берётся подсветка

`markdownConfig.ts` передаёт `codeLanguages: languages` — весь `@codemirror/language-data`.
Токены рисует штатный `TreeHighlighter` из `@codemirror/language`: он пересобирает
mark-декорации при каждой смене дерева или вьюпорта. Своего `highlightTree` у блока нет —
ручная отрисовка токенов означала бы, что подсветку нужно перерисовывать вручную, а это
уже реализовано в CodeMirror и работает инкрементально.

## Почему нужен `CodeGrammarLoader`

Грамматики в `@codemirror/language-data` подключаются асинхронным `import()`. На первом
разборе документа `@codemirror/lang-markdown` подставляет
`ParseContext.getSkippingParser(desc.load())`: содержимое блока остаётся плоским `CodeText`,
токенов нет вообще. Смонтировать грамматику может только повторный разбор.

Полагаться на то, что повторный разбор случится сам, нельзя. `ParseWorker` планирует работу
через `scheduleWork()`, а тот выходит сразу, если работа уже в полёте (`if (this.working) return`).
Промис загрузки грамматики разрешается один раз, `checkAsyncSchedule` его к этому моменту уже
забрал, и если `scheduleWork()` попал в занятый воркер, а текущий проход завершился с
`done = true`, будить воркер больше нечему. Дерево остаётся без грамматики до следующей правки
документа — снаружи это выглядит как «подсветка появляется, только если тронуть блок».

Поэтому блок кода загружает грамматику сам:

1. `sync()` для каждого видимого блока получает `LanguageDescription` по строке языка;
2. если `desc.support` ещё не заполнен — вызывает `desc.load()` (один раз на язык) и по
   разрешению промиса зовёт `forceParsing`;
3. если грамматика уже загружена, но в дереве на месте кода всё ещё `CodeText`
   (`isGrammarMounted`) — тоже зовёт `forceParsing`. Этот случай возникает, когда блок был
   разобран до загрузки грамматики и попал во вьюпорт позже.

`forceParsing` вызывается через `queueMicrotask`: транзакцию нельзя отправлять изнутри
`ViewPlugin.update`. Повторный вызов на одном и том же дереве заблокирован полем
`forcedTree`, поэтому цикл не может закрутиться, если монтировать нечего.

## Вёрстка блока

Фон блока лежит на `::before` строки с `z-index: -2`, а не на самой `.cm-line`. Причина:
`drawSelection` рисует выделение в слое `.cm-selectionLayer` с `z-index: -1` внутри
контекста наложения `.cm-scroller`. Непрозрачный фон на самой строке закрывает этот слой —
выделение пропадает внутри блока и видно только за его пределами.

Отступ у блока один на все стороны — `--q-block-padding`. По горизонтали он
на каждой строке блока, по вертикали — на первой и последней (`--first` / `--last`), они же
несут скругления.

Обводка лежит на том же `::before`: `border-inline` у каждой строки, `border-top` у первой,
`border-bottom` у последней. Блок — это не один элемент, а стопка строк, поэтому `box-shadow` или
`border` целиком дали бы горизонтальную линию между каждой парой строк. Фон, обводка и скругление —
общие токены карточек `--q-block-*` ([[design-tokens]]).

Тег `CodeText` в `@lezer/markdown` помечен как `monospace`, поэтому `markdownStyles` вешает
на текст блока класс `.q-md-code` — тот же, что на инлайн-код. Внутри строки блока этот
класс обнуляется (`padding`, `border-radius`, фон), иначе поверх фона блока рисовалась бы
плашка инлайн-кода. Общий `codeHighlightTheme` задаёт цвета синтаксических классов через
токены `--q-editor-code-*`. Они используются в fenced-блоках
Markdown и обычных текстовых файлах. Для выбранной палитры оттенки синтаксиса вычисляются из её
акцента в OKLCH с сохранением светлоты; светлая или тёмная тема задаёт контрастный акцент.
Тема чтения сохраняет собственные цвета кода.

## Перенос строк и ASCII-схемы

`codeBlockTheme` задаёт `white-space: pre-wrap` и `overflow-wrap: anywhere` для `.cm-line.q-md-code-line`. Пробелы, отступы и исходные переводы строк сохраняются; длинные строки, URL и идентификаторы без пробелов визуально переносятся в доступной ширине редактора. Короткие строки ASCII-схем сохраняют выравнивание, а длинные могут переноситься: иначе хвост кода уходил бы за край узкой области. Блок остаётся набором строк CodeMirror, поэтому в нём работают каретка, undo, поиск и Yjs без вложенного редактора. Переносы меняют только отображение: Markdown и CRDT не получают дополнительных переводов строк, копирование возвращает исходное тело без ограждений и визуальных переносов.

## Панель блока

Контролы добавляются блочным виджетом перед строкой открытия. CodeMirror запрещает блочные
декорации в источнике декораций `ViewPlugin` — он падает с «Block decorations may not be
specified via plugins», даже если это `Decoration.replace({ block: true })` на строку забора.
Поэтому в `StateField` живут оба набора декораций (строки и панель), а плагин пересобирает их
и передаёт эффектами после завершения обновления. Транзакцию нельзя отправлять изнутри
`ViewPlugin.update`, отсюда `queueMicrotask`. Пересборка идёт на doc, вьюпорт, дерево и
`update.selectionSet`.

`ViewPlugin.update` получает `ViewUpdate`; читать нужно `update.view.state`, а не `view.state`
из конструктора — иначе каретка, уехавшая через `dispatch`, читается как старая и забор
остаётся скрытым.

Список языков берётся из уже установленного `@codemirror/language-data`; он включает основные
языки без новых зависимостей, грамматики по-прежнему загружаются только для видимых блоков.
Дополнительно поддержаны короткие fence-алиасы `py` и `rs`. Выбор языка меняет только первый
токен `CodeInfo`, сохраняя следующие атрибуты. Для блока без языка значение вставляется перед
атрибутами.

Копирование берёт только диапазон содержимого между строками ограждения через
`copyText` из `modules/clipboard.ts` (Clipboard API, затем hidden textarea +
`execCommand('copy')`; подробности и причина — [[clipboard-copy]]). Лейбл кнопки переключается на `editor.codeCopied` /
`editor.codeCopyFailed` и откатывается через 1600/2400 мс; таймер не пишет в уничтоженный
виджет — тот же документ дополнительно пересчитывается сканером забора (`scanFence`) при
клике и в `updateDOM`, потому что виджет-декорация сдвигается транзакцией, а не пересоздаётся.
Инлайн-код и блоки с отступом панели не получают.

Заголовок панели — `padding` `var(--q-space-6) var(--q-space-8)`, разделитель
`border-bottom: 1px solid var(--q-block-border)`, верхние скругления карточки. Селект языка
ограничен `max-width: min(11em, 100%)` с `text-overflow: ellipsis`; у кнопки копирования есть hover-фон и
цветовые состояния `--copied` / `--failed` на `--q-text-success` / `--q-text-danger`.

Панель ограничена `max-width: 100%` с `box-sizing: border-box`, чтобы её отступы и обводка входили в доступную ширину. Flex-строка разрешает перенос контролов при нехватке места. Селект языка имеет `min-width: 0` и может сжиматься, а кнопка копирования сохраняет ширину и цельную надпись (`flex-shrink: 0`, `white-space: nowrap`): длинное название языка не должно вытеснять действие копирования. У блока без языка селект показывает `Plain text`, кнопка `Copy code` остаётся доступной.
