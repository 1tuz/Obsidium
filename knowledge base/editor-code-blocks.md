# Блоки кода в редакторе Aquilum

Статус: актуально на 2026-08-20.

## Назначение

Огороженный блок (` ```lang `) и блок с отступом отображаются подсветкой синтаксиса
прямо в редакторе. Блок кода — это **обычные строки CodeMirror**, а не виджет: каретка,
выделение, undo, Yjs, поиск по странице и навигация с клавиатуры работают нативно,
никаких вложенных редакторов и сессий не создаётся.

Внутри блока кода live preview выключен: заборы ` ``` ` и строка языка видны всегда,
поэтому между «режимом просмотра» и «режимом правки» разницы нет.

## Основные файлы

- `extensions/codeBlock/blocks.ts` — где в документе блоки (`codeBlocks`), строка языка
  из `CodeInfo`, распознавание забора (`isFenceMark`)
- `extensions/codeBlock/languages.ts` — строка языка → `LanguageDescription`
- `extensions/codeBlock/grammars.ts` — загрузка грамматики и перепарс документа
- `extensions/codeBlock/decorations.ts` — `Decoration.line` на строки блока
- `extensions/codeBlock/highlight.ts` — классы токенов для `syntaxHighlighting`
- `extensions/codeBlock/theme.ts` — фон, скругления, цвета токенов
- `extensions/codeBlock/index.ts` — `ViewPlugin`, связывающий всё вместе

## Откуда берётся подсветка

`markdownConfig.ts` передаёт `codeLanguages: languages` — весь `@codemirror/language-data`.
Токены рисует штатный `TreeHighlighter` из `@codemirror/language`: он пересобирает
mark-декорации при каждой смене дерева или вьюпорта. Своего `highlightTree` у блока нет —
ручная отрисовка токенов означала бы, что подсветку нужно перерисовывать вручную, а это
уже реализовано в CodeMirror и работает инкрементально.

## Почему нужен `CodeGrammarLoader`

Грамматики в `@codemirror/language-data` подключаются асинхронным `import()`. На первом
разборе документа `@codemirror/lang-markdown` подставляет
`ParseContext.getSkippingParser(desc.load())`: содержимое блока остаётся плоским `CodeText`,
токенов нет вообще. Смонтировать грамматику может только повторный разбор.

Полагаться на то, что повторный разбор случится сам, нельзя. `ParseWorker` планирует работу
через `scheduleWork()`, а тот выходит сразу, если работа уже в полёте (`if (this.working) return`).
Промис загрузки грамматики разрешается один раз, `checkAsyncSchedule` его к этому моменту уже
забрал, и если `scheduleWork()` попал в занятый воркер, а текущий проход завершился с
`done = true`, будить воркер больше нечему. Дерево остаётся без грамматики до следующей правки
документа — снаружи это выглядит как «подсветка появляется, только если тронуть блок».

Поэтому блок кода загружает грамматику сам:

1. `sync()` для каждого видимого блока получает `LanguageDescription` по строке языка;
2. если `desc.support` ещё не заполнен — вызывает `desc.load()` (один раз на язык) и по
   разрешению промиса зовёт `forceParsing`;
3. если грамматика уже загружена, но в дереве на месте кода всё ещё `CodeText`
   (`isGrammarMounted`) — тоже зовёт `forceParsing`. Этот случай возникает, когда блок был
   разобран до загрузки грамматики и попал во вьюпорт позже.

`forceParsing` вызывается через `queueMicrotask`: транзакцию нельзя отправлять изнутри
`ViewPlugin.update`. Повторный вызов на одном и том же дереве заблокирован полем
`forcedTree`, поэтому цикл не может закрутиться, если монтировать нечего.

## Вёрстка блока

Фон блока лежит на `::before` строки с `z-index: -2`, а не на самой `.cm-line`. Причина:
`drawSelection` рисует выделение в слое `.cm-selectionLayer` с `z-index: -1` внутри
контекста наложения `.cm-scroller`. Непрозрачный фон на самой строке закрывает этот слой —
выделение пропадает внутри блока и видно только за его пределами.

Отступ у блока один на все стороны — `--q-block-padding`. По горизонтали он
на каждой строке блока, по вертикали — на первой и последней (`--first` / `--last`), они же
несут скругления.

Обводка лежит на том же `::before`: `border-inline` у каждой строки, `border-top` у первой,
`border-bottom` у последней. Блок — это не один элемент, а стопка строк, поэтому `box-shadow` или
`border` целиком дали бы горизонтальную линию между каждой парой строк. Фон, обводка и скругление —
общие токены карточек `--q-block-*` ([[design-tokens]]).

Тег `CodeText` в `@lezer/markdown` помечен как `monospace`, поэтому `markdownStyles` вешает
на текст блока класс `.q-md-code` — тот же, что на инлайн-код. Внутри строки блока этот
класс обнуляется (`padding`, `border-radius`, фон), иначе поверх фона блока рисовалась бы
плашка инлайн-кода. Цвета токенов заданы селекторами вида
`.cm-line.q-md-code-line .q-code-keyword`, чтобы специфичность гарантированно перебивала
`color` из `.q-md-code`, а не зависела от порядка правил.

## Горизонтальный скролл

Своего скроллера у блока нет: длинные строки переносятся глобальным
`EditorView.lineWrapping`, как в режиме редактирования Obsidian. Отдельный скроллер требует
`Decoration.replace` с виджетом, а виджет не может держать настоящую каретку — вход каретки
пришлось бы обслуживать вложенным `EditorView` со своей историей undo и без подключения к
Yjs. Скролл всего редактора тоже не вариант: `extensions/theme.ts` намеренно ставит
`overflow-x: clip` на главный `.cm-scroller`.

## Замысел: виджеты внутри блока кода (не реализовано)

Планируется аналог dataview на Rust: блок с особой строкой языка должен заменяться таблицей
или виджетом. Для этого `codeBlocks` уже отдаёт `info` — строку языка — так что отдельное
расширение сможет отобрать «свои» блоки по ней и заменить их `Decoration.replace` из
`StateField` (блочные декорации из `ViewPlugin` CodeMirror не принимает). Кода для этого
сейчас нет.
