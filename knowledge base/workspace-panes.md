# Панели рабочего пространства

## Связанные документы

- [[tab-switching]] — активные редакторы, навигация и LRU для вкладок.
- [[workspace-switching]] — границы сессии и per-window кэш.
- [[document-lifecycle]] — общий `Y.Doc` и запись исходного Markdown.

## Владение состоянием

`TabsState.layout` — двоичное дерево: лист хранит `paneId` и активный `tabId`, узел — направление и долю первой ветви. `paneLeaves` и функции изменения дерева лежат в `src/modules/panes/layout.ts`; `tabsReducer` остаётся единственным владельцем связки layout, tab ownership и активной вкладки. Максимум — четыре листа.

Панель владеет своими вкладками, но не документом. При явном Split вкладка клонируется с новым `tabId`; обе вкладки ссылаются на тот же `documentId`/`Y.Doc`. Открытие одного пути в панели не создаёт дубль внутри неё. Перенос во вторую панель допускает такой дубль, чтобы один документ можно было сравнивать в двух позициях.

Закрытие последней вкладки листа оставляет пустую вкладку. Закрытие панели переносит её вкладки в соседнюю ветвь и схлопывает узел; одинаковые пути в целевой панели объединяются. Удаление файла закрывает все его открытые копии.

## Сохранение и восстановление

UI-state SQLite schema 10 добавляет `tabs.pane_id` и `sessions.layout_json` в уже существующую базу. Отдельной БД нет. Layout и полный список вкладок пишутся одним `save_ui_state_batch`; одно изменение активной вкладки или геометрии layout не переписывает список tabs. Старые записи мигрируют в один лист `main`.

Backend проверяет дерево, уникальность `paneId`, принадлежность активных вкладок листам и лимит в четыре панели. Повреждённое дерево восстанавливается одним `main`; повреждение не должно терять документы. Отсутствующий файл очищает активную вкладку только своего листа. Если все сохранённые документы пропали, каждый лист получает пустую вкладку и геометрия остаётся.

Вид CodeMirror уже хранится по `(documentId, paneId)`. Это сохраняет отдельные позиции курсора и прокрутки одной заметки в двух панелях без копии документа или дополнительного индекса. Каждая активная Markdown-вкладка листа закреплена в live-наборе редакторов; настройка «Вкладок в памяти» ограничивает только LRU-фоновые редакторы сверх активных панелей.

`localStorage`-кэш вкладок остаётся только ускорителем первого рендера и разделён по окнам. Источник истины — SQLite. Кэш предыдущей версии читается как один `main`; malformed layout игнорируется, после чего сессия восстанавливается из backend.

## UI и включение

`PaneLayoutView` рисует дерево и интерактивные разделители. Внутренний pointer drag повторно использует `useTabStrip`: перестановка остаётся pane-local, отпускание над другим листом переносит tab по `tabId`. Это не использует браузерный HTML5 drag-and-drop, которое конфликтует с нативным перетаскиванием файлов Tauri на Windows.

Split создаёт второй вид текущей заметки рядом или ниже; размер ограничен 10–90%, мышь и стрелки клавиатуры меняют долю. Кнопки вкладок отображаются только у сфокусированного листа. Ctrl/Cmd+F слушает только глобально выбранная вкладка, а каждый видимый редактор сохраняет собственный CodeMirror-фокус и состояние.

`settings.builtins.panes` управляет показом многопанельного режима. При выключении остальные листы временно скрываются; layout и вкладки сохраняются, повторное включение возвращает прежнюю раскладку. Параметр сериализуется в существующий `settings.json` и имеет включённое значение по умолчанию.

## Проверки при изменении

- `modules/panes/layout.test.ts` — split, collapse, resize, отсутствие мутации исходного дерева.
- `modules/ui-state/tabReducer.test.ts` — ownership, закрытие, перенос, дубли, restore и предел панелей.
- `modules/ui-state/workspaceSession.test.ts` и `workspaceViewState.test.ts` — batch persistence и раздельный вид одного документа.
- Rust `ui_state::` тесты — schema 9→10, повреждённый layout, пропавшие файлы, предел панелей и атомарный rollback.
- `npx tsc --noEmit` и целевые UI-тесты App/Titlebar/Builtins.
