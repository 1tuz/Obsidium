# Дневные заметки (Journal)

## Связанные документы

- [[note-templates]] — обычные шаблоны заметок и их подстановка `{{date:…}}`; дневные заметки используют собственный, более узкий набор плейсхолдеров.
- [[graph-view]] — лестница источников даты создания: `created` из frontmatter сильнее файловых дат.

## Что это

Дневная заметка — обычный Markdown-файл в базе знаний, имя которого является датой. Отдельного хранилища, базы или формата нет: заметка живёт на диске рядом с остальными и индексируется общим поиском. Ядро умеет три вещи без участия UI:

- построить путь заметки на конкретную дату (`note_path`);
- открыть сегодняшнюю заметку, создав её при первом обращении (`today`);
- перечислить даты, для которых заметки уже существуют (`list_dates`).

Плюс чистая функция `link_target` для ссылки на день.

Модуль не знает про Tauri и UI: это функции ядра, которые получают корень базы знаний и секцию настроек. IPC-команды и интерфейс подключаются отдельно.

## Где лежат заметки

Путь: `<корень базы знаний>/<journal.folder>/<имя по journal.dateFormat>.md`.

По умолчанию это `journal/2026-10-25.md`. Папка создаётся при первом создании заметки; если её нет, `list_dates` просто возвращает пустой список и ничего не создаёт.

`journal.folder` — путь относительно корня базы знаний. Вложенность разрешена (`Journal/Daily`), абсолютные пути и `..` отклоняются ошибкой настроек: журнал обязан оставаться внутри базы, иначе заметка выпадет из индекса и ссылок.

## Настройки

Секция `journal` в `settings.json` (`core/src/settings/models.rs`):

```json
{
  "journal": {
    "folder": "journal",
    "dateFormat": "YYYY-MM-DD",
    "templatePath": null
  }
}
```

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `folder` | `journal` | Папка журнала относительно корня базы знаний |
| `dateFormat` | `YYYY-MM-DD` | Формат имени файла |
| `templatePath` | `null` | Шаблон новой заметки относительно корня базы знаний |

Секция объявлена с `serde(default)`, как остальные: старый `settings.json` без `journal` читается без ошибок и получает значения по умолчанию. Неизвестные поля в файле не мешают.

### Почему папка и формат настраиваемы

Базы знаний приходят из Obsidian и других редакторов, где ежедневные заметки уже лежат в своей папке и названы своим форматом. Жёстко зашитый `journal/YYYY-MM-DD` заставлял бы пользователя либо переименовывать существующие файлы, либо держать два журнала. Настройка папки позволяет подключиться к уже существующему журналу, настройка формата — сохранить привычный вид имён (`DD.MM.YYYY`, `YYYY.MM.DD`) и порядок сортировки в файловом менеджере.

Формат имени, а не отдельная настройка «как показывать дату», выбран потому, что имя файла и есть идентификатор дня: `list_dates` восстанавливает дату обратным разбором имени. Показывать одну дату, а хранить другую — значит держать два источника правды.

### Допустимые токены

Поддерживаются ровно три токена, каждый фиксированной ширины, и каждый должен встречаться ровно один раз:

- `YYYY` — год, четыре цифры;
- `MM` — месяц, две цифры;
- `DD` — день, две цифры.

Формат без любого из них или с повтором токена — ошибка настроек. Имя без дня или месяца не различает дни, а значит, две заметки одного месяца получили бы одно имя и `list_dates` не смог бы восстановить дату; повтор токена делает обратный разбор неоднозначным.

Неалфавитные символы, кроме запрещённых ниже, попадают в имя как есть: `DD.MM.YYYY` даёт `25.10.2026`, `YYYY_MM_DD` — `2026_10_25`. Регистр важен: `yyyy` — неизвестный токен.

Неизвестный алфавитный токен (`HH`, `mm`, `dddd`) — ошибка настроек, а не молчаливый пропуск. Иначе формат `YYYY-MM-DD HH:mm` создавал бы файл с буквальным `HH` в имени, а `list_dates` не смог бы восстановить дату и журнал выглядел бы пустым без объяснения. По той же причине отклоняются разделители пути (`/`, `\`), управляющие символы и символы, запрещённые в именах файлов Windows (`: * ? " < > |`): журнал — плоский набор файлов в одной папке, а настройка, синхронизированная между платформами, не должна ломать Windows.

Календарная дата проверяется до создания файла: `2026-02-30` и `2026-13-01` возвращают ошибку даты. Год ограничен диапазоном `1..=9999`, потому что обратный разбор читает ровно четыре цифры.

## Создание сегодняшней заметки

`today(root, settings)` берёт текущий момент через `core/src/search/note_date.rs`, переводит его в локальную гражданскую дату и вызывает создание для этой даты. Возвращается `JournalNote { path, created }`:

- `created: true` — файл создан этим вызовом;
- `created: false` — файл уже существовал и не был прочитан, изменён или перезаписан.

Повторный вызов в тот же день — штатная операция «открой мой день»: содержимое пользовательской заметки остаётся нетронутым. Создание идёт через `create_new` (`files::document::create_file_impl`), поэтому гонка двух вызовов не приводит к перезаписи: проигравший получает `already_exists` и тоже возвращает `created: false`.

Если настроен `templatePath`, содержимое берётся из шаблона. Если нет — создаётся минимальный frontmatter:

```markdown
---
created: 2026-10-25
---
```

В заготовке по умолчанию `created` записывается в ISO-виде, даже при нестандартном `dateFormat`. Это осознанно: значение читает индексатор (`search/created.rs`), а ISO понимается им однозначно. Имя файла может быть каким угодно, метаданные — нет. Если шаблон задаёт `created` сам, за разбор отвечает шаблон: `{{date}}` подставляет дату в `dateFormat`, и этот формат должен оставаться таким, который индексатор умеет читать (`YYYY-MM-DD`, `DD-MM-YYYY`, `DD.MM.YYYY`).

### Шаблон

`templatePath` — путь относительно корня базы знаний. Абсолютный путь и выход за пределы базы отклоняются. Отсутствующий файл шаблона — ошибка `Template`, а не тихий откат к пустому frontmatter: иначе опечатка в пути выглядела бы как «шаблон применился, но почему-то пустой».

Подставляются три плейсхолдера:

| Плейсхолдер | Значение |
| --- | --- |
| `{{date}}` | Дата заметки в формате `dateFormat` |
| `{{title}}` | То же значение — имя файла без `.md` |
| `{{time}}` | Время создания `HH:mm` |

Подстановка заменяет все вхождения. Незнакомые плейсхолдеры остаются как есть: шаблон может содержать заготовки для других инструментов, и ядро не должно их портить. Сам файл шаблона не меняется никогда — замены применяются к прочитанной копии.

Это не тот же подстановщик, что в [[note-templates]]: у обычных шаблонов есть варианты с форматом (`{{date:DD-MM-YYYY}}`, `{{time:HH:mm}}`), у дневного — только три фиксированных имени. Дневной формат уже задан настройкой, дублировать его внутри шаблона незачем; заодно набор токенов остаётся маленьким и предсказуемым.

## Список дат

`list_dates(root, settings)` читает папку журнала (один уровень, только файлы `.md`, расширение без учёта регистра) и разбирает каждое имя обратно по текущему `dateFormat`. Возвращаются только полностью разобранные и календарно корректные даты, отсортированные по возрастанию и без дублей.

Пропускаются:

- имена, не совпадающие с форматом (`2026-10-2`, `2026-10-25-extra`, `заметка`);
- календарно невозможные даты (`2026-02-30`);
- файлы с другим расширением;
- подпапки, даже если они названы как дата.

Отсутствующая папка и невалидный `dateFormat` дают пустой список: это запрос «покажи, что есть», у него нет причины падать. Ошибку формата пользователь увидит при создании заметки, где она действительно мешает.

## Ссылка на день

`link_target((year, month, day))` всегда строит каноническую ISO-ссылку:

```
[[2026-10-25]]
```

Формат ссылки не зависит от `dateFormat`. Это делает ссылки на день стабильными и переносимыми между базами, но накладывает ограничение: при нестандартном формате имени (`25.10.2026.md`) ссылка `[[2026-10-25]]` будет искать файл с ISO-именем и не найдёт заметку текущего журнала. При стандартном формате (по умолчанию) эти два представления совпадают.

## Что происходит при смене формата

Старые файлы остаются на месте и не переименовываются. `list_dates` перестаёт их находить, потому что разбирает имена только текущим форматом; `today` создаёт рядом заметку с новым именем. В журнале на один день могут оказаться два файла — старый и новый.

Это осознанное поведение, а не недосмотр:

- смена настройки не должна переписывать пользовательские файлы. Массовое переименование — необратимая операция, которая ломает внешние ссылки, git-историю и синхронизацию, а при конфликте имён может затереть файл;
- формат — часть идентификатора заметки. Если приложение «догадается» переименовать файлы, оно должно угадать и то, какие ссылки править, а это уже миграция ссылок, а не смена настройки;
- ошибка в формате не уничтожает данные: достаточно вернуть прежний `dateFormat`, и старые заметки снова видны в списке.

Практическое следствие: формат меняют один раз и осознанно, а существующие заметки переносят вручную или отдельным скриптом, который видит обе стороны и умеет обновлять ссылки. Ядро такой миграции не делает.

## Применение

### Команда «Открыть заметку на сегодня»

Палитра команд (`src/App.tsx`) содержит команду `journal.today` с подписью «Открыть заметку на сегодня» и горячей клавишей `Mod+Shift+D` (`SHORTCUTS.JOURNAL_TODAY`). Команда доступна только при открытой базе знаний.

Обработчик вызывает IPC-команду `journal_today(workspace_path)`, получает `{ path, created }` и открывает `path` тем же `openNote`, что и остальные файлы. Дерево файлов обновляется не вручную, а событием `workspace-changed` от наблюдателя за базой — ровно так же, как после создания связанной заметки из `[[ссылки]]`.

Повторный вызов в тот же день открывает тот же файл: `created` в этом случае `false`, второй заметки не появляется.

### IPC-команды

Слой Tauri (`src-tauri/src/journal/commands.rs`) не содержит бизнес-логики: он берёт `journal` из `core.settings.get_config()` на каждый вызов и передаёт работу сервису ядра.

| Команда | Аргументы | Результат |
| --- | --- | --- |
| `journal_today` | `workspacePath` | `{ path, created }` |
| `journal_dates` | `workspacePath` | `["2026-10-25", …]` — ISO-даты |
| `journal_note` | `workspacePath`, `year`, `month`, `day` | путь заметки на дату |

Настройки читаются в момент вызова, поэтому смена папки или формата в настройках действует сразу, без перезапуска приложения.

Фронтенд-обёртки лежат в `src/modules/journal/gateway.ts` (`journalToday`, `journalDates`, `journalNotePath`).

### Маркеры в календаре

Календарное представление Base (`src/components/Bases/BaseView.tsx`, `BaseCalendar.tsx`) при открытии вида запрашивает `journal_dates` и передаёт полученный набор ISO-дат в модель месяца (`buildCalendarMonth` в `src/modules/bases/calendar.ts`). У каждого дня модели есть флаг `hasJournal`; на отмеченных днях рисуется точка-маркер.

Клик по маркеру строит путь через `journal_note` (учитывает текущую папку и формат) и открывает заметку. Список дат запрашивается заново при смене настроек журнала, поэтому новый формат или папка отражаются в календаре без перезапуска, и при изменении индекса базы — новая заметка появляется в календаре без переоткрытия вида. Запрос идёт на открытие вида и на изменение индекса, а не на каждый рендер: набор дат хранится в состоянии представления.

### Настройки

Раздел «Дневные заметки» в настройках (`src/components/Settings/sections/JournalSection.tsx`) правит три поля секции `journal`: папка, формат даты и путь к шаблону. Пустое поле шаблона сохраняется как `null` — минимальная заготовка с frontmatter.

Ключи переводов: `settings.journal.*`, `settings.nav.journal`, `commands.journalToday`, `bases.calendarJournal`.

## Архитектура

- `core/src/journal/mod.rs` — `JournalNote`, `JournalError`, публичные реэкспорты.
- `core/src/journal/service.rs` — формат имён, `note_path`, `today`, `list_dates`, `link_target`, разбор шаблона.
- `core/src/journal/tests.rs` — создание и идемпотентность, шаблон, список дат, формат, ссылка, настройки по умолчанию.
- `src-tauri/src/journal/commands.rs` — IPC-команды `journal_today`, `journal_dates`, `journal_note`.
- `src/modules/journal/gateway.ts` — обёртки `invoke` для фронтенда.
- `src/components/Bases/BaseCalendar.tsx`, `src/modules/bases/calendar.ts` — маркеры дней с дневными заметками.
- `src/components/Settings/sections/JournalSection.tsx` — раздел настроек журнала.
- `core/src/settings/models.rs` — секция `journal` в `AppConfig`.
- `core/src/search/note_date.rs` — единственный источник календарной арифметики: текущий момент, гражданская дата, длина месяца.
- `core/src/files/document.rs` — создание файла без перезаписи и создание папок.

## Инварианты

- Существующий файл не перезаписывается ни при каких условиях: повторный `today` возвращает `created: false`.
- Имя файла строится только из `dateFormat` и даты; никакие другие поля настроек на него не влияют.
- Обратный разбор строже прямого: имя принимается, только если оно разобрано целиком и дата существует в календаре.
- `list_dates` не создаёт папку, не пишет файлы и не падает на мусоре.
- `created` в заготовке по умолчанию всегда ISO, независимо от `dateFormat`; шаблон может писать своё значение.
- Шаблон читается до создания папки журнала: ошибка в шаблоне не оставляет после себя пустую папку.
