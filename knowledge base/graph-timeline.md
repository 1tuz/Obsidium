# История графа

Временная шкала графа хранит состояние связи заметок отдельно от пользовательской истории текстовых версий. Она нужна, потому что milestone-версии заметок не фиксируют каждое изменение и не образуют согласованный снимок базы на выбранное время.

При первом открытии поисковой SQLite-базы индексатор в одной транзакции сохраняет текущие узлы, исходящие wiki/Markdown-ссылки и структурные связи `parent`, `related`, `depends_on`, `blocks`. Это начальная точка доступной истории; состояние до неё из текстовых версий не реконструируется.

После baseline индексатор добавляет delta только после изменения состояния графа заметки. Все изменения одной SQLite-транзакции получают общую метку времени; выдача событий возвращает последний ID этой группы. Удаление записывается tombstone, добавление и переименование сохраняют новый путь. Повторная индексация неизменившегося графового состояния не создаёт событие.

Событие хранит сериализованный графовый фрагмент одной заметки: её путь и ключи разрешения целей, даты, типизированные исходящие Markdown/wiki-ссылки и структурные цели. При проигрывании backend берёт начальный baseline и применяет последние состояния заметок до выбранного ID, затем разрешает цели относительно набора заметок того времени и использует обычный построитель бинарного WebGL-снимка. Координаты берутся из постоянного кэша раскладки по пути; историческая раскладка не перезаписывает кэш и не допускает перетаскивание узлов.

Записи остаются локально в SQLite рядом с индексом. Политика хранения пока не ограничивает срок или число событий: объём растёт с количеством изменений графа и размером сохранённых исходящих связей у изменённых заметок. UI показывает дату baseline, поэтому пользователь видит фактическую границу доступной истории. Необходимость ограничения хранения следует решать вместе с настройкой срока хранения и её влиянием на старые временные точки.
