# Просмотр исходного кода (TextFilePane)

Помимо Markdown-редактора Obsidium умеет открывать текстовые файлы кода — `.py`, `.yaml`, `.json`,
`.sh`, `.rs`, `.swift`, `.kt`, `.ts` и другие — в отдельной панели `TextFilePane`. Это не Markdown и
не полноценная IDE: панель даёт чтение и правку файла с нормальной подсветкой, номерами строк и
сворачиванием блоков.

## Связанные документы

- [[editor-code-blocks]] — подсветка внутри ограждённых блоков Markdown; палитра токенов общая.
- [[editor-markdown-live-preview]] — почему подсветка Markdown устроена иначе.
- [[file-tree-rendering]] — как файл попадает в эту панель.
- [[design-tokens]] — откуда берутся токены `--q-editor-code-*`.

## Определение языка

Язык выбирает `languageForPath` из `components/Editor/codeViewer.ts` — одна обёртка над
`LanguageDescription.matchFilename(languages, path)` из `@codemirror/language-data`.

Раньше здесь стоял `matchLanguageName(languages, extension, true)`, куда передавалось **расширение**,
а не имя файла. У `LanguageDescription` два разных матчера: `matchLanguageName` сравнивает строку с
именем языка и его алиасами, а расширения и особые имена файлов (`Dockerfile`, `Makefile`, `.bashrc`)
разбирает `matchFilename`. Из-за подмены расширение `py` не совпадало с именем языка `Python`, и
подсветка не включалась вовсе; работали только те файлы, у которых алиас языка случайно совпадал с
расширением.

Грамматика загружается лениво: `LanguageDescription.load()` вызывает динамический импорт пакета
языка только при открытии файла с этим расширением. При старте приложения ни один язык, кроме
Markdown, не подтягивается, поэтому список поддерживаемых языков не влияет на время запуска и память.

Файл с неизвестным расширением открывается как обычный текст: `languageForPath` возвращает `null`, и
панель не пытается угадать язык.

## Расширения CodeMirror

`codeViewerSetup` в том же файле собирает редактор:

| Расширение | Зачем |
|---|---|
| `history`, `defaultKeymap`, `historyKeymap` | отмена и стандартные сочетания |
| `foldKeymap`, `foldGutter` | сворачивание блоков по отступам и скобкам |
| `indentOnInput`, `indentUnit.of('    ')`, `tabSize(4)` | автоотступ и ширина таба, как в распространённых языках |
| `lineNumbers` | номера строк |
| `highlightActiveLineGutter`, `highlightActiveLine` | подсветка текущей строки |
| `bracketMatching` | парные скобки |

Панель использует `obsidiumFieldSetup` (история и базовая раскладка) плюс `codeViewerSetup`, общую
тему `obsidiumCodeMirrorTheme` и свою `codeViewerTheme`. Тема панели задаёт моноширинный шрифт из
`--q-editor-code-font`, размер и межстрочный интервал из настроек редактора
(`--q-editor-font-size`, `--q-editor-line-height`), приглушённые номера строк, фон текущей строки и
рамку парных скобок — всё токенами, поэтому светлая, тёмная и бумажные темы работают без отдельных
правил.

## Палитра токенов

Классы токенов описаны один раз в `components/Editor/extensions/codeBlock/highlight.ts` и общие с
ограждёнными блоками Markdown: ключевые слова, строки, числа, комментарии, функции, типы, свойства,
переменные, операторы и пунктуация. Цвета живут в токенах `--q-editor-code-*`
(`styles/tokens/components.css` для светлой и тёмной темы, `themes/reading.css` для бумажных стилей,
`themes/palette-semantic.css` для палитр, выведенных из акцента). Новая палитра обязана определить
все эти токены, иначе подсветка в ней станет одноцветной.

## Что панель не делает

- Не подключает Monaco, Ace или LSP: автодополнение, переходы и диагностика в панель не входят,
  для этого есть MCP-инструменты и внешний редактор.
- Не форматирует и не переписывает файл: сохранение пишет ровно то, что набрал пользователь, через
  тот же шлюз `writeFileAtomic` с проверкой хэша, что и заметки.
- Не переносит длинные строки: горизонтальная прокрутка вместо переноса, как в VS Code и Zed.
- Не хранит состояние на файл: позиция каретки и свёртки живут до закрытия вкладки.

## Производительность

Панель не создаёт фоновых вычислений: сохранение идёт по таймеру 700 мс после последней правки,
грамматика грузится один раз на файл, а расширения не пересоздаются между рендерами (`useMemo` по
загруженному языку). Большие файлы остаются плавными за счёт виртуализации строк самого CodeMirror.
