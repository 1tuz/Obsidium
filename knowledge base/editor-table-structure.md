## Добавление и удаление

Плюс внизу добавляет строку с высотой 40 px. Плюс справа — столбец с
выравниванием по умолчанию. Структурная операция завершает активное
редактирование, сбрасывает табличный диапазон, перерисовывает таблицу и
сериализует модель (`structure.ts` / `widgetSessionStructure.ts`).

### Chrome кнопок add-row / add-col

Разметка и hit-testing — [[editor-table-layout]].
Визуал:

| Что | Токен / значение |
|---|---|
| Толщина полосы | `--q-space-20` (высота add-row, ширина add-col) |
| Иконка Plus | Lucide, квадрат `--q-space-16`, цвет `--q-editor-table-handle` |
| Цвет handle | `--q-editor-table-handle` → `--q-icon-faint` (`components.css`) |
| Курсор | `pointer` (не resize) |
| Фон / бордер | `--q-editor-table-add-bg` / `--q-editor-table-add-border` |

Перестановка существующих строк/столбцов — отдельно:
[[editor-table-strip-reorder]].

Правила ядра относительно merge:

| Операция относительно merge | Поведение |
|---|---|
| Вставка строки/столбца до якоря | Регион сдвигается целиком. |
| Вставка внутри региона, но не перед якорем | Регион расширяется на новую строку/столбец. |
| Удаление до региона | Регион сдвигается к началу. |
| Удаление строки/столбца внутри региона | Span уменьшается; значение якоря сохраняется. |
| Удаление, превратившее merge в 1×1 | Merge удаляется, остаётся обычная ячейка со значением якоря. |

Пример. Вертикальный merge A2:A4 со значением `Backend`:

```ts
{ top: 1, left: 0, bottom: 3, right: 0 }
```

Удаление средней строки даст A2:A3. Удаление якоря также даст A2:A3 с
переносом значения. Ещё одно удаление превратит область в обычную ячейку
`Backend`.

## Высота строк и ширина столбцов

Граница между строками / столбцами (полоса ~12px на всю длину сетки): курсор
`row-resize` / `col-resize` и синяя линия `--q-bg-accent`. Тянем линию под
строкой `r` → `rowHeights[r]`; справа от столбца `c` → `colWidths[c]`.
Merge не мешает: меняется трек сетки, span следует за суммой высот / ширинами.

Минимум высоты 28 px, новой строки 40 px. Минимум ширины 36 px, дефолт 60 px.
Высоты и ширины в metadata `<!--q-table-->` как `rows` / `cols`. Strip labels
больше не содержат отдельную 6px-ручку resize — только select / reorder.

### Два режима ширины столбцов

| Режим | Когда | Что рисуется |
|---|---|---|
| `auto` | в markdown нет `cols` | `<colgroup>` без ширин, `table { width: 100% }` — браузер делит ширину редактора поровну; `colWidths` в модели не используются и не сохраняются |
| `explicit` | в markdown есть `cols` или пользователь потянул границу | `<col style="width: Npx">` и `table { width: сумма }` — ширины отдаются ровно как в модели |

Режим обязателен, потому что промежуточного состояния не существует: при
`table { width: 100% }` и `table-layout: fixed` браузер раздаёт остаток ширины
по столбцам, и отрендеренная ширина перестаёт совпадать с моделью. Первый drag
границы столбца материализует все измеренные ширины (`withExplicitColWidths`) и
переводит таблицу в `explicit`, поэтому дальше перетаскивание идёт ровно за
курсором.

Высоты строк остаются минимумами: строка не может стать ниже своего текста, и
это не режим, а свойство текстового потока. Столбцы, наоборот, при
`table-layout: fixed` управляются моделью полностью, а текст в ячейке
переносится.

### Геометрия для интерактива — только из DOM

`geometry.ts` — единственный источник размеров треков для интерфейса:

| Функция | Роль |
|---|---|
| `measureColWidths` / `measureRowHeights` | реальные размеры треков; fallback на модель, пока виджет не в layout |
| `syncStripSizes` | ширины кнопок col-strip, высоты кнопок row-strip, ширина corner, высота add-col |

Правила:

1. Ни strip, ни hit-test границы, ни baseline drag не берут числа из
   `model.colWidths` / `model.rowHeights`. Модель — это запрос, DOM — результат.
2. `beginBorderResize` запоминает измеренные размеры всех треков оси. Раньше
   baseline брался из модели: при расхождении модели и рендера начало drag
   уходило в «мёртвую зону» — граница не двигалась, пока курсор не пройдёт
   разницу.
3. Ширина `.q-md-table-corner` синхронизируется с измеренной шириной
   row-strip (`--q-md-table-corner-width`). Иначе трёхзначные номера строк
   расширяют row-strip, а corner остаётся 24 px, и буквы столбцов уезжают
   влево относительно самих столбцов.

Выравнивание столбца — в `aligns`, сериализуется separator-строкой Markdown.
У объединённой ячейки используется выравнивание якорного столбца.

## Навигация с merge

`Tab` / `Shift+Tab` обходят только видимые якорные ячейки. Покрытые
`rowSpan`/`colSpan` координаты в навигацию не попадают.

`Enter` идёт вниз по столбцу. При `rowSpan` переход — сразу под нижней
границей merge. Если ниже нет строки — добавляется новая. `Tab` на последнем
видимом якоре также добавляет строку и переходит в её первую ячейку.

Пример для A2:B3:

```text
      A           B          C
2   Backend                  12.08
3                              14.08
4   UI          Проверка     15.08
```

`Enter` в `Backend` → A4, не в скрытую A3. `Tab` из `Backend` → C2.
