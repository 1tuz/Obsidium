# Формат Markdown таблиц на диске

Связано с: [[editor-tables]] ·
[[editor-table-merges]] ·
[[editor-table-structure]]

Источник правды на диске и в Yjs — GFM Markdown плюс опциональный блок
`<!--q-table:{...}-->`. DOM-виджет не хранит отдельную копию данных.

## Обычная таблица

```md
| Задача | Статус | Срок |
| --- | --- | --- |
| API | Готово | 12.08 |
| UI | В работе | 15.08 |
```

## Настоящая пустая ячейка

Пустая самостоятельная ячейка — `<!--q-empty-->`, чтобы не принять пустоту за
горизонтальный span в legacy-формате.

```md
| Задача | Статус | Срок |
| --- | --- | --- |
| API | <!--q-empty--> | 12.08 |
```

Буквальный ввод текста `<!--q-empty-->` сериализуется как
`&lt;!--q-empty--&gt;` и снова показывается как обычный текст.

## Горизонтальный merge

```md
| Этап | Понедельник | Вторник |
| --- | --- | --- |
| Разработка | Два дня |  |
<!--q-table:{"merges":[[1,1,1,2]]}-->
```

Пустое место во второй ячейке региона — синтаксический `colSpan`;
`q-table.merges` — авторитетная геометрия.

## Вертикальный merge

```md
| Этап | Задача |
| --- | --- |
| Разработка | API |
| ^^ | UI |
<!--q-table:{"merges":[[1,0,2,0]]}-->
```

`^^` — покрытая ячейка следующей строки. Каноническая геометрия всё равно из
`merges`. Буквальный `^^` пишется как `\^\^`.

## Прямоугольник 2×2, высоты и ширины

```md
| Блок | Команда | Срок |
| --- | --- | --- |
| Backend |  | 12.08 |
| ^^ | ^^ | 14.08 |
| UI | Алиса | 15.08 |
<!--q-table:{"merges":[[1,0,2,1]],"rows":[40,52,52,40],"cols":[80,120,60]}-->
```

`rows` появляется, если хотя бы одна высота ≠ 40 px. `cols` появляется, только
если ширины заданы пользователем: наличие ключа `cols` — это и есть режим
`colSizing: 'explicit'` в модели. Таблица без `cols` живёт в режиме `auto` и
делит ширину редактора поровну, поэтому обычные рукописные таблицы никогда не
получают `cols` при правке ячеек. Resize границы столбца переводит таблицу в
`explicit` и пишет массив — [[editor-table-structure]].

## Несколько независимых объединений

```md
| Категория | Код | Этап | Срок |
| --- | --- | --- | --- |
| Первый блок |  | x | y |
| p | q | Второй блок |  |
| r | s | ^^ | ^^ |
<!--q-table:{"merges":[[1,0,1,1],[2,2,3,3]]}-->
```

Порядок в metadata стабилен, но не означает связь между регионами.

## Групповой заголовок

```md
| Задача | Планирование |  | Факт |
| --- | :---: | :---: | ---: |
| API | Пн | Вт | Готово |
<!--q-table:{"merges":[[0,1,0,2]]}-->
```

Отдельной логики «header merge» нет: это обычный merge в ряду 0.

## Legacy без metadata

Без `<!--q-table:...-->` поддерживается чтение: пустые ячейки после значения
могут стать горизонтальным merge, `^^` — вертикальным. Формат неоднозначен.

После первого сохранения с merge или нестандартной высотой пишется канонический
metadata; пустые самостоятельные ячейки — всегда `<!--q-empty-->`. При наличии
metadata он авторитетен. Повреждённый metadata не запускает legacy-угадывание.

## Разметка внутри ячейки

Ячейка рендерит инлайн-Markdown: жирный, курсив, зачёркивание, код и ссылки. Раньше текст писался
через `textContent`, и `[jvm-e2e.md](user-manual-master/…)` показывался целиком как исходник ссылки,
а `` `код` `` — с обратными кавычками. Рендер идёт через общий `renderMarkdownToHtml`; если рендерер
вернул больше одного блока (в ячейке это признак неожиданной разметки), ячейка откатывается к
простому тексту, чтобы не ломать высоту строки.

Целая ячейка `[[Заметка]]` остаётся вики-ссылкой с `data-wiki-target`: по этому классу виджет
делегирует открытие заметки, и этот путь не заменяется общим рендерером.

При входе в редактирование отрендеренное содержимое убирается и на его место встаёт поле ввода; после
завершения правки `releaseWrapper` рисует разметку заново. Поэтому `setWrapperText` обязан быть
идемпотентным: он полностью заменяет содержимое обёртки.
