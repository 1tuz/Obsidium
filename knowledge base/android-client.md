# Android-клиент Obsidium на базе Aquilum

## Область изменений

Исходная версия Obsidium: `1tuz/Obsidium`, `main`,
`7c2d05193702429012f5b65a1beadbc6fe2808b7` (0.5.32).
Основа Android-клиента: `Freaction/Aquilum`,
`2f4c6b516b54ca13109794af454fe4f03e3ca73e` (0.3.26).

Это отдельный мобильный клиент с повторным использованием редактора, Rust-ядра
и Android-интеграции Aquilum. Настольный Obsidium остаётся на Tauri, Preact и
CodeMirror. Замены настольного ядра, CRDT, установщиков и канала обновлений нет.
Существующий процесс переноса изменений ядра из Aquilum не изменён.

Добавлены подготовка закреплённых исходников, оформление Obsidium, отдельная
идентичность приложения, сборка APK и проверки в CI. В патче нет готового APK
и нет копии всего Aquilum: исходники загружаются при первой подготовке по
полному SHA, а не из изменяющейся ветки `main`.

Мобильная версия имеет независимый номер `0.1.0`, `versionCode=1`. Внутренние
Cargo-пакеты сохраняют версии исходного Aquilum, чтобы не менять его Cargo.lock.
Раздел «О программе» показывает версию мобильного Obsidium.

## Что переиспользуется, а что не переносится

Мобильный клиент использует исходный нативный редактор Aquilum, обработку
экранной клавиатуры, касаний, локальных файлов, поиска и книг. Интеграция не
переписывает эти подсистемы и не доказывает их безошибочность.

Цвета фона, текста, акцентов и совместимая часть семантических токенов берутся
из `obsidium-app/src/styles/themes/palettes.css` и `palette-semantic.css`.
Иконка берётся из `obsidium-app/src-tauri/icons/128x128@2x.png`. Светлая и тёмная
палитры Obsidium преобразуются в токены нативного интерфейса. Относительные
выражения `oklch(...)`, не поддерживаемые его сборщиком токенов, не переносятся:
для этих цветов остаются исходные определения Aquilum. Это сближение оформления,
не перенос всех тем, компонентов, анимаций и расположения панелей настольной версии.

Собственные Canvas, Kanban, расширения поиска, плагины и интерфейс настольного
Obsidium в мобильный клиент этим изменением не добавляются. На компьютере не
добавляются новые возможности редактора из Aquilum.

## Совместимость данных

Общая граница — файлы Markdown и вложения, а не внутренняя база состояния.
Обычные заметки не конвертируются. Исправления конфликтов и запись документов
остаются реализацией исходного Aquilum.

История, настройки, индексы, CRDT-журнал и служебные каталоги двух приложений
не объявляются взаимозаменяемыми. Форматы Canvas и Kanban не мигрируются;
наличие их файлов в папке не означает наличие соответствующего мобильного
интерфейса. Не следует подключать единую рабочую базу до проверки копии с
реальными заметками, вложениями, YAML, wiki-ссылками и служебными файлами.

Данные Android-клиента принадлежат его отдельному пакету. Удаление приложения
может удалить его локальные данные; системное резервное копирование отключено.
Перед переустановкой с удалением пакета нужна независимая сохранённая копия
заметок. Доступ к произвольной папке Android и двусторонний обмен с настольным
Obsidium в этом патче не реализованы дополнительно к исходному клиенту.

## Изоляция приложения и сетевых подключений

Релизный пакет: `com.obsidium.mobile`.
Предварительная сборка: `com.obsidium.mobile.debug`, название `Obsidium Preview`.
Они не заменяют пакет Aquilum и могут устанавливаться независимо.

Java namespace `com.dmitriy.aquilum` сохранён намеренно: исходные JNI-символы
привязаны к нему. Это не Android applicationId. В манифесте компоненты имеют
полные имена, а имя библиотеки остаётся `aquilum`.

Обновление через канал Aquilum на Android отключено. Разрешение установки
пакетов и провайдер исходного механизма обновлений удалены. Собственный
автообновлятор не добавлен; новый APK устанавливается вручную.

Ключ Dropbox автора Aquilum не используется. Без собственного публичного
ключа приложения OAuth-обработчик отсутствует, а подключение сообщает, что
Dropbox не настроен. Для сборки с Dropbox:

- в CI для релизной сборки используется repository variable
  `OBSIDIUM_DROPBOX_APP_KEY`;
- для предварительной сборки — отдельная variable
  `OBSIDIUM_DROPBOX_DEBUG_APP_KEY`;
- локально выбранный публичный ключ передаётся через переменную окружения
  `OBSIDIUM_DROPBOX_APP_KEY`.

OAuth-схема в манифесте и идентификатор в Rust формируются из одного значения.
Не использовать один ключ для одновременно установленных preview и release:
иначе оба пакета претендуют на один callback. Настройку приложения Dropbox,
его разрешений, доступа и возврата из браузера нужно проверить отдельно.

В настольный Obsidium Dropbox этим патчем не добавлен. Наличие реализации
синхронизации в исходном мобильном ядре не означает готовый сквозной обмен
между мобильной и настольной версиями.

## Структура

`mobile/android/upstream.json` фиксирует исходный репозиторий, SHA, версию
мобильного клиента и версии SDK/NDK/Gradle/cargo-ndk.

`prepare.py` загружает закреплённый коммит, создаёт отдельную рабочую копию и
применяет изменения из `overlay.py`, `theme.py` и `overrides/`. Загруженное
дерево находится в игнорируемом `mobile/android/.build/source`.
Кэш Git и результаты компиляции также находятся внутри `.build`.

Подготовка не перезаписывает ручные изменения молча. При изменении входных
файлов или подготовленной копии она останавливается. После сохранения нужных
ручных правок дерево можно пересоздать явно:

```sh
python3 mobile/android/prepare.py --recreate
```

Правки, которые должны пережить пересоздание, вносятся в слой интеграции,
а не только в `.build/source`. Команда удаления ограничена управляемой
директорией с маркером подготовки.

`build.py` собирает ARM64-библиотеку Rust и APK, проверяет подпись, package ID,
версию и ABI. `package_source.py` сохраняет изменённые исходники и скрипты
интеграции рядом с APK. Проверка подписи означает проверку `apksigner`, а
не успешный запуск приложения или аудит безопасности.

## Локальная проверка и сборка

Лёгкие тесты требуют Python 3.11+ и Git, без SDK, Rust и сетевых запросов:

```sh
python3 -m unittest discover -s mobile/android/tests -v
```

Основная среда сборки — Ubuntu 24.04 в GitHub Actions. Для локальной сборки
нужны Git, Python 3.11+, Rust с target `aarch64-linux-android`, cargo-ndk,
JDK 21, Gradle и Android SDK/NDK версий из `upstream.json`.
`ANDROID_HOME` должен указывать на установленный SDK. На первом запуске
нужен сетевой доступ к GitHub, Cargo, Maven и Android SDK.

```sh
python3 mobile/android/prepare.py
python3 mobile/android/build.py --variant debug
```

`prepare.py --offline` работает только после загрузки закреплённого коммита;
это не обещание полностью автономной компиляции зависимостей.

Нативный `CARGO_TARGET_DIR` используется только для мобильной сборки.
Он не меняет разделение dev/release и механизм Tauri в настольном приложении.

## Подпись

По умолчанию создаётся предварительная сборка с Android debug-подписью.
Ключ на разных одноразовых CI-машинах может отличаться, поэтому установка
поверх предыдущей preview-сборки не гарантируется. Не удалять установленный
пакет ради обхода ошибки подписи без резервной копии данных.

Для последовательных устанавливаемых обновлений нужна релизная сборка с
одним постоянным ключом владельца. Она не должна использовать ключ Aquilum.
В GitHub Secrets задаются:

```text
OBSIDIUM_ANDROID_KEYSTORE_BASE64
OBSIDIUM_ANDROID_STORE_PASSWORD
OBSIDIUM_ANDROID_KEY_ALIAS
OBSIDIUM_ANDROID_KEY_PASSWORD
```

Локально вместо BASE64 задаётся `OBSIDIUM_ANDROID_KEYSTORE` — абсолютный путь
к keystore вне обоих деревьев исходников — и остальные три переменные.
Ключи и пароли не помещаются в Git, исходный архив или параметры командной
строки. Процессам компиляции Rust эти переменные не передаются.

Без полного набора своих реквизитов release-сборка завершается ошибкой:
перехода на debug-подпись нет. Для нового выпуска увеличиваются мобильные
`version` и `version_code`, исходный ключ сохраняется.

## CI

В `Quality gate` добавлен только запуск Python-тестов при изменении мобильной
интеграции, её workflow, используемых цветов или иконок. Сборки Rust/Android
в быстрый этап не добавляются.

Workflow `Android companion` запускается вручную или вызывается существующим
ночным workflow. По умолчанию он создаёт preview-APK и запускает тесты
исходного `aquilum-core`. Ручной параметр `signed_release=true` включает
собственный ключ; `test_core=false` позволяет отключить повтор полного
набора core-тестов для отдельного сборочного запуска.

Настольные `release.yml` и `build-macos-app.yml` не меняются.
Существующая ночная периодичность сохраняется; добавляется отдельная задача
Android. Мобильный workflow не создаёт релиз, не публикует APK автоматически
и не обновляет настольный `latest.json`.

Артефакт содержит APK, SHA-256, сведения о сборке, архив изменённых исходников
и метаданные этого архива. Права workflow — `contents: read`.
Временный ключ удаляется завершающим шагом. Оригинальные LICENSE и
уведомления об авторстве сохраняются в исходном архиве.

## Передача агенту

Применять патч в отдельной ветке текущего Obsidium; не заменять существующие
настольные исходники копией Aquilum. Для указанного базового коммита изменённые
существующие файлы патча соответствуют оригинальным Git blob SHA.

```sh
git apply --check /path/to/obsidium-android.patch
git apply /path/to/obsidium-android.patch
python3 -m unittest discover -s mobile/android/tests -v
ruby scripts/check-workflow-yaml.rb
```

Если `main` продвинулся и проверка применения не проходит, согласовать
изменения затронутых workflow вручную, сохраняя новые настольные проверки.
Не применять патч с принудительным игнорированием конфликтов.

После разрешённой пользователем отправки ветки выполнить actionlint,
подготовку реальных исходников и ручную Android-сборку в CI. Сначала
проверить APK на отдельной копии данных: запуск, кириллический ввод,
экранную клавиатуру и выделение, сохранение после сворачивания, вложения,
светлую/тёмную тему, поиск, отсутствие запросов к обновлениям Aquilum.
При включённом Dropbox проверить вход, отдельный callback и конфликт
одновременного редактирования на тестовой базе. Только после такой проверки
рассматривать установку как основной мобильный клиент.

## Статус проверки

Локально выполнены тесты Python-интеграции, включая подготовку Git-копии по
закреплённому коммиту в локальных тестовых репозиториях и преобразование
минимальных тестовых исходников. Тесты проверки APK используют подставные
ответы утилит; реальный `apksigner` здесь не запускался.

Первая реальная сборка прошла в CI на `main`: workflow «Android companion»,
run 42086920433. Подготовка закреплённых исходников, сборка Rust-ядра через
`cargo ndk`, `gradle assembleDebug`, проверка `apksigner verify` и
`aapt dump badging` — получен `Obsidium_0.1.0_arm64_debug.apk`
(29 655 434 байта, sha256
`0f8eaa805a7dec16b6b5588cbfad1fa695d0b7b556279d45123145e36c756d4c`,
`com.obsidium.mobile.debug`, versionName `0.1.0-preview`, только `arm64-v8a`).

Первый запуск упал на шаге Gradle: AGP 9 выключил resource values в
`defaultConfig` по умолчанию (`defaultConfig contains custom resource values,
but the feature is disabled`), поэтому `overrides/app.build.gradle.kts` явно
включает `buildFeatures { resValues = true }`. Без этого блока `resValue` для
`app_name` не компилируется.

APK не запускался на телефоне и в эмуляторе, Dropbox не проверялся, релизная
подпись не создавалась (секретов `OBSIDIUM_ANDROID_*` в репозитории нет).
Полный комплект тестов настольного Obsidium не запускался. Успешные тесты
скриптов не заменяют компиляцию и проверку мобильного приложения.

При каждом повышении закреплённого SHA повторно проверить точки изменений,
сборку и сценарии на устройстве. Нельзя заменять фиксацию SHA на `main` или
на автоматическое неконтролируемое обновление исходников.
