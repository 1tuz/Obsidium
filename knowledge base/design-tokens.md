## Файловая структура

```
src/styles/
├── tokens/
│   ├── unit.css        ← Figma Unit
│   ├── dimension.css   ← Figma Dimension Semantic
│   ├── typography.css  ← Figma Typography
│   ├── colors.css      ← Figma Color Primitives
│   ├── semantic.css    ← Figma Color Semantic, Light
│   ├── effects.css     ← app-level durations, easing, z-index, opacity
│   ├── elevations.css  ← app-level shadow recipes (в т.ч. фокусное кольцо)
│   └── components.css  ← component aliases
├── themes/
│   └── dark.css         ← Переопределяет семантические токены для тёмной темы
├── base.css             ← Ресет, скроллбар, выделение, фокус
└── index.css            ← Импортирует всё в правильном порядке
```

## Figma → frontend

Единственный источник токенов — `aquilum-app/variables.json`, экспортированный из Figma. CSS генерируется командой:

```powershell
cd aquilum-app
npm run tokens:sync
```

Проверка соответствия цветов Figma и CSS:

```powershell
npm run tokens:diff
```

После нового экспорта из Figma замени `aquilum-app/variables.json` и выполни полный pipeline:

```powershell
npm run tokens:sync
npm run tokens:diff
npm run check:figma-names
npm run check:colors
```

Автоматического watcher-а Figma нет: CSS обновляется только после запуска `tokens:sync`. Сгенерированные CSS-файлы не редактировать вручную.

Для запуска полного pipeline двойным кликом используй `aquilum-app/scripts/sync-figma-tokens.bat`. Скрипт оставляет окно открытым и показывает логи даже при ошибке.

Не редактировать вручную сгенерированные `unit.css`, `dimension.css`, `typography.css`, `colors.css`, `semantic.css` и `themes/dark.css`. Компонентные алиасы остаются в `components.css`.

## Правила именования

Имена Figma Variables используют lowercase slash-hierarchy и описывают роль, а не силу значения:

- `bg/canvas`, `bg/surface`, `bg/surface-raised`, `bg/surface-overlay`, `bg/surface-hover`
- `text/primary`, `text/secondary`, `text/muted`, `text/on-accent`
- `icon/primary`, `icon/secondary`, `icon/muted`, `icon/faint`, `icon/quiet`
- `border/subtle`, `border/default`, `border/emphasis`, `border/contrast`, `border/focus`
- `font/size/*`, `font/weight/*`, `font/line-height/*`, `font/letter-spacing/*`, `font/family/*`

Не использовать ordinal-суффиксы (`*-2`), неясные уровни (`strong`, `very-strong`) и имена по внешнему виду (`secondary` вместо роли поверхности). Проверка: `npm run check:figma-names`.

## Масштабирование (Ctrl + / –)

Как устроен масштаб интерфейса, где его меняют и почему ни один размер интерфейса не задаётся в `px`, —
[[interface-scale]]. Коротко: все размеры — токены в `rem`, масштаб меняет корневой размер шрифта
(70–150 %, шаг 5 %). Не масштабируются только толщина границ в 1px, круглое скругление
`--q-rounded-full`, z-index и прозрачность.

### Геометрия компонента не смешивает `px` и `rem`

Свитч (`Switch.css`) показал, во что превращается такая смесь. Трек, ручка и её отступ были заданы
жёсткими `48px / 22px / 26px / 18px / 2px`, а ход ручки — токеном `translateX(var(--q-size-18))`.
При масштабе 100 % числа совпадали, потому что `--q-size-18` равен `1.125rem` = 18px. Стоило
изменить масштаб, и ход поехал вместе с `rem`, а трек остался в пикселях — внутренний кружок
выезжал за границу свитча.

Вывод шире одного компонента: **если хоть одна величина геометрии взята из токена, из токенов
обязаны быть взяты все.** Одна пиксельная величина рядом с одним `rem` — это гарантированная
поломка на любом масштабе, кроме 100 %.

Второе правило оттуда же: **производные величины считаются, а не выписываются.** Ход ручки — это не
самостоятельное число, а `ширина − ручка − 2 × отступ`, и он объявлен именно так:

```css
--q-switch-handle-travel: calc(
  var(--q-switch-width) - var(--q-switch-handle-size) - var(--q-switch-handle-inset) * 2
);
```

Пока ход был отдельным числом, он мог разойтись с геометрией; теперь он не может разойтись по
построению. Размеров `38px` и `22px` в генерируемом `unit.css` нет, а править этот файл нельзя, —
поэтому они объявлены компонентными токенами в `components.css` сразу в `rem`.

Текстовым тестом это не покрыть: в vitest импорт `./Switch.css?raw` отдаёт пустую строку, потому что
CSS там не обрабатывается. Гарантию даёт сам `calc`, а не проверка исходника.

## Namespace `--q-`

Все токены используют префикс `--q-` (aquilum), чтобы:
- Не конфликтовать с CSS-переменными браузера
- Не конфликтовать с переменными плагинов и модов
- Быть легко различимыми при отладке

## Шрифтовые семейства

Четыре отдельных семейства — каждое можно настроить независимо:

| Токен | Назначение | По умолчанию |
|-------|-----------|-------------|
| `--q-font-family-ui` | Кнопки, меню, сайдбар | Inter (настраивается) |
| `--q-font-family-editor` | Текст заметок | iA Writer Mono (настраивается) |
| `--q-font-family-mono` | Код, инлайн-код | iA Writer Mono |
| `--q-font-family-heading` | Заголовки заметок (наследует от editor) | var(--q-font-family-editor) |

Семейства, веса и откуда берутся файлы — [[fonts]].

## Темы

Тема — это CSS-файл, переопределяющий семантические токены:

```css
[data-theme="my-custom-theme"] {
  --q-bg-app: #1a1b2e;
  --q-bg-primary: #232439;
  --q-text-primary: #e8e8ff;
  /* ... */
}
```

Встроенные темы:
- **Light** — значения по умолчанию в `semantic.css`
- **Dark** — переопределения в `themes/dark.css`
- **System** — автоматически по настройкам ОС

Пользовательский основной цвет подменяет `--q-blue-alpha-main` и `--q-blue-500`, а `--q-blue-600` (hover) выводится из него через `color-mix(in srgb, <цвет> 78%, black)`. У `blue/600` нет ссылки на альфа-шкалу, от которой его можно было бы пересчитать, и без вывода hover оставался бы исходным синим при любом выбранном акценте.

## i18n (Переводы)

Минимальная система:
- `src/i18n/locales/ru.json` — русский
- `src/i18n/locales/en.json` — английский
- Точечная нотация: `t('editor.words')` → "слов"
- Интерполяция: `t('msg', { count: 5 })` → подставляет `{{count}}`
- Автоопределение языка по системе

## Как добавить свою тему (для модов)

1. Создать CSS-файл с `[data-theme="название"]`
2. Переопределить нужные семантические токены
3. Подключить через `@import` или `<link>`

## Как добавить новый язык

1. Создать `src/i18n/locales/xx.json` по образцу `en.json`
2. Импортировать в `src/i18n/index.ts`
3. Добавить в `translations` и тип `Locale`

## Ловушка: семантическая поверхность может не отличаться от фона

Найдено в светлой теме и стоило отдельного разбора. Числа:

```
--q-editor-bg  → --q-bg-primary → --q-bg-canvas → --q-white-alpha-main = #ffffff
--q-bg-surface → --q-gray-50                                           = #fcfcfc
--q-bg-sunken  → --q-bg-surface                                        = #fcfcfc
```

Разница между фоном редактора и «поверхностью» — **3 из 255**, то есть около процента яркости. Всё,
что брало фон из `--q-bg-surface` или `--q-bg-sunken`, в светлой теме визуально не имело фона вовсе:
блок кода, инлайн-код, подложка обложки в виджете книги. В тёмной теме шаг настоящий, поэтому дефект
не замечался годами — владелец работает в тёмной.

Отдельно та же история с рамками: `--q-border-subtle` это `--q-black-alpha-05`, пять процентов
чёрного. На белом фоне это край, которого не видно. Карточка виджета книги стояла на
`--q-bg-surface-subtle` (три процента чёрного) с такой рамкой и не читалась как карточка.

Что из этого следует для работы с токенами:

- **Проверять контраст пары, а не значение по отдельности.** «Поверхность» — понятие относительное;
  сама по себе `--q-bg-surface` не может быть правильной или неправильной, правильной или нет бывает
  только её разница с тем, на чём она лежит.
- **Не править семантический слой ради одного компонента.** Поднять `--q-bg-surface` для светлой темы
  было бы соблазнительно и сдвинуло бы каждую поверхность приложения. Правильно — завести токен
  компонента в `:root` и перекрыть его в `[data-theme="dark"]` прежним значением, чтобы тёмная тема
  осталась байт в байт такой же.
- **Если два компонента обязаны совпадать — делать один токен, а не совпадающие значения.** Карточки
  редактора сидят на общем наборе `--q-block-*` (см. ниже). Два одинаковых литерала разъехались бы
  при следующей правке палитры, общий токен — нет.
- **Перекрытие в тёмной теме нужно писать даже когда оно выглядит избыточным.** Иначе усиление
  светлой темы молча уезжает в тёмную, где всё было в порядке.

## Общие токены блоков

Всё, что в заметке рисуется карточкой, — таблица dataview (с вариантами «ждёт данные» и «ошибка»),
виджет книги (одиночный и группа), блок кода, а также сниппет кода в настройках MCP — стоит на одном
наборе токенов из `styles/tokens/components.css`:

| Токен | Светлая | Тёмная | Где |
|---|---|---|---|
| `--q-block-bg` | `--q-bg-surface-raised` → gray-100 | `--q-white-alpha-03` → ≈ #161a21 на фоне редактора | фон карточки |
| `--q-block-border` | `--q-gray-150` | `--q-border-subtle` | внешняя обводка 1px |
| `--q-block-divider` | `--q-border-default` | `--q-white-alpha-08` | линии внутри: строки dataview, между книгами группы |
| `--q-block-radius` | `--q-rounded-2xl` (12px) | — | скругление |
| `--q-block-padding` | `--q-space-12` | — | внутреннее поле кода и dataview |

Эталон — отрисованная таблица dataview: у неё уже были и обводка, и фон. Раньше семейства жили на
разных токенах: dataview брал фон и рамку у виджета книги, книга скруглялась на 8px вместо 12px,
у блока кода не было обводки, а сниппет MCP стоял на `--q-bg-surface` со своим радиусом. Рядом
стоящие блоки выглядели как разные компоненты.

**Почему фон в тёмной теме — `--q-white-alpha-03`.** Прежний фон `--q-bg-surface` (gray-850,
#14181f) лежал на фоне редактора gray-900 (#0f131a), разница едва видна, и карточка держалась только
на пятипроцентной рамке. Первой попыткой стал `--q-bg-surface-raised` (gray-800, #1b1f28), но
владелец счёл его слишком ярким. Сплошной ступени между gray-850 и gray-800 в палитре нет, они
соседние, поэтому взята полупрозрачная: три процента белого на фоне редактора дают ≈ #161a21, ровно
посередине. Ступень `--q-white-alpha-04` дала бы ≈ #191c23, почти тот же gray-800.

Полупрозрачность здесь безопасна: все карточки лежат прямо на фоне редактора, а выделение текста в
блоке кода рисуется слоем над фоном строки (`::before` с `z-index: -2`, [[editor-code-blocks]]).
Следствие для сниппета кода в настройках MCP: он лежит на фоне диалога gray-750, и три процента
белого делают его чуть светлее диалога, а не темнее. Светлая тема не меняется: там `--q-block-bg`
по-прежнему `--q-bg-surface-raised` (gray-100).

**Разделитель — отдельный токен.** Рамка и линии внутри карточки — разные вещи. Восемь процентов
белого подобраны глазами владельца, история подбора — в [[editor-book-callout]].

**Обычная markdown-таблица сюда не относится.** Это сетка как в Excel: без фона, без скругления,
рамка ячеек `--q-editor-table-border`. Карточный стиль на ней владелец отверг: таблица — это просто
таблица, а не виджет.

Как каждое семейство надевает обводку, зависит от его DOM. Карточка dataview, книга и сниппет MCP —
это один элемент с обычным `border`. Блок кода — это строки CodeMirror с фоном на `::before`, у него
`border-inline` на каждой строке, `border-top` у первой и `border-bottom` у последней, см.
[[editor-code-blocks]]. У группы книг фон и рамка стоят на контейнере, у вложенных карточек фон
прозрачный, а между ними рисуется разделитель.

## Фон редактора в тёмной теме

Обратная сторона той же ловушки: поверхность может отличаться от фона слишком **сильно**. Зона
редактора брала `--q-editor-bg → --q-bg-primary → --q-bg-canvas`, то есть в тёмной теме
`--q-gray-950` (#090b11), тогда как хром приложения — тайтлбар, сайдбар, рельс — стоит на
`--q-tabs-bg → --q-bg-surface`, то есть `--q-gray-850` (#14181f). Самая большая площадь экрана
оказывалась самой чёрной, выбивалась из окна и утомляла при письме.

Тёмная тема перекрывает `--q-editor-bg` до `--q-gray-900` (#0f131a): шаг от хрома остался, но зона
письма перестала быть краем палитры. Светлая тема не тронута — там пара читалась нормально.

Активная вкладка тайтлбара обязана совпадать с редактором: она визуально продолжает его лист. Раньше
совпадение держалось случайно — оба токена независимо разворачивались в `--q-bg-canvas`. Теперь связь
объявлена алиасом `--q-tab-bg-active: var(--q-editor-bg)`, по правилу «если два компонента обязаны
совпадать — делать алиас».

Перекрытие живёт в блоке «App dark overrides» в `themes/dark.css`, и **этот список продублирован в
`scripts/sync-figma-tokens.mjs`**: файл генерируемый, правка только в CSS переживёт до первого
`npm run tokens:sync`.

## Фокусное кольцо

Рецепт живёт в одном месте — `elevations.css`:

- `--q-shadow-focus-ring` — 1px `--q-border-focus` плюс гало 4px `--q-border-focus-ring`;
  им пользуются `Input`, `ColorControl` и всё, что должно фокусироваться так же. Своя копия
  двух теней в компоненте запрещена: `ColorControl` держал её и разошёлся бы при первой правке
  рецепта.
Для медиа кольцо оставлено внешним, но место под него выкраивается внутри виджета
(картинка чуть уже колонки) — см. [[editor-images]].

Однослойное гало без внутренней рамки (`Switch`) — отдельный случай и токеном
пока не оформлено.

Токены кольца полупрозрачные (`--q-border-focus` — blue-alpha-46, `--q-border-focus-ring` —
blue-alpha-25), поэтому кольцо рассчитано на фон интерфейса. Если оно должно окружать медиа,
под него нужно оставить зазор, чтобы оно не легло на сам кадр и не потерялось — так сделано у
картинок в редакторе.

## Слои (`z-index`)

Слои приложения — токены в `effects.css`, сырое число в `z-index` допустимо только для порядка
внутри одного компонента, который сам создаёт контекст наложения (`isolation: isolate` или
`position` с `z-index`):

| Токен | Значение | Кто |
|---|---|---|
| `--q-z-header` | 300 | системные кнопки окна |
| `--q-z-modal` | 500 | модалки, читалка |
| `--q-z-popover` | 600 | меню, поповер настроек читалки |
| `--q-z-drag` | 800 | «призрак» перетаскивания файлов в дереве |
| `--q-z-system` | 900 | экран установки обновления — поверх всего, включая модалки |

Раньше призрак и экран обновления стояли на `9999` и `10000`: числа подбирались «побольше», и
следующий слой пришлось бы ставить на `100000`. У страницы-книги свои слои
(`--q-book-z-cover`, `--q-book-z-controls`, `--q-book-z-star`, `--q-book-z-thumbnail`,
`--q-book-z-cover-repositioning` в `components.css`): обложка, кнопки, звезда и миниатюра книги
перекрываются между собой, и их порядок — часть макета, а не случайные числа.

## Что удалено из генератора

Из блока совместимости в `scripts/sync-figma-tokens.mjs` убраны псевдонимы, которыми никто не
пользовался: `--q-black`, `--q-transparent`, `--q-bg-hover`, `--q-bg-active`, `--q-bg-selected`,
`--q-bg-accent-hover`, `--q-border-overlay`, `--q-border-hover`, `--q-bg-tooltip`,
`--q-text-tooltip`, `--q-rounded-none`, `--q-rounded-3xl`, а также `--q-transition-opacity` и
`--q-tracking-*`. Из тёмных перекрытий убраны `--q-search-shadow` (токен больше нигде не читается)
и `--q-book-thumb-shadow`: светлое значение теперь собрано из `--q-shadow-lg/md/sm`, а эти три
токена уже различаются по темам, так что отдельное тёмное перекрытие повторяло бы то же выражение.
Используемые псевдонимы (`--q-rounded-*`, `--q-bg-primary`, `--q-text-link` и другие) остались в
блоке «Legacy aliases»: на них ссылаются в том числе файлы редактора, и перевод на имена Figma —
отдельная задача. `--q-scrollbar-track` оставлен и теперь действительно используется в `base.css`
вместо зашитого `transparent`.

Цвета «светофора» macOS — компонентные токены `--q-window-mac-close-bg`,
`--q-window-mac-minimize-bg`, `--q-window-mac-maximize-bg` рядом с красным крестиком Windows: это
фирменные цвета платформы, они одинаковы в обеих темах. Ширина окна подтверждения —
`--q-confirm-dialog-width` ([[dialogs]]).
