# Диаграммы Mermaid в редакторе

Статус: актуально на 2026-11-05.

## Назначение

Блок ` ```mermaid ` не показывается как код: вместо ограждений, строки языка и тела в документе
рисуется SVG-схема. Поддерживаются все типы Mermaid (flowchart, sequence, class, state, ER, gantt),
потому что рендер один — `mermaid.render()` над исходником блока. Flowchart — первый по частоте тип,
поэтому его же вставляет команда `/` → Diagram.

Исходник остаётся обычными строками Markdown: каретка внутри блока показывает сырой текст
(общий контракт live preview), правка меняет только содержимое блока, документ и CRDT не знают
о SVG. Схема — украшение отображения, её потеря восстанавливается из текста при следующем рендере.

## Основные файлы

`src/components/Editor/extensions/diagram/`:

- `constants.ts` — язык `mermaid`, лимит кэша, задержки префетча, имена классов, скелет блока для `/`
- `constructs.ts` — `findDiagramBlocks`: блоки кода с информацией `mermaid` во всём документе
- `decorations.ts` — `collectDiagramDecorations`: замена диапазона блока виджетом
- `widget.ts` — `DiagramWidget`: `eq` по кэш-ключу, измеренная высота, клик в режиме правки
- `dom.ts` — DOM кадра: ожидание, ошибка, `<svg>` из строки через `DOMParser`
- `store.ts` — кэш результатов и высот, LRU на 40 записей
- `render.ts` — ленивая загрузка Mermaid, очередь рендера, конфиг темы, текст ошибки
- `prefetch.ts` — `ViewPlugin`: пересчёт блоков по документу и дереву, наблюдение за темой
- `theme.ts` — токены темы в `themeVariables` Mermaid и CSS кадра

Подключение — `extensions/livePreviewWidgets.ts`: декорации попадают в общий
`livePreviewWidgetField`, префетч и тема — в список расширений `livePreviewWidgetExtension`.

## Почему виджет, а не отдельный редактор

Виджет — `Decoration.replace` на весь блок, включая строки ограждения: `collectPreviewReplaceDecorations`
из `livePreviewEditableSpans.ts`. Подсветка синтаксиса, панель языка и копирование у диаграммы не нужны,
а вложенный CodeMirror внутри блока (как у таблиц) дал бы второй документ, который надо синхронизировать.
Тот же хелпер даёт бесплатно главное правило: пока выделение пересекает диапазон блока, виджет не
ставится. Поэтому клик в режиме правки просто переносит каретку в начало блока, и Mermaid-текст
раскрывается штатным reveal — отдельного «режима исходника» нет.

В режиме чтения (`EditorState.readOnly`) виджет не отправляет транзакцию: читатель не может случайно
перевести документ в правку. `contenteditable=false` на кадре запрещает браузерную правку SVG.

## Почему префетч по всему документу

`findDiagramBlocks` сканирует документ целиком, а не вьюпорт. Причина — прокрутка: декорации
вьюпорта создаются заново при каждом скролле, и если рендер запускать только для видимого блока,
каждая новая схема появлялась бы с кадром ожидания. Сейчас схема приезжает уже готовой из кэша.
Цена ограничена: сканирование идёт по существующему дереву разбора, а рендер — только для блоков,
которых нет в кэше.

Пересчёт запускает `PrefetchScheduler` (`extensions/prefetchScheduler.ts`) на изменение документа и
дерева: `editMs: 200` ждёт паузу в наборе, `revisionMs: 0` пропускает правку, пришедшую без паузы,
сразу — иначе кадр ожидания висел бы до следующей остановки.

## Кэш и ключи

Ключ — `diagramKey(source, themeKey)`: исходник плюс тема (`data-theme`, `data-palette`,
`data-accent-mode`). Одна и та же схема в двух заметках рендерится один раз; смена темы делает
старые записи недостижимыми и не требует ручной инвалидации. Кэш — `Map` на 40 записей с LRU-порядком;
`forgetDiagramsOutside` чистит записи, которых нет в документе, но только когда дерево разобрано
целиком (`syntaxTreeAvailable`) — на частичном дереве такой вывод был бы ложным.

Высота схемы запоминается отдельно (`diagramHeight`) и отдаётся виджету как `estimatedHeight`:
CodeMirror считает прокрутку до монтирования виджета, и без сохранённой высоты документ прыгал бы
при появлении каждой схемы. Высота пишется из `view.requestMeasure` в фазе `write`, чтобы чтение
DOM не вызывало повторный layout.

## Рендер

Mermaid грузится динамическим `import('mermaid')` и только когда в документе есть диаграмма: основной
бандл не растёт. `mermaid.render` меняет глобальную конфигурацию и вставляет временные узлы в DOM,
поэтому вызовы идут строго последовательно через цепочку промисов; на каждую схему выдаётся новый
`id` (`q-diagram-N`), иначе старые определения `<style>`/маркеров конфликтуют между собой.

`securityLevel: 'strict'` запрещает произвольный HTML из блока, `suppressErrorRendering` выключает
собственный DOM-вывод ошибок Mermaid — при синтаксической ошибке рисуется наш кадр с текстом
`editor.diagramFailed`, в котором остаётся очищенное сообщение (теги вырезаны, длина ограничена 400
символами). Ошибка хранится в кэше как результат, поэтому сломанная схема не пытается перерисоваться
на каждый скролл.

`theme: 'base'` — единственный режим, где Mermaid слушается `themeVariables`. Значения берутся из
CSS-токенов (`--q-bg-accent-subtle`, `--q-text-primary`, `--q-border-accent-subtle` и другие) скрытым
элементом-пробником: `var()` разрешается в `getComputedStyle`, кэшируется по `themeKey`. Шрифт
и размер — `--q-editor-font-family` / `--q-editor-font-size`, поэтому подпись схемы совпадает с текстом.

## Цвета: rasterize, а не строка

`getComputedStyle().color` в Chromium возвращает современный синтаксис для `color-mix()`, например
`color(srgb 0 0 0 / 0.03)`. Mermaid парсит цвета через khroma и падает на нём с
`Unsupported color format`, из-за чего любая схема в такой теме показывала ошибку вместо SVG.
Поэтому каждый разрешённый цвет рисуется в canvas 1×1 и читается `getImageData`: оттуда берётся
`rgb()` / `rgba()` — формат, который khroma понимает. Тот же приём, что в `Graph/palette.ts`;
здесь он ещё и нормализует любой современный синтаксис (`oklch`, `color()`, `hwb`).

Если canvas недоступен (юнит-тесты в happy-dom), исходная строка остаётся как есть: тесты цветов
не проверяют, а браузерный `canvas` есть всегда.

## Смена темы

`prefetch.ts` наблюдает `data-theme`, `data-palette`, `data-accent-mode`, `data-appearance` и `style`
на `documentElement`. Смена любого атрибута меняет `themeKey`, и все схемы рендерятся заново в новую
тему; без наблюдателя SVG оставался бы с цветами прошлой темы до ближайшей правки документа.

## Корнер-кейсы

- Схема приехала прокруткой: кэш уже тёплый (префетч идёт по всему документу), кадр ожидания
  не мигает.
- Пустой блок (` ```mermaid ` без тела) не считается диаграммой и остаётся обычным блоком кода:
  рендерить нечего, а замена скрыла бы ограждения у пустого блока, куда нельзя поставить каретку.
- Синтаксическая ошибка в одной схеме: кадр с текстом, остальные схемы документа рисуются нормально,
  потому что очередь рендера изолирует исключение в результат.
- Тема без токена: `var(--token, currentColor)` даёт наследуемый цвет, схема остаётся читаемой.
