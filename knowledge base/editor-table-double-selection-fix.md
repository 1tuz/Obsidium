# Фикс двойного выделения в таблицах редактора

## Цель и область действия

Этот документ описывает, как таблица гарантирует один видимый слой выделения.
Он относится к интерактивному виджету таблицы: вложенному CodeMirror активной
ячейки, прямоугольному выделению ячеек и родительскому CodeMirror.

Карта документов таблиц: [[editor-tables]].
Жесты и overlay: [[editor-table-interaction]].
Геометрия merge и Markdown: [[editor-table-merges]],
[[editor-table-markdown]].

Инвариант прост: в каждый момент пользователь видит либо текстовое выделение
вложенного редактора, либо один overlay табличного диапазона, либо обычное
выделение родительского редактора — но не их сочетание.

## Почему возникало двойное выделение

Вложенный CodeMirror включает `drawSelection()`. Он рисует каретку и текстовое
выделение своими DOM-слоями (`.cm-cursor` и `.cm-selectionBackground`).
Одновременно браузер может рисовать нативный `::selection` цветом системного
`Highlight`. В WebView это особенно заметно как яркий второй слой поверх
полупрозрачного CodeMirror.

Отдельный источник дублирования — сохранённое выделение исходного Markdown в
родительском CodeMirror. Когда поверх него появляется таблица или её диапазон,
родительский `.cm-selectionBackground` не должен быть виден одновременно с
табличным overlay.

Это два разных дефекта с разными исправлениями. CSS нативного `::selection` не
заменяет очистку состояния родительского редактора, а очистка этого состояния
не подавляет нативную отрисовку браузера.

## Распределение ответственности

| Модуль | Ответственность |
|---|---|
| `components/Common/codeMirror.ts` | Для всех CodeMirror делает нативный `::selection` прозрачным. Селектор намеренно имеет высокую специфичность и `!important`: он должен перекрыть focused fallback CodeMirror для системного `Highlight`. |
| `tableCellFieldExtensions.ts` | Подключает `drawSelection()` и тему только к nested CodeMirror ячейки. |
| `parentSelection.ts` | Схлопывает непустое выделение родительского CodeMirror и переключает класс `q-md-table-interaction`. |
| `selection.ts` | Перед применением табличного диапазона закрывает редактор ячейки и очищает родительское выделение; рисует один прямоугольный overlay. |
| `widgetSession.ts` | Координирует переходы по pointer-событиям, фокус nested editor и класс режима взаимодействия. |
| `theme.ts` | Пока есть редактирование ячейки или табличный диапазон, скрывает cursor и selection layer родительского CodeMirror. |
| `tableCellField.ts` | Перед переносом переиспользуемого nested editor в отсоединённый host схлопывает его собственное выделение, чтобы не оставить устаревший браузерный слой. |

`q-md-table-interaction` — это не визуальный флаг таблицы, а граница владения
выделением: пока он установлен, видимые слои родительского CodeMirror скрыты.

## Переходы состояний

### Редактирование одной ячейки

Клик открывает nested CodeMirror. Родительское выделение схлопывается,
`q-md-table-interaction` включается. Пользователь может выделять текст только
внутри активной ячейки: CodeMirror рисует единственный собственный слой, а
нативный `::selection` остаётся прозрачным благодаря общей теме CodeMirror.

### Drag внутри активной ячейки

Пока указатель не вышел за границы этой ячейки, `widgetSession` передаёт
координаты `selectFromCoords` nested editor. Это всё ещё текстовое, а не
табличное выделение; overlay диапазона не создаётся.

### Drag или Shift-клик на другой ячейке

Переход за границу ячейки закрывает nested editor. `selection.ts` очищает
родительское выделение, нормализует прямоугольник с учётом merge-регионов и
рисует один `.q-md-table-selection-overlay`. Внутри выбранных ячеек больше нет
активного текстового выделения.

### Выход из таблицы

При снятии диапазона, потере nested-фокуса или уничтожении widget-сессии её
синхронизация снимает `q-md-table-interaction`. После этого родительский
CodeMirror снова вправе показывать собственные слои. Это не должно происходить
раньше закрытия редактора ячейки или удаления tabular overlay.

## Важные пограничные случаи

- **Текстовый drag превращается в табличный.** До пересечения границы виден
  только nested слой; после пересечения nested editor закрыт до появления
  overlay. Нельзя оставлять оба состояния активными на один кадр.
- **В исходном Markdown уже был выделен диапазон.** Любое начало
  взаимодействия с таблицей вызывает `collapseSelection` (`extensions/editorFocus.ts`); одного CSS
  скрытия недостаточно, потому что старое состояние может проявиться после
  смены фокуса.
- **Переиспользование поля ячейки.** Nested editor переносится между DOM-host
  без пересоздания. Перед отсоединением его selection схлопывается, иначе
  браузер может удержать нативную подсветку старого узла.
- **DevTools и blur.** Открытие DevTools часто меняет фокус и сбрасывает
  нативное выделение, поэтому диагностировать проблему по состоянию после
  переключения окна нельзя. Снимок делается до blur.
- **Backspace вокруг таблицы.** Родительский редактор может намеренно выбрать
  весь source-диапазон таблицы для удаления. Это не табличный режим; при
  последующем входе в таблицу это выделение обязательно схлопывается.

## Диагностика

До потери фокуса зафиксируйте:

1. `window.getSelection()` и `document.activeElement`;
2. `getClientRects()` нативного выделения;
3. все видимые `.cm-selectionBackground`, `.cm-cursor` и
   `.q-md-table-selection-overlay`;
4. принадлежность каждого слоя: parent CodeMirror, nested CodeMirror или
   table widget.

Интерпретация результатов:

| Наблюдение | Проверять |
|---|---|
| Яркий системный слой поверх CodeMirror в активной ячейке | `drawSelection()` и общий `::selection` в `components/Common/codeMirror.ts`. |
| Parent `.cm-selectionBackground` под табличным overlay | `collapseSelection`, `q-md-table-interaction` и правила в `theme.ts`. |
| Overlay и открытый редактор ячейки после перехода между ячейками | Порядок `closeCellEditor` и `applySelection` в `selection.ts`, pointer-переход в `widgetSession.ts`. |

## Приёмочная проверка

Проверяйте в светлой и тёмной темах, без DevTools поверх окна:

1. Выделить слово двойным кликом и drag внутри активной ячейки — виден только
   полупрозрачный nested CodeMirror слой.
2. Начать drag в тексте ячейки и вывести указатель в соседнюю, включая
   объединённую, — текстовый слой исчезает, остаётся один overlay полного
   прямоугольника.
3. Выделить строку, столбец и диапазон через Shift — не виден слой parent
   CodeMirror.
4. Вне таблицы выделить обычный текст — табличный overlay и
   `q-md-table-interaction` отсутствуют.
5. Выделить таблицу Backspace из родительского текста, затем кликнуть ячейку —
   старое source-выделение не остаётся под таблицей.
6. Открыть и закрыть ячейку, перейти на другую, снять диапазон и удалить
   таблицу — после каждого перехода не остаётся ни overlay, ни скрывающего
   режима родителя.

Изменения в одном из перечисленных модулей требуют этой ручной проверки:
нативное выделение зависит от браузера и WebView и не может быть надёжно
покрыто только тестом модели таблицы.
