# Автодополнение ссылок в редакторе

## Назначение

По мере набора текста Aquilum показывает список заметок, чьи имена подходят под набранное, и
вставляет выбранную как `[[Заметка]]`. Список появляется и внутри уже набранных `[[ ]]`, и в обычном
тексте без скобок.

Референс поведения — плагин Obsidian [Various Complements](https://github.com/tadashi-aikawa/obsidian-various-complements-plugin),
режим *Internal link complement*. Из него взяты три вещи: приоритет «начало имени → начало слова →
середина», вид строки списка (имя сверху, путь снизу приглушённым) и набор настроек (вкл/выкл,
источник, минимум символов). Код плагина завязан на Obsidian API (`EditorSuggest`) и напрямую не
переносится: в Aquilum редактор — это CodeMirror 6.

## Почему штатный `@codemirror/autocomplete`

Свой попап не писался. Взято стандартное расширение CodeMirror, потому что оно уже решает то, что в
самодельном пришлось бы повторять: асинхронный источник с отменой устаревшего запроса,
позиционирование во всплывающем слое редактора, переворот списка вверх у нижнего края экрана,
прокрутка к выбранному пункту, клавиатура и ARIA.

Вес приложения от этого не вырос: пакет уже лежал в `node_modules` как транзитивная зависимость
`@codemirror/lang-*`, в `package.json` он просто объявлен прямой зависимостью.

Отрисовкой занимается сам CodeMirror, React в ней не участвует — набор текста не вызывает ни одного
ре-рендера дерева компонентов.

## Откуда берутся заметки

Источник — таблица `wiki_documents` индекса ссылок, та же, по которой разрешаются цели wikilink
(см. [[links-and-backlinks]]). В ней уже лежит строка на каждую заметку: путь, нормализованный
относительный путь и `title_key` — имя файла в нижнем регистре, с индексом `wiki_documents_title`.

Полнотекстовый индекс Tantivy для подсказок **не** используется, хотя `search_knowledge_base` умеет
префиксный поиск и бустит заголовок. Причина в том, что он ищет ещё и по телу заметки, поэтому в
выдачу попадали бы заметки, где набранное встречается в тексте, а не в названии. Для выбора цели
ссылки это шум.

Новой таблицы, кэша в памяти и фонового прогрева тоже нет: список имён не дублируется ни в Rust, ни в
JavaScript. Оперативная память под автодополнение не расходуется вообще, в JS живут только
показанные строки.

## Как устроен запрос

Два оператора SQL, оба по одному индексу:

1. **Начало имени** — диапазон `title_key >= ?1 AND title_key < ?1 || U+10FFFF`. Это обычный поиск по
   индексу, стоимость не зависит от размера хранилища. Обычный случай закрывается здесь.
2. **Середина имени** — `title_key LIKE '%ключ%'` с исключением уже найденного диапазона. Запускается
   только если первый оператор вернул меньше строк, чем нужно показать.

Диапазон записан явно, а не через `LIKE 'ключ%'`, потому что оптимизация `LIKE` в SQLite отключается
конструкцией `ESCAPE` и по-разному ведёт себя на не-ASCII. Явный диапазон предсказуем.

Ключ приводится к нижнему регистру на стороне Rust тем же `to_lowercase()`, которым строится
`title_key` при индексации, поэтому кириллица сравнивается корректно.

## Ранжирование

Кандидаты ранжируются в памяти, тремя ступенями:

| Ступень | Условие | Пример для «дми» |
| --- | --- | --- |
| 0 | имя начинается с ключа | `Дмитрий Чаплинский` |
| 1 | с ключа начинается слово внутри имени | `Иван Дмитриев` |
| 2 | ключ встречается в середине слова | `Кто такой аудмитрий` |
<!--q-table:{"merges":[],"cols":[90,260,220]}-->

Внутри ступени короче имя — выше, при равной длине порядок задаёт полный путь, чтобы результат был
устойчивым между вызовами.

Ступень 1 существует ровно ради случая, когда набирают фамилию: «Чапл» должно находить
«Дмитрий Чаплинский». Границами слова считаются пробел, дефис, подчёркивание, точка, запятая,
открывающая скобка и слеш.

Пул кандидатов вчетверо шире показанного списка: ранжировать имеет смысл только то, что уже прочитано,
а читать всё хранилище ради двенадцати строк незачем.

## Где стоит каретка

Одна функция `suggestContext` отвечает на вопрос «что сейчас заменяем», и у неё две ветки.

**Внутри скобок.** Сканируется текущая строка влево до последнего `[[`. Синтаксическое дерево для
этого не годится: парсер wikilink в `links/syntax.ts` возвращает `-1`, если `]]` не найден до конца
строки, — то есть ровно в тот момент, когда подсказка нужнее всего, узла `WikiLink` ещё не существует.
Поэтому незакрытая конструкция распознаётся наравне с закрытой, а сканирование ограничено строкой,
как и сама грамматика.

Если `]]` дальше по строке есть — заменяется текст до них, скобки остаются на месте. Если нет — `]]`
дописываются при вставке. Подсказка не предлагается после `|`: там пишется alias, а не цель.

**Вне скобок.** Берётся слово перед кареткой; вставляется `[[Имя]]` целиком. Слово после `#` не
подхватывается, чтобы не мешать вводу тегов.

В коде и во frontmatter список не показывается: перед обеими ветками проверяется узел
синтаксического дерева под кареткой.

## Возврат списка после удаления

`@codemirror/autocomplete` поднимает список только на пользовательское событие `input.type`.
Удаление даёт `delete.backward`, и оно умеет лишь поддерживать уже открытый список, но не открыть
закрытый. Из-за этого набранное слово, после которого поставили пробел, теряло подсказки навсегда:
пробел закрывал список (слова перед кареткой больше нет), а удаление пробела его не возвращало —
приходилось дописывать букву заново.

Поэтому на `EditorView.updateListener` висит возврат: если документ изменился удалением, список
сейчас закрыт и перед кареткой снова есть слово нужной длины — вызывается штатная команда
`startCompletion`. Диспатч из слушателя здесь допустим: CodeMirror возвращает `updateState` в
`Idle` до того, как обходит слушателей.

Открытый список эта ветка не трогает: `completionStatus` не `null` — выходим сразу, и удалением
внутри открытого списка по-прежнему управляет сам CodeMirror. Ввод текста она тоже не дублирует,
потому что срабатывает только на события `delete`.

## Клавиши

Подсказка принимается по `Enter`, закрывается по `Escape`, выбор двигают стрелки и `PageUp`/`PageDown`.
`Tab` намеренно не занят и остаётся отступом пункта списка.

Одного `Prec.highest` для этого мало. В `outline/commands.ts` на `Enter` висят три команды, а на `Tab` —
`indentMore` из `@codemirror/commands`, и всё это тоже с `Prec.highest`. При равном приоритете CodeMirror отдаёт клавишу тому
расширению, которое стоит в массиве раньше. Поэтому `noteSuggestExtension` собирается **первым**, до
`outlineExtension`: иначе `Tab` уходил в отступ и превращал слово под кареткой в блок кода, а `Enter`
точно так же ушёл бы в продолжение списка, и подсказка не принималась бы вовсе.

Перехвата при закрытом списке не происходит: каждая команда возвращает `false`, когда подсказок нет,
и клавиша уходит дальше по цепочке — в аутлайн и в стандартные команды редактора.

## Почему не мигает

Запрос уходит на каждое изменение текста, без `validFor` и без локальной фильтрации на стороне
CodeMirror: ранжирование принадлежит Rust, и второй, расходящийся с ним порядок в JS заводить не
нужно. Отсюда `filter: false` в результате.

Мигания это не вызывает, потому что CodeMirror держит предыдущий список отрисованным, пока не
разрешится новый промис источника. Никакого состояния «загрузка» нет — именно оно и выглядело бы как
мигание. Плюс ввод сглажен встроенной задержкой в 80 мс, а устаревшие ответы отсекаются флагом
`context.aborted`.

Высота строки в списке фиксирована, у списка задан `max-height`, поэтому попап не прыгает при
изменении числа результатов.

## Стоимость и лишние запросы

Вне скобок подсказки ищутся на каждое слово, поэтому набор обычного текста мог бы означать запрос на
каждую клавишу. Гасит это память о неудаче: если запрос не дал ни одного совпадения, он запоминается,
и всякий следующий запрос, который начинается с него, отсекается без обращения к Rust. Это корректно,
потому что совпадение ищется подстрокой: раз ни одно имя не содержит «фыв», то ни одно не содержит и
«фыва».

Память живёт три секунды. Ограничение нужно на время первичной индексации: тогда пустой ответ
означает лишь «пока не проиндексировано», и вечно доверять ему нельзя. Любой запрос с совпадениями
сбрасывает память сразу.

Что ещё не тратится впустую:

- в коде и во frontmatter запрос не уходит вовсе — контекст отсеивает их до обращения к Rust;
- короче минимума символов запрос не уходит;
- устаревшие ответы отбрасываются по `context.aborted`, а не перерисовывают список;
- функция вставки в `apply.ts` одна на весь модуль и читает имя из `completion.label`, поэтому на
  каждый показ списка не создаётся дюжина замыканий с захваченным контекстом.

Постоянного состояния у расширения нет: ни списка имён в памяти, ни подписок, ни таймеров. Между
запросами живёт только одна строка последнего пустого запроса. Утекать здесь нечему.

## Настройки

Раздел «Автодополнение» в настройках редактора:

- **Подсказки ссылок** — выключатель целиком;
- **Минимум символов** — со скольких набранных букв появляется список, по умолчанию 2.

Выбора источника подсказок в настройках нет намеренно. Сначала он был заведён на вырост, пунктами
«Заметки» и «Заметки и слова», но второе значение вело себя как первое, потому что источник слов не
написан. Настройка, которая ничего не меняет, хуже её отсутствия: она обещает поведение, которого
нет. Пункт и поле `linkSuggestSource` убраны и вернутся вместе с работающим источником слов.

## Оформление

Попап получает класс `q-suggest`, строка — `q-suggest__item`. Стили берут токены у плавающего меню
(`Menu.css`, Figma 85:849): фон `--q-dialog-bg`, тень `--q-elevation-float` с кольцом
`--q-shadow-ring`, радиусы `--q-radius-xl` / `--q-radius-lg`, внутренние отступы строки
`--q-padding-xs` (6px со всех сторон), минимальная высота `--q-size-20`. Выбранная строка подсвечена
нейтральным `--q-bg-surface-active`, а не accent-заливкой.

Наведение мыши — отдельное состояние на более слабом `--q-bg-surface-overlay`, и оно исключает
`[aria-selected]`. Разные токены нужны потому, что состояния независимы: выбор ведёт клавиатура, а
курсор в это время может стоять над другой строкой, и одинаковая заливка сделала бы непонятным, что
именно вставит Enter. Своего обработчика мыши здесь нет и быть не должно: CodeMirror слушает у списка
только `mousedown`, наведение он не трогает вовсе, поэтому состояние целиком живёт в CSS.

Готовый React-компонент `Menu` здесь применить нельзя: список рисует сам CodeMirror внутри своего
слоя подсказок, React в этом дереве не участвует. Общее у них — набор токенов, и он общий полностью.

### Специфичность: почему в селекторах есть `.cm-tooltip-autocomplete`

Базовая тема `@codemirror/autocomplete` объявляет `.cm-tooltip.cm-tooltip-autocomplete > ul` —
специфичность `(0,2,1)`, ровно такая же, как у `.cm-tooltip.q-suggest > ul`. При равной специфичности
побеждает правило, чей `<style>` вставлен в документ позже, а StyleModule CodeMirror монтируется
после CSS сборки Vite. Из-за этого первая версия стилей проигрывала молча: список получал из базовой
темы `max-height: 10em` (помещалось три строки) и `font-family: monospace`, то есть шрифт редактора
вместо интерфейсного.

Поэтому во всех селекторах присутствует и `.cm-tooltip-autocomplete`, и `.q-suggest`, а у строки —
ещё и `.q-suggest__item`: подсветка выбранного пункта в базовой теме объявлена как
`&light .cm-tooltip-autocomplete ul li[aria-selected]`, и её нужно перевесить тоже.

### Высота и края экрана

Отдельной логики подгонки под экран не писалось — она есть в CodeMirror. Слой подсказок измеряет
свободное место сверху и снизу от каретки, переворачивает попап на ту сторону, где места больше, и,
если и там не хватает, проставляет попапу `style.height` по доступному месту
(`@codemirror/view`, `tooltip.ts`). Список внутри при этом должен растянуться на всю высоту попапа и
прокручиваться — за это отвечает `height: 100%` вместе с `overflow: hidden auto` из базовой темы.

Отсюда правило: **`height: 100%` у `> ul` снимать нельзя.** Если его переопределить, попап перестанет
ужиматься и начнёт уезжать за край окна. Собственный `max-height` задаёт лишь верхний предел —
`min(22rem, calc(100vh - var(--q-space-16)))`, как у `Menu.css`.

### Шрифт

Шрифт списка совпадает с интерфейсным шрифтом приложения: `--q-font-family-ui`,
`--q-font-size-ui-base` и `--q-font-weight-ui-base` — те же три переменные, что стоят на `body` в
`styles/base.css`. Все три меняются из настроек, поэтому подсказки следуют за выбранным шрифтом
интерфейса автоматически.

Путь к папке в строке не показывается: он занимал вторую строку, из-за чего в попап помещалось вдвое
меньше заметок, а для выбора цели почти ничего не давал. Поле `folder` убрано и из ответа Rust —
чтобы не считать и не передавать то, что никто не читает.

## Подсветка совпадений

Буквы, из-за которых заметка попала в список, подсвечены — так же, как в результатах поиска по
хранилищу.

Собственного рендера для этого не писалось. У `@codemirror/autocomplete` есть штатный хук
`CompletionResult.getMatch`: он нужен как раз для случая `filter: false`, когда библиотека сама не
знает, что и где совпало. Хук возвращает плоский список чисел — пары «начало, конец» на строке
подписи, — а CodeMirror оборачивает эти куски в `span.cm-completionMatchedText`. Подчёркивание из
базовой темы снято, фон взят токеном `--q-search-match-bg` — тем же, что красит `<mark>` в карточке
результата поиска и подсветку Ctrl+F.

Сами диапазоны считает общий модуль `modules/search/matchRanges.ts`. Он вынут из
`components/Search/highlight.tsx`, где раньше лежал приватно, и теперь им пользуются обе дороги:
карточка результата поиска рисует по нему `<mark>`, а подсказки отдают его через `getMatch`. Модуль
складывает диакритику (`NFD` с отбрасыванием меток), поэтому «cafe» подсвечивается в «Café», и ведёт
карту позиций между свёрнутой и исходной строкой, чтобы вернуть смещения по оригиналу.

Разошлись две дороги ровно в одном: поиск по хранилищу засчитывает совпадение только в начале слова,
а подсказки — в любом месте имени, потому что и находят они заметки подстрокой. Это один параметр
`wordStartOnly`, а не вторая копия алгоритма; по умолчанию он включён, то есть поведение поиска по
хранилищу осталось прежним.

Компонент для этого не заводился и проп в существующий не добавлялся: карточку результата рисует
React, а список подсказок — сам CodeMirror внутри своего слоя, и общего узла рендера у них нет.
Общей может быть только логика, ей и сделан один дом.

## Ограничения текущей версии

- Alias из frontmatter в подсказках не участвует — ищется только имя файла.
- Папка заметки в списке не показывается, поэтому одноимённые заметки в строке неразличимы.
- Заголовки и блоки (`[[Заметка#Раздел]]`) не подсказываются.
- Текущая заметка не исключается из списка.
- Источник «слова из текущего документа» не реализован.
- Пока индекс ссылок ещё строится, список может быть неполным: он показывает то, что уже
  проиндексировано.

## Проверка поведения

1. В теле заметки набрать три буквы имени существующей заметки — под кареткой появляется список, и
   набранные буквы подсвечены в каждой строке.
2. Нажать `Enter` — слово заменяется на `[[Имя]]`, каретка встаёт после скобок.
3. Нажать `Tab` при открытом списке — подсказка не принимается, работает обычный отступ пункта.
4. Набрать `[[` и первые буквы имени — список появляется, `Enter` принимает, `]]` дописываются.
5. Внутри готовой `[[Заметка]]` поставить каретку после первых букв и выбрать другую цель — заменяется
   только цель, скобки остаются одни.
6. Набрать фамилию из середины имени заметки — она находится и стоит ниже совпадений по началу имени.
7. Набрать те же буквы внутри блока кода — списка нет.
8. Набрать имя, поставить пробел (список пропадает) и стереть пробел — список возвращается сам.
9. Выключить подсказки в настройках — список не появляется нигде.
