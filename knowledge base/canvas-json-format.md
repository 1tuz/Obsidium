# JSON Canvas

Obsidium opens `.canvas` files in the Canvas board view. The file remains JSON Canvas: standard `nodes` and `edges` are read and written in place, and unknown root, node, edge, and extension fields survive edits. Obsidium-specific board preferences live under `obsidium.canvas` so the board can store its paper palette, grid, and camera without changing the JSON Canvas fields.

Canvas edits use the workspace file gateway's snapshot hash as a write precondition. A concurrent external write stops autosave and keeps the local document in memory; the user can download that local JSON before choosing to reload the external version. Window close waits for every open board's pending write and is cancelled when a board cannot save. Invalid JSON is never auto-rewritten. File cards keep workspace-relative paths, render Markdown through the shared renderer, and refresh when the workspace index revision changes.

Opening a board establishes a serialized in-memory baseline and does not write the file. This keeps the original JSON bytes and formatting when the user only opens and closes a board; the next actual edit writes the parsed document through the serializer.

Paper palettes reuse the reading-style roles from `styles/themes/reading.css`; the global app theme remains responsible for light and dark mode. Canvas-local icon buttons use the paper ink token so tool icons stay visible when the app theme and board paper have different brightness. Canvas rendering mounts only objects intersecting the camera viewport, and retains off-screen nodes in the JSON model.

CanvasView stays inside the editor `<main>` so its toolbar, viewport, and cards share the same flex bounds. The editor area moves offstage only while the graph is active; hiding it for a selected Canvas tab also hides the Canvas itself.

The app creates empty boards through the command palette or the Canvas rail button and uses 16-character hexadecimal IDs for new nodes and edges. The Canvas toolbar searches indexed Markdown notes and adds the selected note as a workspace-relative file node. The connection tool links two cards by selecting the source and then the target; JSON Canvas stores the arrow and label. Rectangle, ellipse, and freehand tools remain standard JSON Canvas text nodes; their shape is stored in the node's `obsidium.shape` extension, and freehand points are stored in `obsidium.points`. Other JSON Canvas readers still see valid text nodes, while Obsidium renders the extension. Unknown fields are preserved. PNG export rasterizes generated SVG, so browser support for SVG `foreignObject` limits fidelity for rich Markdown and local images.

The selection tool uses the V key; T creates text, F adds a file, L adds a link, G groups selected cards, A connects cards, R draws a rectangle, E draws an ellipse, and P draws freehand. Undo and redo use the platform command key with Z, Shift+Z, or Y. Keyboard shortcuts work while the Canvas has focus. Paper style and grid remain board-local; selected cards and shapes can use the six theme color tokens or a custom color. Canvas paper styles remap the surface and icon tokens locally so the global app theme does not make toolbar icons disappear.

The active Canvas view is mounted by the pane renderer, while the live-tab layer keeps inactive documents warm. Rendering the active Canvas in both paths duplicated its board and toolbar; the live-tab layer now skips that active Canvas only. Other live tabs and intentionally split panes keep their existing behavior.
