# JSON Canvas

Obsidium opens `.canvas` files in the Canvas board view. Аудит, выбранная архитектура (DOM + SVG, без Konva) и план развития — [[canvas-editor-plan]]. The file remains JSON Canvas: standard `nodes` and `edges` are read and written in place, and unknown root, node, edge, and extension fields survive edits. Obsidium-specific board preferences live under `obsidium.canvas` so the board can store its paper palette, grid, and camera without changing the JSON Canvas fields.

Autosave treats failures in three separate buckets. A board that failed to load keeps no document and blocks saving, so stale content from a previous tab is never written into the failed target. A concurrent external write stops autosave through the snapshot hash. Errors from unrelated actions — opening a URL, exporting, dropping a file from outside the workspace, creating a note — are shown as action warnings and never gate autosave; otherwise one failed export would silently stop every later save until reload. The pane renderer keys each Canvas view by pane and path, so a view never switches boards in place; a failed read therefore leaves that view without a document and its fatal error blocks saving.

Canvas edits use the workspace file gateway's snapshot hash as a write precondition. A concurrent external write stops autosave and keeps the local document in memory; the user can download that local JSON before choosing to reload the external version. Window close waits for every open board's pending write and is cancelled when a board cannot save. Invalid JSON is never auto-rewritten. File cards keep workspace-relative paths, render Markdown through the shared renderer, and refresh when the workspace index revision changes.

Opening a board establishes a serialized in-memory baseline and does not write the file. This keeps the original JSON bytes and formatting when the user only opens and closes a board; the next actual edit writes the parsed document through the serializer.

Node positions and sizes accept finite JSON numbers, including fractions. Earlier app builds can save sub-pixel drag coordinates; rejecting them prevents those existing boards from reopening. Loading leaves their values intact and does not write the file until an edit occurs.

Paper palettes reuse the reading-style roles from `styles/themes/reading.css`; the global app theme remains responsible for light and dark mode. Canvas-local icon buttons use the paper ink token so tool icons stay visible when the app theme and board paper have different brightness. Canvas rendering mounts only objects intersecting a measured camera viewport, retains off-screen nodes in the JSON model, and temporarily mounts all nodes while the viewport has no size so a pending/hidden layout cannot make unselected objects disappear.

Inline board geometry is written with explicit pixel units. Preact 11 serializes a numeric `style` value as-is and does not append `px`, and the browser then drops the declaration: a node styled with `left: 120` ends up at `left: auto`. `modules/canvas/renderStyle.ts` (`canvasNodeStyle`, `canvasPixels`) is the single place that converts world coordinates and overlay offsets to `px` strings, and its test pins that contract. Tests in happy-dom cannot catch a regression here because happy-dom coerces numbers into pixels, so the helper test is the guard.

CanvasView stays inside the editor `<main>` so its toolbar, viewport, and cards share the same flex bounds. The editor area moves offstage only while the graph is active; hiding it for a selected Canvas tab also hides the Canvas itself.

The app creates empty boards through the command palette or the Canvas rail button, which is labelled as creation (`rail.canvas` = "New Canvas") because it always makes a new file instead of opening an existing board, and uses 16-character hexadecimal IDs for new nodes and edges. The Canvas toolbar searches indexed Markdown notes and adds the selected note as a workspace-relative file node. Press `/` or choose `/ Commands` to search Canvas actions, create a note, or find a note and place it on the board. New notes use the existing collision-safe document factory. Rectangle, diamond, and ellipse tools draw from pointer down to pointer up, normalize either drag direction, and use a 160×100 size when clicked without dragging; freehand remains a separate tool. Shape, number marker, and freehand nodes remain standard JSON Canvas text nodes with their details in the `obsidium.shape` extension, and freehand points are stored in `obsidium.points`. Number markers increase from the largest existing value. Eight resize handles preserve the opposite edge or corner; holding Shift locks the shape's aspect ratio. Other JSON Canvas readers still see valid text nodes, while Obsidium renders the extension. Unknown fields are preserved.

Shape geometry is drawn by a dedicated SVG layer inside the node, not by an HTML border. A rectangle is a `rect`, a diamond is a `polygon`, an ellipse and a number marker are `ellipse` elements, and freehand stays a quadratic path through `obsidium.points`. This removes the old `clip-path` on the card, which used to cut the diamond's border and its text. The default stroke is mixed from the paper ink (`color-mix(in srgb, ink 78%, paper)`), and the default fill is mixed from the same ink at 20%; both stay readable on light, dark, and paper palettes (measured stroke contrast 4.5:1…9.1:1 across the five palettes in both themes; fill 1.4:1…1.8:1). `obsidium.fill: 'transparent'` disables the fill for a node, and its absence means the default fill; the canvas controls expose that choice for new and selected shapes. Stroke width is expressed in world units as `2 / zoom`, so the on-screen outline stays two pixels from 0.2× to 2.5×. Selection is a separate outline and separate handles: selecting or deselecting never changes the node's fill or stroke. The resize handles and the connection dots are counter-scaled by the same `1 / zoom` factor, so they stay the same screen size at every zoom.

Export builds the SVG through `modules/canvas/svgExport.ts` from the whole document, never from the viewport or the selection. Nodes paint in document order, shapes use the same geometry as the board, freehand paths are wrapped in `translate(node.x, node.y)`, number markers are ellipses, and groups keep a dashed frame. Edge arrows use one marker per distinct colour with `markerUnits="userSpaceOnUse"`, honour both start and end arrow settings, and labels sit at the routed midpoint over a paper-coloured halo. The palette is resolved to concrete colours through a probe element, so no `var(...)` or `color-mix(...)` reaches the file; Chromium computes mixed colours as `color(srgb ...)`, and `modules/canvas/colorMix.ts` parses that form as well as hex and `rgb()`. An image whose bytes could not be embedded becomes a labelled placeholder instead of an `<image>` with an `asset:` URL, because drawing that URL taints the canvas and makes the PNG download fail. Local and external images are fetched and embedded as data URLs; video becomes a labelled card with a play triangle, because a still image cannot play.

The SVG file keeps rich Markdown inside `foreignObject`. PNG uses the same builder with `textMode: 'svg'`: card text becomes real `<text>`/`<tspan>` lines wrapped on word boundaries, because Chromium and WebKit taint a canvas that draws a `foreignObject`, and `toBlob` would then fail. PNG rasterizes that SVG in a canvas capped at 4096 px on the long side, and a rasterization failure surfaces as the existing export warning instead of an empty download.

Shape icons in the canvas toolbar and the selection-bar glyphs are local SVG nodes in `CanvasGlyphs.tsx` rather than new entries in the app-wide icon catalog, because they are canvas-specific affordances; the catalog test requires every Lucide icon imported anywhere in `src` to exist in all three icon sets.

Selected connections and selected cards are mutually exclusive: selecting a card clears the connection selection, so Delete removes the object the user just picked instead of the connection chosen earlier.

Connections are made two ways. The `A` tool picks a source card and then a target card, which is precise but slow. Dragging one of the four connector dots that appear on hover is the fast path: pressing a dot starts a `connect` drag, the board draws a dashed preview from that side to the pointer, and releasing over another card creates the edge with the source side fixed to the dragged dot and the target side chosen by `canvasEdgeSides`. Releasing over empty space cancels without creating anything. Both paths write the same JSON Canvas edge, so a board made by dragging opens in other editors and vice versa.

Cards accept media from outside. Dropping image or video files imports them through `importIntoFiles` into the configured attachments folder and places one file card per file, offset by the grid step so a multi-file drop does not stack them. Pasting an image onto the board does the same at the last pointer position. Clipboard reading prefers `clipboardData.files`, then falls back to `clipboardData.items` with `kind: 'file'`, because a screenshot in the WebView often arrives only as an item; pasting a plain-text URL that points at an image creates a link card instead. A drop that carries a text URL or a workspace path outside the vault creates a link card when the target is an image, and otherwise reports the workspace warning. This reuses the editor's import path, so names, collisions and the `Files` folder setting behave identically.

Media paths resolve by context, not by one global base. A file node's own `file` is workspace-relative, so its image or video URL is built from the workspace root. Markdown inside a file note resolves images from the note's directory. Markdown in a text card, and a relative URL in a link card, resolve from the directory of the `.canvas` file. `http:`, `https:`, `data:`, `asset:`, `blob:` and absolute filesystem paths pass through unchanged. `resolveCanvasMedia` in `modules/canvas/media.ts` normalizes separators, percent escapes, `.`/`..`, spaces and Cyrillic, refuses paths that leave the workspace, and returns the media kind from the resolved extension. Image file nodes render an `<img>` with the file name only as its accessible label; video file nodes render `<video controls preload="metadata" playsinline>`, never autoplay. Both report loading and error states, and media outside the measured viewport is not mounted, so decoded images do not accumulate off-screen. Markdown file previews are cached per path and workspace revision, so panning does not re-read every visible note.


Freehand strokes are stored as points in `obsidium.shape.points` and rendered as a quadratic path through midpoints (`canvasFreehandPath`), not as a polyline: the midpoint chain removes the visible corners of a fast stroke without adding points to the file. The same path builder feeds the board and the SVG export, so what the user draws is what the export contains.

Node order in `nodes` is paint order. The world gives each painted node a `z-index` taken from its position in that filtered document order, so a reorder changes both the painted stacking and hit-testing, and viewport culling cannot reshuffle the stacking of the nodes that remain. `Cmd/Ctrl+]` brings the selection to the front and `Cmd/Ctrl+[` sends it back; the compact selection bar and the card context menu expose the same two actions. Double-clicking a group edits its label in place instead of only through the menu; Enter or Escape commits it.

The selection bar sits above the selection's bounding box and offers bring-to-front, send-to-back, duplicate, group, ungroup and delete. It appears only while something is selected and no drag or text edit is running. Ungroup removes the group frames and keeps their members selected; Delete on a group also keeps the members, so grouping is never a way to lose content by accident. Resize handles are shown only when exactly one node is selected, which keeps multi-selection and group frames free of eight marker squares per member. Connection dots are rendered for the selection and connection tools, appear on hover, and are inert while hidden.

Link cards are created and edited through the shared `Dialog` (`CanvasLinkDialog`), not `window.prompt`: the browser prompt blocks the WebView, cannot be styled or translated, and leaves no place for validation. The dialog accepts absolute `http`, `https`, `mailto` and `tel` addresses and workspace-relative paths, rejects protocol-relative `//host` values and any other scheme, and keeps the dialog open with an inline message when the address is invalid. The same validator guards both the add and edit paths, so an edited link cannot smuggle a `javascript:` URL into the board.

A text card that is left empty when editing ends is removed instead of staying as an invisible box on the board; shapes, freehand strokes and number markers are exempt because their `obsidium.shape` carries meaning without text. Escape in the text editor commits and closes it, so the user does not have to click outside the card. While the user types, the textarea reports its scroll height and the card grows downward when the text no longer fits, so long notes do not scroll inside a 180-pixel box; the card never shrinks automatically, because that would fight a manual resize.

Paper styles in the toolbar reuse the `settings.editor.styles.*` translations shared with the reading-style settings; a separate `editor.styles.*` namespace never existed and surfaced raw keys in the menu.

Panning and zooming are board view state, not document content. A pan never records an undo step; undo and redo restore scene content but keep the current camera, including the camera they write into the restored document and into `history.current`. Without that, undo would persist an old viewport and reopening the board would jump back. A no-op undo or redo returns the same history object and changes nothing.

Camera math lives in `modules/canvas/viewport.ts` and is pure, so the same functions serve the board, fit-to-content, and tests. A plain wheel or trackpad scroll pans the board; the platform command key with the wheel zooms around the pointer, keeping the world point under the cursor fixed. Zoom is clamped to 0.2–2.5. `Cmd/Ctrl+0` resets the camera, `Cmd/Ctrl+=` and `Cmd/Ctrl+-` zoom around the viewport center, and `Shift+1` fits every node with padding and caps the result at 100%, so a single small card is not blown up. Holding Space switches the pointer to a hand: pressing on empty space or on a card pans the board instead of starting a marquee or moving the card, and releasing Space restores the tool. Camera writes are debounced: a wheel gesture updates React state immediately and persists the camera into `obsidium.canvas.camera` once, after the gesture settles, so a long pan does not serialize the document on every frame.

The selection tool uses the V key; T creates text, F adds a file, L adds a link, G groups selected cards, A connects cards, R draws a rectangle, D draws a diamond, E draws an ellipse, N places a sequential number marker, and P draws freehand. Undo and redo use the platform command key with Z, Shift+Z, or Y. `Cmd/Ctrl+D` duplicates the selection together with edges whose both ends are selected, `Cmd/Ctrl+A` selects every card, and arrow keys nudge the selection by one unit or by the grid step with Shift. Enter edits a selected text card or opens a selected file or link card, Escape leaves editing and clears selection, and Delete removes the selected card or connection. Keyboard shortcuts work while the Canvas has focus. Paper style and grid remain board-local. The toolbar color menu applies one of six theme colors to selected cards or connections and sets the color for new objects. Explicit saved colors take precedence; without one, shapes use the paper-ink stroke and fill described above, and connections use the neutral canvas edge token. Unstyled connections use straight lines by default and can switch to elbow or curved routes; dragging the selected route handle changes its bend offset while its endpoints remain attached to nodes. Grid lines and dots mix the paper and ink tokens so they stay visible across both app themes and paper styles. Canvas paper styles remap the surface and icon tokens locally so the global app theme does not make toolbar icons disappear.

A selection shows one compact action bar above its bounding box: bring to front, send to back, duplicate, group or ungroup, and delete. The same actions remain in the right-click menu. Resize handles appear only when exactly one node is selected; a multi-node selection shows no per-node handles, which keeps group members from covering each other with marker squares. Connection dots appear on hover and while the connection tool is active, and hidden dots do not accept pointer events. Ungroup removes only the selected group nodes and keeps their members, selecting them afterwards.


Canvas cards render Markdown through the shared print renderer with `noteLinks: true`. That opt-in adds `data-note-target` and `data-note-source` (wiki or markdown) and nothing else; export and PDF keep the plain renderer, so their HTML never gains canvas-only attributes. `[[note|alias]]`, `[[folder/note#Heading]]` and `[[note#^block]]` go to the same wiki resolver the editor uses; aliases are display-only and the raw target keeps its fragment. Relative Markdown note links are filesystem paths, not wiki names, and resolve once through `resolveNotePath` in `modules/paths.ts`, which normalizes separators, decodes percent escapes and refuses anything that leaves the workspace. Their base is the embedded note directory for file cards and the canvas directory for text cards. A resolved relative path that fails must not fall back to the wiki resolver, because that could open an unrelated note with the same basename. Activation is a delegated click and Enter on a focusable anchor; the handler prevents the default before navigation, so a failure surfaces as the Canvas action warning instead of leaving the WebView. External `http`, `https`, `mailto` and `tel` still go to the opener, and the sanitizer still blocks `javascript:` and `data:`.

Heading and block fragments land on a real editor offset, never on the top of the note: `noteEmbedOffset` reports the heading line start or the block marker, skipping fenced code, matching block ids only as a whole identifier, and converting CRLF to the single `\n` that CodeMirror stores, so the offset addresses the editor document rather than the raw file. Merged embed parsing and anchor offsets share that one helper rather than re-implementing fenced code scanning. Unsupported backlink integration remains out of scope here; Canvas links do not create graph edges.

Renaming or moving a note also rewrites `file` nodes in boards whose stored path points at the moved note. The rewrite runs inside the existing rename owner in `core/src/files/gate.rs` (`files/canvas_refs.rs`): it preflights every board hash, writes atomically with the same precondition, and rolls back the boards it already wrote when a later write fails. Boards are scanned from the moved path's parent, which covers a renamed file and every board in a renamed or moved folder; a board that changed after the preflight stops the rename with the existing conflict error instead of overwriting concurrent edits. Relative Markdown links inside card text are not rewritten yet, and only file nodes participate.

The active Canvas view is mounted by the pane renderer, while the live-tab layer keeps inactive documents warm. Rendering the active Canvas in both paths duplicated its board and toolbar; the live-tab layer now skips that active Canvas only. Other live tabs and intentionally split panes keep their existing behavior.
