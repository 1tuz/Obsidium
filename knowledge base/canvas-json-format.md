# JSON Canvas

Obsidium opens `.canvas` files in the Canvas board view. Аудит, выбранная архитектура (DOM + SVG, без Konva) и план развития — [[canvas-editor-plan]]. The file remains JSON Canvas: standard `nodes` and `edges` are read and written in place, and unknown root, node, edge, and extension fields survive edits. Obsidium-specific board preferences live under `obsidium.canvas` so the board can store its paper palette, grid, and camera without changing the JSON Canvas fields.

Autosave treats failures in three separate buckets. A board that failed to load keeps no document and blocks saving, so stale content from a previous tab is never written into the failed target. A concurrent external write stops autosave through the snapshot hash. Errors from unrelated actions — opening a URL, exporting, dropping a file from outside the workspace, creating a note — are shown as action warnings and never gate autosave; otherwise one failed export would silently stop every later save until reload. The pane renderer keys each Canvas view by pane and path, so a view never switches boards in place; a failed read therefore leaves that view without a document and its fatal error blocks saving.

Canvas edits use the workspace file gateway's snapshot hash as a write precondition. A concurrent external write stops autosave and keeps the local document in memory; the user can download that local JSON before choosing to reload the external version. Window close waits for every open board's pending write and is cancelled when a board cannot save. Invalid JSON is never auto-rewritten. File cards keep workspace-relative paths, render Markdown through the shared renderer, and refresh when the workspace index revision changes.

Opening a board establishes a serialized in-memory baseline and does not write the file. This keeps the original JSON bytes and formatting when the user only opens and closes a board; the next actual edit writes the parsed document through the serializer.

Node positions and sizes accept finite JSON numbers, including fractions. Earlier app builds can save sub-pixel drag coordinates; rejecting them prevents those existing boards from reopening. Loading leaves their values intact and does not write the file until an edit occurs.

Paper palettes reuse the reading-style roles from `styles/themes/reading.css`; the global app theme remains responsible for light and dark mode. Canvas-local icon buttons use the paper ink token so tool icons stay visible when the app theme and board paper have different brightness. Canvas rendering mounts only objects intersecting a measured camera viewport inflated by a 200-pixel margin (`CANVAS_VIEW_MARGIN_PX`, `canvasVisibleBounds` and `canvasNodeVisible` in `modules/canvas/viewport.ts`), retains off-screen nodes in the JSON model, and temporarily mounts all nodes while the viewport has no size so a pending/hidden layout cannot make unselected objects disappear. The margin is what keeps a card from popping in exactly at the screen edge during a pan; selected nodes are mounted even when off-screen so a drag, resize or text edit never loses its element mid-gesture.

Inline board geometry is written with explicit pixel units. Preact 11 serializes a numeric `style` value as-is and does not append `px`, and the browser then drops the declaration: a node styled with `left: 120` ends up at `left: auto`. `modules/canvas/renderStyle.ts` (`canvasNodeStyle`, `canvasPixels`) is the single place that converts world coordinates and overlay offsets to `px` strings, and its test pins that contract. Tests in happy-dom cannot catch a regression here because happy-dom coerces numbers into pixels, so the helper test is the guard.

CanvasView stays inside the editor `<main>` so its toolbar, viewport, and cards share the same flex bounds. The editor area moves offstage only while the graph is active; hiding it for a selected Canvas tab also hides the Canvas itself.

The app creates empty boards through the command palette or the Canvas rail button, which is labelled as creation (`rail.canvas` = "New Canvas") because it always makes a new file instead of opening an existing board, and uses 16-character hexadecimal IDs for new nodes and edges. The Canvas toolbar opens a note picker that searches indexed Markdown notes and adds the selected note as a workspace-relative file node. An empty query lists recent notes from the existing navigation history (topped up from the search index when history is empty), and a query with no exact title match offers a create row that makes a note with that title through the document factory, so adding a note never starts from an empty dialog. `modules/canvas/recentNotes.ts` reuses both sources instead of building a third listing. Press `/` or choose `/ Commands` to search Canvas actions, create a note, or find a note and place it on the board. New notes use the existing collision-safe document factory. Rectangle, diamond, and ellipse tools draw from pointer down to pointer up, normalize either drag direction, and use a 160×100 size when clicked without dragging; freehand remains a separate tool. Shape, number marker, and freehand nodes remain standard JSON Canvas text nodes with their details in the `obsidium.shape` extension, and freehand points are stored in `obsidium.points`. Number markers increase from the largest existing value. Eight resize handles preserve the opposite edge or corner; holding Shift locks the shape's aspect ratio. Other JSON Canvas readers still see valid text nodes, while Obsidium renders the extension. Unknown fields are preserved.

Shape geometry is drawn by a dedicated SVG layer inside the node, not by an HTML border. A rectangle is a `rect`, a diamond is a `polygon`, an ellipse and a number marker are `ellipse` elements, and freehand stays a quadratic path through `obsidium.points`. This removes the old `clip-path` on the card, which used to cut the diamond's border and its text. The default stroke is mixed from the paper ink (`color-mix(in srgb, ink 78%, paper)`), and the default fill is mixed from the same ink at 20%; both stay readable on light, dark, and paper palettes (measured stroke contrast 4.5:1…9.1:1 across the five palettes in both themes; fill 1.4:1…1.8:1). Shapes are created with `obsidium.fill: 'transparent'` and no fill of their own: an unfilled outline is what a diagram needs first, and the properties panel adds a background in one click. The fill choice lives only there, so the toolbar no longer carries a second, conflicting control. `obsidium.fill` accepts `'transparent'` or a preset key `'1'`…`'6'`; an absent key means no fill as well, because a shape whose interior is silently derived from the stroke colour reads as "the stroke painted the whole figure" — exactly the confusion this rule removes.

Fill reaches the SVG as an inline `fill` style, not as a presentation attribute. `.q-canvas__shape-body { fill: var(--q-canvas-shape-fill) }` beats a `fill="..."` attribute in the cascade, so the attribute was ignored and every shape kept the neutral ink tint no matter which swatch was pressed; an inline style outranks the stylesheet and wins. The preset is mixed with the paper at 42 %, which stays a recognisable colour on both light and dark paper instead of washing out to grey. Stroke width is expressed in world units as `2 / zoom`, so the on-screen outline stays two pixels from 0.25× to 2×. Selection is a separate outline and separate handles: selecting or deselecting never changes the node's fill or stroke. The resize handles and the connection dots are counter-scaled by the same `1 / zoom` factor, so they stay the same screen size at every zoom.

Export builds the SVG through `modules/canvas/svgExport.ts` from the whole document, never from the viewport or the selection. Nodes paint in document order, shapes use the same geometry as the board, freehand paths are wrapped in `translate(node.x, node.y)`, number markers are ellipses, and groups keep a dashed frame. Edge arrows in the exported SVG use one marker per distinct colour with `markerUnits="userSpaceOnUse"`, honour both start and end arrow settings, and labels sit at the routed midpoint over a paper-coloured halo. The board itself draws arrowheads as `<polygon>` elements computed by `canvasEdgeArrowheads`, not as SVG markers: a marker inherits `fill` through `context-fill` semantics that WebKit (the shipping Tauri engine) resolves to the path's stroke, so the head rendered as a hairline, and `markerUnits="strokeWidth"` scaled it by the one-pixel edge width. The polygon is derived from the routed tangent, so an elbow or curved line points along its last segment instead of along the straight centre-to-centre direction. The palette is resolved to concrete colours through a probe element, so no `var(...)` or `color-mix(...)` reaches the file; Chromium computes mixed colours as `color(srgb ...)`, and `modules/canvas/colorMix.ts` parses that form as well as hex and `rgb()`. An image whose bytes could not be embedded becomes a labelled placeholder instead of an `<image>` with an `asset:` URL, because drawing that URL taints the canvas and makes the PNG download fail. Local and external images are fetched and embedded as data URLs; video becomes a labelled card with a play triangle, because a still image cannot play.

The SVG file keeps rich Markdown inside `foreignObject`. PNG uses the same builder with `textMode: 'svg'`: card text becomes real `<text>`/`<tspan>` lines wrapped on word boundaries, because Chromium and WebKit taint a canvas that draws a `foreignObject`, and `toBlob` would then fail. PNG rasterizes that SVG in a canvas capped at 4096 px on the long side, and a rasterization failure surfaces as the existing export warning instead of an empty download.

Shape icons in the canvas toolbar and the selection-bar glyphs are local SVG nodes in `CanvasGlyphs.tsx` rather than new entries in the app-wide icon catalog, because they are canvas-specific affordances; the catalog test requires every Lucide icon imported anywhere in `src` to exist in all three icon sets.

Selected connections and selected cards are mutually exclusive: selecting a card clears the connection selection, so Delete removes the object the user just picked instead of the connection chosen earlier.

Connections are made three ways, and all of them write the same JSON Canvas edge, so a board made by dragging opens in other editors and vice versa. The fastest path is the arrow tool: with `A` armed, pressing a card and dragging to another card creates the edge on release and picks both sides through `canvasEdgeSides`, the way Excalidraw binds an arrow; a press that never moves more than four pixels is not a drag, so the plain click still runs the older two-step path. That second path picks a source card and then a target card, which is precise but slow. The third path is dragging one of the four connector dots that appear on hover: pressing a dot starts the same `connect` drag, the board draws a dashed preview from that side to the pointer, and releasing over another card creates the edge with the source side fixed to the dragged dot. Releasing over empty space cancels without creating anything. An auto drag previews from the card centre, because no side has been chosen yet.

Cards accept media from outside. Dropping image or video files imports them through `importIntoFiles` into the configured attachments folder and places one file card per file, offset by the grid step so a multi-file drop does not stack them. Pasting an image onto the board does the same at the last pointer position. Clipboard reading prefers `clipboardData.files`, then falls back to `clipboardData.items` with `kind: 'file'`, because a screenshot in the WebView often arrives only as an item; pasting a plain-text URL that points at an image creates a link card instead. A drop that carries a text URL or a workspace path outside the vault creates a link card when the target is an image, and otherwise reports the workspace warning. This reuses the editor's import path, so names, collisions and the `Files` folder setting behave identically.

Media paths resolve by context, not by one global base. A file node's own `file` is workspace-relative, so its image or video URL is built from the workspace root. Markdown inside a file note resolves images from the note's directory. Markdown in a text card, and a relative URL in a link card, resolve from the directory of the `.canvas` file. `http:`, `https:`, `data:`, `asset:`, `blob:` and absolute filesystem paths pass through unchanged. `resolveCanvasMedia` in `modules/canvas/media.ts` normalizes separators, percent escapes, `.`/`..`, spaces and Cyrillic, refuses paths that leave the workspace, and returns the media kind from the resolved extension. Image file nodes render an `<img>` with the file name only as its accessible label; video file nodes render `<video controls preload="metadata" playsinline>`, never autoplay. Both report loading and error states, and media outside the measured viewport is not mounted, so decoded images do not accumulate off-screen. Markdown file previews are cached per path and workspace revision, so panning does not re-read every visible note.


Freehand strokes are stored as points in `obsidium.shape.points` and rendered as a quadratic path through midpoints (`canvasFreehandPath`), not as a polyline: the midpoint chain removes the visible corners of a fast stroke without adding points to the file. The same path builder feeds the board and the SVG export, so what the user draws is what the export contains.

Node order in `nodes` is paint order. The world gives each painted node a `z-index` taken from its position in that filtered document order, so a reorder changes both the painted stacking and hit-testing, and viewport culling cannot reshuffle the stacking of the nodes that remain. `Cmd/Ctrl+]` brings the selection to the front and `Cmd/Ctrl+[` sends it back; the compact selection bar and the card context menu expose the same two actions. Double-clicking a group edits its label in place instead of only through the menu; Enter or Escape commits it.

One properties panel replaces the old selection bar and the old connection bar. It is anchored to the board's top-right corner rather than to the selection: a panel that follows the selection moves under the pointer, covers the very object being edited, and jumps when a resize changes the bounding box. The panel is a fixed-height column with its own scroll, so it never grows past the viewport. It appears while something is selected and no drag or text edit is running, and its close button clears only the selection it belongs to.

The panel edits the object, not the document: stroke colour, background, stroke width and style, corners, font family, size and alignment, opacity, layer order, duplicate, group, ungroup and delete. Every control writes through `withCanvasAppearance`, which stores only values that differ from the node's defaults and deletes the key when a value returns to the default, so a board keeps the compact JSON Canvas shape instead of accumulating `strokeWidth: 2` on every node. A multi-selection applies the patch to every selected node and shows the appearance of the first one; the count appears in the header.

Selecting a connection never leaves its panel behind: an empty-stage press, a marquee start, Escape, and any new shape, draw or connect drag clear `selectedEdgeId`. Earlier the edge panel could only be dismissed by selecting something else, so it sat on the board after the user had moved on.

Ungroup removes the group frames and keeps their members selected; Delete on a group also keeps the members, so grouping is never a way to lose content by accident. Resize handles are drawn once on the selection frame for a multi-selection and on the group's own frame for a selected group, never eight per member: `resizeCanvasSelection` scales every selected node from the original selection bounds, and a selected group scales its members through `resizeCanvasGroup`. A single non-group node keeps its own eight handles. The frame sits above the node layer, so a group's handles are reachable even when its members fill it. Connection dots appear on hover and while the connection tool is active, and are inert while hidden.

Link cards are created and edited through the shared `Dialog` (`CanvasLinkDialog`), not `window.prompt`: the browser prompt blocks the WebView, cannot be styled or translated, and leaves no place for validation. The dialog accepts absolute `http`, `https`, `mailto` and `tel` addresses and workspace-relative paths, rejects protocol-relative `//host` values and any other scheme, and keeps the dialog open with an inline message when the address is invalid. The same validator guards both the add and edit paths, so an edited link cannot smuggle a `javascript:` URL into the board.

A text card that is left empty when editing ends is removed instead of staying as an invisible box on the board; shapes, freehand strokes and number markers are exempt because their `obsidium.shape` carries meaning without text. Escape in the text editor commits and closes it, so the user does not have to click outside the card. While the user types, the textarea reports its scroll height and the card grows downward when the text no longer fits, so long notes do not scroll inside a 180-pixel box; the card never shrinks automatically, because that would fight a manual resize.

Paper styles in the toolbar reuse the `settings.editor.styles.*` translations shared with the reading-style settings; a separate `editor.styles.*` namespace never existed and surfaced raw keys in the menu.

Panning and zooming are board view state, not document content. A pan never records an undo step; undo and redo restore scene content but keep the current camera, including the camera they write into the restored document and into `history.current`. Without that, undo would persist an old viewport and reopening the board would jump back. A no-op undo or redo returns the same history object and changes nothing.

Camera math lives in `modules/canvas/viewport.ts` and is pure, so the same functions serve the board, fit-to-content, and tests. A plain wheel or trackpad scroll pans the board; the platform command key with the wheel zooms around the pointer, keeping the world point under the cursor fixed. Zoom is clamped to 0.25–2 (`MIN_CANVAS_ZOOM`/`MAX_CANVAS_ZOOM`) and the zoom buttons plus `Cmd/Ctrl+=`/`Cmd/Ctrl+-` step through the fixed levels `0.25 / 0.5 / 1 / 1.5 / 2` (`nextCanvasZoom`), so a keypress lands on a legible scale instead of an arbitrary factor and stops at both bounds; the pointer-anchored wheel zoom stays continuous inside the same bounds. Panning is bounded by the content: `clampCanvasCamera` keeps the visible rect inside the node bounds padded by 100 pixels (`CANVAS_PAN_PADDING_PX`) and centres content smaller than the viewport, so the board cannot be lost off-screen. Because the pane renderer remounts a Canvas view when it becomes the active tab, `modules/canvas/persistence.ts` also keeps the last camera per path in session memory (`rememberCanvasCamera`/`recalledCanvasCamera`); the document stays the source of truth, but a remount no longer reads a stale camera off disk before the debounced write lands. `Cmd/Ctrl+0` resets the camera, and `Shift+1` fits every node with padding and caps the result at 100%, so a single small card is not blown up. Holding Space switches the pointer to a hand: pressing on empty space or on a card pans the board instead of starting a marquee or moving the card, and releasing Space restores the tool. Camera writes are debounced: a wheel gesture updates React state immediately and persists the camera into `obsidium.canvas.camera` once, after the gesture settles, so a long pan does not serialize the document on every frame.

Tools stay armed until Escape. Drawing a rectangle, diamond, ellipse, freehand stroke or number marker no longer flips the board back to the selection tool, so several shapes in a row need one keystroke instead of one per shape. `Escape` clears the selection and returns to `V`; picking another tool replaces the armed one. The previous behaviour made a multi-shape diagram a repeated `R`-drag-`R`-drag cycle and hid the fact that the tool was still active.

Connection dots sit on the node edge, not eight pixels outside it. The old offset left a dead gap between the card and its dot: the dot faded out and became `pointer-events: none` while the pointer crossed the gap, so a drag could not reach it at all. A dot now overlaps the card by half its width, keeps `:hover` alive through the transition, and stays visible while the pointer travels toward it.

The selection tool uses the V key; T creates text, F adds a file, L adds a link, G groups selected cards, A connects cards, R draws a rectangle, D draws a diamond, E draws an ellipse, N places a sequential number marker, and P draws freehand. A shape tool stays armed after a shape is drawn, so a diagram is drawn with one keystroke instead of one per shape, but it never takes over an existing card: pressing on a node with `R`, `D` or `E` armed selects and drags that node and falls back to the selection tool. Drawing continues to start from empty canvas. Undo and redo use the platform command key with Z, Shift+Z, or Y. `Cmd/Ctrl+D` duplicates the selection together with edges whose both ends are selected, `Cmd/Ctrl+A` selects every card, and arrow keys nudge the selection by one unit or by the grid step with Shift. Enter edits a selected text card or opens a selected file or link card, Escape leaves editing and clears selection, and Delete removes the selected card or connection. Keyboard shortcuts work while the Canvas has focus. Paper style and grid remain board-local. Stroke and background colour are chosen in the properties panel from six theme presets; an explicit saved colour takes precedence, and without one shapes use the paper-ink stroke and connections use the neutral canvas edge token. The toolbar keeps no colour control of its own: a second colour menu that only affected the next created object was the most confusing control on the board. Unstyled connections use straight lines by default and can switch to elbow or curved routes; dragging the selected route handle changes its bend offset while its endpoints remain attached to nodes. Grid lines and dots mix the paper and ink tokens so they stay visible across both app themes and paper styles. Canvas paper styles remap the surface and icon tokens locally so the global app theme does not make toolbar icons disappear.

A group is a real container, not a decorative frame. `expandCanvasSelection` in
`modules/canvas/interaction.ts` closes a selection over groups in both directions: picking a group adds
its members, and picking a member adds the group plus every sibling. Without that closure a member could
be dragged out of its frame, which turned the group into a rectangle that happened to be drawn around
two cards. `resizeCanvasGroup` maps each member's rect from the original frame into the resized one, so
dragging a group handle scales its contents instead of leaving them at the old size inside a bigger
frame. Reorder treats a group and its members as one block, otherwise bringing a group to the front
would lift the frame above cards that should still cover it.

Members of a selected group render without their own selection outline, resize handles or connection
dots: the group frame carries all of that. A group member is still individually selectable after
ungrouping, and a click on it inside the group selects the group, so the handles never multiply into
eight markers per card. Connection dots also stopped appearing for a plain selection — they belong to
hover and to the connection tool — because a selected card used to show eight resize markers and four
dots at once, and the dots competed with the shape itself.

A selection shows one compact action bar above its bounding box: bring to front, send to back, duplicate, group or ungroup, and delete. The same actions remain in the right-click menu. Resize handles appear only when exactly one node is selected; a multi-node selection shows no per-node handles, which keeps group members from covering each other with marker squares. Connection dots appear on hover and while the connection tool is active, and hidden dots do not accept pointer events. Ungroup removes only the selected group nodes and keeps their members, selecting them afterwards.


Canvas cards render Markdown through the shared print renderer with `noteLinks: true`. That opt-in adds `data-note-target` and `data-note-source` (wiki or markdown) and nothing else; export and PDF keep the plain renderer, so their HTML never gains canvas-only attributes. `[[note|alias]]`, `[[folder/note#Heading]]` and `[[note#^block]]` go to the same wiki resolver the editor uses; aliases are display-only and the raw target keeps its fragment. Relative Markdown note links are filesystem paths, not wiki names, and resolve once through `resolveNotePath` in `modules/paths.ts`, which normalizes separators, decodes percent escapes and refuses anything that leaves the workspace. Their base is the embedded note directory for file cards and the canvas directory for text cards. A resolved relative path that fails must not fall back to the wiki resolver, because that could open an unrelated note with the same basename. Activation is a delegated click and Enter on a focusable anchor; the handler prevents the default before navigation, so a failure surfaces as the Canvas action warning instead of leaving the WebView. External `http`, `https`, `mailto` and `tel` still go to the opener, and the sanitizer still blocks `javascript:` and `data:`.

Heading and block fragments land on a real editor offset, never on the top of the note: `noteEmbedOffset` reports the heading line start or the block marker, skipping fenced code, matching block ids only as a whole identifier, and converting CRLF to the single `\n` that CodeMirror stores, so the offset addresses the editor document rather than the raw file. Merged embed parsing and anchor offsets share that one helper rather than re-implementing fenced code scanning. Unsupported backlink integration remains out of scope here; Canvas links do not create graph edges.

Renaming or moving a note also rewrites `file` nodes in boards whose stored path points at the moved note. The rewrite runs inside the existing rename owner in `core/src/files/gate.rs` (`files/canvas_refs.rs`): it preflights every board hash, writes atomically with the same precondition, and rolls back the boards it already wrote when a later write fails. Boards are scanned from the moved path's parent, which covers a renamed file and every board in a renamed or moved folder; a board that changed after the preflight stops the rename with the existing conflict error instead of overwriting concurrent edits. Relative Markdown links inside card text are not rewritten yet, and only file nodes participate.

The active Canvas view is mounted by the pane renderer, while the live-tab layer keeps inactive documents warm. Rendering the active Canvas in both paths duplicated its board and toolbar; the live-tab layer now skips that active Canvas only. Other live tabs and intentionally split panes keep their existing behavior.

A text node is bare text, not a box. It renders without a border, background, radius or padding, so a new text card is a single 40-pixel line with a blinking caret at the pointer position instead of a filled 280×180 square, and it grows downward while the user types. Obsidian draws JSON Canvas `text` nodes the same way, which also makes board files look the same in both editors. File and link cards keep their boxed chrome because they represent an object rather than a label; shapes keep their own SVG layer. Hover and selection draw an inset ring, so a borderless text node is still reachable and the selected one is visible. The rule that removes the chrome has to outrank `.q-canvas__object > .q-canvas-card` from `CanvasView.css` and excludes shape cards (`:not(.q-canvas-card--shape)`), otherwise rectangles, diamonds, ellipses and number markers would lose their selection ring and padding.

A note card opens its note on a plain press, except when the press became a drag or carried Shift, Cmd or Ctrl: dragging a card must move it, and modifiers belong to multi-selection. The open runs on `pointerup`, not `click`. The board captures the pointer when a card drag starts, so the browser retargets the release to the stage and the `click` event lands on the stage instead of the card; a `click` handler on the card looked correct in happy-dom, where tests dispatch `click` directly, and never fired in a real WebView. `dragMovedRef` records whether the pointer travelled more than four pixels, and `pressRef` remembers the card under the pointer so releasing without movement opens it.

Dropping a file from the workspace sidebar places a file card at the pointer. The file tree already exports `application/x-obsidium-file-path`, so the board accepts any workspace file — notes, images, video, other boards — instead of only boards, and resolves the workspace-relative path through `relativePath`. A path outside the workspace still becomes a link card, or reports the workspace warning when it is not a resolvable image. The note picker in the toolbar remains the keyboard path to the same operation.

The board itself has a right-click menu, while cards keep their own. Right-clicking empty canvas offers add text, find a note, select all, fit content, reset view, and the three exports; right-clicking a card offers open, edit, duplicate, z-order, delete, group, ungroup and alignment. Both menus close on the next pointer press that is not inside the menu. Export now also downloads the board as JSON through the same `serializeCanvasDocument`, next to SVG and PNG, because the file is the canonical format and a user may want the document rather than a picture.

The bottom bar holds only the camera and the save state: zoom out, percentage, zoom in, fit, reset, and `Сохранено`/`Сохранение…`. Fill moved to the top toolbar next to colour, because it is a property of shapes, and the connection controls moved to a floating panel next to the selected edge. That panel shows the three route shapes, the two arrow ends, the label and delete; explicit source and target sides are still available by starting the drag from a connector dot, and existing `fromSide`/`toSide` values in a file keep working even though the manual override was removed from the bar. The old bar exposed six selects in a row of text buttons, which was unreadable and pushed the save state out of sight.

The stage measures itself through a callback ref (`attachStage`), not a mount effect. While the document loads, `CanvasView` renders a loading node instead of the stage, so an effect with an empty dependency list ran once with `stageRef.current === null`, never observed the element that appeared later, and left the viewport at 0×0. The edges SVG then had `width="0" height="0"` and every connection was invisible, and fit-to-content worked against an empty rectangle. A callback ref runs whenever the node mounts or unmounts, which is exactly the lifetime the observer needs.

Edge arrowheads are painted by SVG markers, and markers are `<path>` elements too. A blanket `.q-canvas__edges path { fill: none }` made every arrowhead invisible because a CSS declaration beats the `fill` presentation attribute on the marker path. The rule is now scoped to `.q-canvas__edges > g > path` (the connection lines), with `pointer-events: stroke` merged into the same block, and markers only reset their `stroke`. This was invisible in unit tests and in export, which builds its own markers; it showed up in the real browser.

Text inside a shape is centred, both horizontally and vertically, and the shape grows instead of clipping. A rectangle, diamond, ellipse or number marker keeps its own padding (`12px`, `22% 18%`, `14% 16%`), and `text-align: center` plus `align-content: center` centre the line box inside that padded content box, so text still stays inside a diamond's inscribed area and inside an ellipse's curve. Preview and edit share the same rule, so entering edit mode does not move the text. The textarea keeps a transparent background and no border; the focus ring that other text cards never had was removed from shapes too, because a box drawn inside a figure reads as a selection artefact rather than as a caret. Number markers keep their own grid centring, which is later in the cascade.

Growing a centred textarea needs the overflow measured with `align-content: start`. A centred textarea's `scrollHeight` excludes the overhang above the content box in WebKit, which is the shipping Tauri engine, so `scrollHeight - clientHeight` under-reports by the padding on each side and the node converges only after several input events. `canvasTextOverflow` in `modules/canvas/textFit.ts` measures once with `start` alignment and restores the previous value; in Chromium both measurements are identical, so the helper is behaviour-neutral there. The card reports `node.height + overflow` for shapes and plain `scrollHeight` for borderless text cards, and `resizeTextNode` accepts shape nodes again — the earlier early return was what kept a long label clipped inside its figure.

Fitting also runs when editing starts, not only on input, because a board opened from a file may already hold a label longer than its shape. `beginTextEditing` sets the editing id, measures on the next frame, grows the node, and on the frame after that focuses the textarea and puts the caret at the end. Every entry point uses it: double click, Enter on a selected card, the context-menu Edit item, and a freshly created text card. Without the explicit focus the textarea relied on `autoFocus`, which lost focus when the same render also changed the node height, so the user saw a caret-less box and typed into nothing.

## Свойства объекта

Панель свойств — единственное место, где меняется вид объекта. Она стоит в правом верхнем углу доски и не следует за выделением: панель, привязанная к bounding box, уезжает из-под курсора, закрывает редактируемый объект и прыгает при изменении размера. Высота ограничена окном, содержимое прокручивается, так что панель никогда не выходит за пределы доски.

`modules/canvas/nodeProps.ts` — единственный владелец расширения `obsidium`: `strokeWidth` (1/2/4), `strokeStyle` (`solid`/`dashed`/`dotted`), `corners` (`sharp`/`round`), `fontFamily` (`sans`/`serif`/`mono`), `fontSize` (`s`/`m`/`l`/`xl`), `textAlign` (`left`/`center`/`right`), `opacity` (0…1) и `fill` (ключ пресета или `transparent`). `readCanvasAppearance` нормализует неизвестные значения к дефолтам, `withCanvasAppearance` пишет только отличия и удаляет ключ при возврате к дефолту. Без этого правила доска накапливала бы `strokeWidth: 2` на каждом узле и переставала быть компактным JSON Canvas.

Дефолты зависят от формы: текст внутри фигуры центрируется по горизонтали и вертикали, обычная текстовая карточка выравнивается влево. Поэтому текст в ромбе стоит в его вписанном прямоугольнике, а не прилипает к левому краю, и одна и та же фигура выглядит одинаково до и после входа в редактирование.

Внешний вид применяется тремя путями и везде из одного источника. На доске `CanvasCard` получает `appearance` и выставляет `--q-canvas-font-size`, `--q-canvas-font-family`, `--q-canvas-text-align` и `opacity`; `CanvasShape` получает толщину, стиль и скругление, а толщина и штрих делятся на зум, чтобы линия оставалась одинаковой на экране. В SVG-экспорте те же значения переводит `svgExport` (шрифты — в конкретные семейства, потому что SVG не читает CSS-переменные). В панели — те же типы, поэтому новое свойство добавляется в один модуль и появляется во всех трёх местах.

## Якоря связей

Связь хранит `fromAnchor` и `toAnchor` — точку внутри узла в долях его ширины и высоты (0…1). Они записываются при протягивании связи: источник берётся из точки нажатия, цель — из точки отпускания. Это и есть «тянуться к любому указанному месту»: связь приходит ровно туда, где пользователь отпустил указатель, а не в середину ближайшей стороны.

Без якорей `getCanvasEdgeGeometry` пересекает отрезок между центрами с контуром узла: прямоугольник — по прямоугольнику, эллипс — по уравнению эллипса, ромб — по уравнению ромба. Такой расчёт остаётся фолбэком для связей, созданных до появления якорей, для связей из других редакторов и для вырожденного случая совпадающих центров, где направление не определено и берётся сохранённая сторона. Угол между узлами больше не выбирает «правую» или «нижнюю» сторону: линия выходит из контура по фактическому направлению, поэтому диагональная связь между двумя прямоугольниками больше не идёт горизонтально от середины правого края.

Якорь валидируется при разборе файла: `edges[i].fromAnchor` обязан быть объектом с конечными `x` и `y` в диапазоне 0…1. Мусор в этих полях отклоняет документ, а не сдвигает связь в случайное место.

## Стрелки на доске

Наконечники на доске — `<polygon>`, построенный `canvasEdgeArrowheads` по касательной маршрута: для прямой это направление отрезка, для угловой — последний сегмент, для кривой — направление от контрольной точки к концу. Размер задаётся в экранных пикселях и слегка растёт с зумом, но остаётся в пределах 10…16 px.

SVG-маркеры для этого не годятся. `fill` внутри `<marker>` наследуется по правилам `context-fill`, которые WebKit (движок Tauri на macOS) разрешает в цвет обводки пути, а не в собственный `fill` фигуры: наконечник рисовался волосяной линией. `markerUnits="strokeWidth"` дополнительно масштабировал его толщиной связи в один пиксель. Полигон не зависит ни от того, ни от другого, и в экспорте остаются маркеры, потому что там SVG собирается один раз и открывается другими просмотрщиками.

## Группы и множественное выделение

Рамка выделения рисуется одна: на bounding box множественного выделения или на самой группе. Восемь маркеров на каждом узле делали выделение из пяти карточек лесом квадратов и перекрывали содержимое.

`resizeCanvasSelection(nodes, selectedIds, next)` масштабирует выделенные узлы из исходных границ в новые: позиции и размеры умножаются на отношение сторон, минимальный размер — 24 px, как у `resizeCanvasGroup`. Узлы, лежащие внутри выделенной группы, масштабируются вместе с ней, даже если выделена только сама группа: иначе рамка группы росла бы, а содержимое оставалось на месте. Невыделенные узлы возвращаются теми же объектами, поэтому история и сравнение документов не видят лишних изменений.

Маркеры группы лежат в слое выше узлов. Раньше они оказывались под карточками участников, и группа с заполненным содержимым не выделялась за угол: нажатие попадало в участника.

## Сокращения на панели

Кнопки инструментов показывают свою букву (`V`, `T`, `F`, `L`, `G`, `A`, `R`, `D`, `E`, `N`, `P`) в углу кнопки, как в Excalidraw, и объявляют её через `aria-keyshortcuts`. Подсказка в `title` остаётся, но буква видна без наведения: раскладка инструментов запоминается быстрее, чем читается меню.

Иконка ромба — собственный `rhombus` из `CanvasGlyphs.tsx`, а не lucide `diamond`: lucide рисует огранённый кристалл с внутренними линиями, и в панели он читался как «кристалл», а не как ромб. Пользовательские SVG-узлы остаются в наборе lucide при переключении набора иконок приложения: `getMappedIconId` возвращает `null` для узла, которого нет в каталоге, и подстановка чужого глифа не происходит.

## Перетаскивание заметки из сайдбара

Боковая панель таскает строки собственным pointer-драгом (`useFileTreeDrag`), а не HTML5 drag-and-drop: Tauri перехватывает нативные drag-события окна, поэтому `drop` на доске для сайдбара не приходил никогда, и заметка «не добавлялась». Мост между двумя мирами — `modules/dragPayload.ts`: дерево при старте драга публикует `NoteDragPayload`, доска при монтировании регистрирует единственную цель (`registerNoteDropTarget`) и помечает свою сцену `data-canvas-drop="true"`. На отпускании дерево спрашивает `document.elementFromPoint` и, если под курсором доска, отдаёт полезную нагрузку ей и не пытается перемещать файл по папкам. Последняя регистрация побеждает: две открытые доски в разных панелях не крадут дроп друг у друга, потому что цель перерегистрируется при монтировании и снимается при размонтировании, не затирая чужую.

HTML5-путь остаётся для файлов извне окна и для вставки из буфера. Оба пути сходятся в `canvasWorkspacePath` (`modules/canvas/dropPath.ts`), который принимает абсолютный путь, относительный путь и `text/uri-list` с `file://`, снимает `file://` и Windows-префикс диска, отбрасывает `..` и пути вне базы знаний. Без этого нормализатора абсолютный путь из `text/plain` попадал в `relativePath` и бросал исключение — второй способ, которым «заметка не добавлялась». Неподдерживаемый дроп теперь показывает `canvas.errors.dropUnsupported`, а не молчит.

## Связь как объект

Связь выбирается по широкой полосе `.q-canvas__edge-hit` (16 px, `pointer-events: stroke`), а не по однопиксельной линии: попасть курсором в тонкую кривую было почти невозможно, и пользователь решал, что связь не выделяется. Полоса лежит под видимой линией, поэтому не меняет вид, но даёт курсор и подсветку при наведении.

Выбранная связь показывает два маркера концов в отдельном слое `.q-canvas__edge-overlay`. Слой нужен, чтобы маркеры не масштабировались вместе с зумом сцены и не оказывались под карточками: раньше они лежали в SVG связей с `z-index: 1`, то есть под слоем узлов, и перетащить конец можно было только там, где карточка не мешает. Перетаскивание конца пишет `fromAnchor`/`toAnchor` и, если курсор над другой карточкой, меняет `fromNode`/`toNode` — связь можно перенаправить на любой узел, а не только пересоздать.

`Delete` удаляет выбранную связь, двойной щелчок по ней — тоже. Двойной щелчок не конфликтует с одиночным: одиночный только выделяет.

## Примагничивание

`modules/canvas/guides.ts` держит три привязки. Перемещение карточек выравнивает края и центры по другим карточкам (это было и раньше). Изменение размера притягивает ту грань, которую тянет пользователь: `snapResizeRect` знает, какой угол или сторона движется, и подтягивает только её, а не весь прямоугольник — иначе при тяге за правый нижний угол дёргался бы левый верхний.

Конец связи примагничивается к девяти точкам узла: четырём углам, четырём серединам сторон и центру (`snapPointToNodes`). Это и есть «лёгкое примагничивание к фигуре, к центру стороны или углу»: порог 6 px в экранных единицах, поэтому на любом зуме притяжение ощущается одинаково, а не растёт вместе с масштабом. Точка привязки показывается кольцом `.q-canvas__snap`; без него снап выглядит как случайный сдвиг курсора.

## Стикер

Стикер — текстовый узел с `obsidium.shape: 'sticker'`: залитый скруглённый прямоугольник без обводки, текст по центру. Это не новая сущность в формате, поэтому стикер открывается в Obsidian как текстовая карточка, а не как неизвестный тип. Заливка по умолчанию — жёлтый пресет, смешанный с бумагой на 82 %: на светлой бумаге это читаемый стикер, на тёмной он не превращается в кислотное пятно. Цвет текста берётся из темы (`--q-canvas-sticker-ink`), потому что тёмный текст на тёмной теме был бы невидим, а светлый на светлой — тоже.

Стикер не участвует в обводке: толщина и стиль штриха его не касаются, скругление всегда включено. Панель свойств для него показывает фон и шрифт, а не толщину линии — это следует из того, что стикер рисуется без `stroke`.

## Копирование

`Cmd/Ctrl+C` кладёт выделение во внутренний буфер, `Cmd/Ctrl+V` вставляет его со смещением на шаг сетки или в точку меню доски, `Cmd/Ctrl+X` копирует и удаляет. Копия сохраняет относительное расположение узлов: смещение считается от левого верхнего угла выделения, поэтому группа из трёх карточек вставляется той же группой, а не тремя карточками друг на друге. Связи копируются только между скопированными узлами — иначе копия тянулась бы к оригиналам, и на доске появлялись бы невидимые связи.

Копирование и вставка доступны из меню доски и из панели свойств, а не только с клавиатуры: пункт меню отключён, когда копировать нечего, и вставка отключена при пустом буфере.


## Почему обводка красила фигуру, а прозрачность не работала

Цвет обводки хранится в `node.color` и попадает в `--q-canvas-node-color`. Из этого же токена выводился и фон (`--q-canvas-shape-fill: color-mix(node-color 20%, paper)`), поэтому выбор цвета обводки перекрашивал всю фигуру. Теперь фон берётся только из `obsidium.fill`; если его нет — фигура не залита вообще. Обводка меняет только контур.

Непрозрачность раньше выставлялась на карточку, а SVG-слой фигуры — её сосед, поэтому заливка и контур не тускнели, а текст тускнел. Прозрачность теперь ставится на обёртку узла: и карточка, и фигура, и свободное рисование лежат внутри неё и гаснут вместе. Двойного затухания нет, потому что карточка больше не выставляет `opacity` сама.

Цвет связи больше не наследуется от фигуры. Раньше выбор цвета обводки заодно писал `edgeColor`, и следующие созданные связи рождались цветными «как фигура». Теперь у связи свой цвет: он задаётся в панели при выделенной связи (секция обводки) и по умолчанию нейтральный. Связь никогда не перекрашивается вместе с фигурой.

Якорь связи притягивается к контуру узла, а не к точке под курсором внутри фигуры. Если курсор попал внутрь карточки, конец связи встаёт на контур с той стороны, которая смотрит на второй конец: иначе линия проходила бы сквозь фигуру и текст, что и читалось как «коллизия». Наружу от фигуры курсор работает как раньше — конец встаёт на контур по направлению к курсору.


## Инструменты доски: фото, заметка, стикер

Панель инструментов отражает то, что пользователь действительно делает, а не тип узла в файле. `F` открывает выбор фото или видео, `L` — поиск заметки, `S` ставит стикер, `T` создаёт текст. Раньше `F` и `L` назывались «файловая карточка» и «карточка ссылки»: первое открывало произвольный файл с диска и клало его путём внутрь базы, второе создавало пустую ссылку с `https://`. Оба действия — редкие и не те, ради которых открывают доску.

Фото проходит через тот же `importIntoFiles`, что и вставка картинки в редакторе: файл копируется в папку вложений, а узел получает относительный путь. Поэтому вложение живёт в базе знаний, а не ссылается на `~/Pictures`, и переживает перенос базы. Ссылка на внешний адрес осталась отдельной командой (`/ Команды` → «Карточка ссылки» и пункт контекстного меню), потому что это осознанное действие, а не инструмент.

Поиск заметки (`L`) открывает тот же диалог, что и кнопка поиска в панели: интерактивный поиск по индексу базы с недавними заметками и строкой создания. Раньше инструмент «файловая карточка» открывал системный диалог выбора файла — то есть «заметка» на деле означала «любой файл на диске», и заметку из хранилища так было не добавить.

## Вставка из буфера

`Cmd/Ctrl+V` работает на доске независимо от того, где стоит фокус. Обработчик висит и на сцене, и на `window`: сценический ловит обычный случай, оконный — когда фокус ушёл в сайдбар, на панель свойств или на пустое место документа. Оконный обработчик не срабатывает, если фокус в поле ввода (там вставка принадлежит полю) или если доска неактивна, поэтому в редакторе заметки и в диалогах поведение не меняется. Копирование устроено так же: `Cmd/Ctrl+C` копирует выделение, только когда копировать есть что.

## Панель свойств показывает только применимое

`capabilities` на цели панели описывает, какие секции имеют смысл для выделения: у свободного рисования нет фона и шрифта, у стикера нет обводки, у ромба и эллипса нет скругления углов, у обычной текстовой карточки нет ни обводки, ни фона. Панель, которая предлагает толщину штриха текстовой карточке, выглядит сломанной: пользователь жмёт, ничего не происходит, и он не понимает, почему.

Для множественного выделения возможности пересекаются: если в выделении есть карточка и прямоугольник, секция обводки показывается (прямоугольнику она нужна), а скругление — только когда все выделенные прямоугольники. Изменение всё равно применяется ко всем, но затрагивает только те узлы, у которых это свойство есть.

## Свободное рисование не имеет рамки

У штриха нет карточки, поэтому он не должен получать рамку при наведении и выделении. Рамка рисовалась тенью карточки (`box-shadow: inset`), которая включалась правилом для текстовых карточек; штрих от неё исключён селектором `:not(.q-canvas__object--freehand)`, а его собственное выделение показывает цвет линии. Раньше при наведении вокруг штриха появлялся прямоугольник — визуально это читалось как «у полоски есть фон», хотя его нет.

## Escape закрывает верхний диалог

`Escape` обрабатывается на `document` в фазе перехвата, поэтому диалог закрывается, даже когда фокус внутри CodeMirror-поля, которое гасит клавишу своим keymap. Закрывается только верхний диалог: если поверх открыт подтверждающий, `Escape` закрывает его, а не тот, что под ним. Обработчик на панели диалога пропускает событие, если оно уже обработано в перехвате, иначе `onClose` вызывался дважды.


## Цвет штриха и вставка из буфера

Свободное рисование хранит цвет в `node.color`, как и остальные узлы, но раньше он не доходил до картинки по двум причинам. `createCanvasFreehandNode` принимал только точки и не записывал цвет, поэтому новый штрих всегда рождался нейтральным. А правило `.q-canvas__object--freehand.is-selected .q-canvas__freehand path` перекрашивало линию в акцент выделения — CSS-правило сильнее презентационного атрибута `stroke`, поэтому выбранный штрих выглядел синим независимо от сохранённого цвета. Теперь цвет пишется при создании и передаётся в живое превью, а выделение рисует отдельный полупрозрачный «ореол» той же формы: цвет линии больше не подменяется, а видимость выделения не теряется.

`Cmd/Ctrl+V` работает на доске в любом режиме и при любом фокусе, кроме полей ввода. Обработчик висит на окне, но пропускает события из `textarea`, `input`, `select`, `contenteditable` и `.cm-editor`, поэтому редактор заметки сохраняет свою вставку. Помимо `files` и `items` буфер разбирается как путь: `text/uri-list` или `text/plain` с `file://`-адресом либо абсолютным путём к медиафайлу импортируется в папку вложений через `importIntoFiles`. Путь вне базы знаний даёт `canvas.errors.dropUnsupported`, а не тишину. Копирование по-прежнему требует фокуса на доске и не перехватывает `Cmd+C`, когда копировать нечего.

Инструменты «Фото или видео» и «Заметка из базы знаний» не зажимаются: нажатие сразу открывает диалог выбора файла или поиск заметки в центре вьюпорта, а активным остаётся `select`. Зажатый режим означал бы, что после выбора файла следующий клик по пустому месту создаёт пустую карточку — этого не происходит.
