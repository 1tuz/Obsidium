## Порядок

1. Rust `setup()` (`lib.rs`), до показа окна и синхронно: каталог данных, `migrate_legacy_data`,
   `settings.json`, состояние окна, `ui-state.sqlite3`, сервис поиска (без сканирования — оно
   начинается, когда фронт открывает базу), сервис истории, MCP-сервер, в release — путь автозапуска.
   Всё здесь обязано быть быстрым: пока `setup()` не вернулся, окна нет.
2. Окно создаётся скрытым (`"visible": false` в `tauri.conf.json`), чтобы не мигать белым до
   применения темы и шрифтов.
3. `main.tsx`: шрифты, i18n, тема, корневой `ErrorBoundary`, `App`.
4. `App` загружает настройки и в `finally` вызывает `revealAppWindow` — окно показывается
   и при ошибке загрузки настроек.
5. `useWorkspace` открывает последнюю базу из `ui-state`; пропавшая папка даёт экран «не удалось
   открыть», а не падение.

## Правила

- **Окно показывается при любой ошибке отрисовки.** Если `App` падает при первой отрисовке, до
  `revealAppWindow` дело не доходит: процесс жив, окна нет, повторный запуск только фокусирует тот же
  невидимый экземпляр (single-instance). Для пользователя это «Aquilum не запускается». Поэтому
  корневой `ErrorBoundary` в `main.tsx` получает `onCatch={revealAppWindow}` и заголовок «Упс,
  приложение упало!»: окно показывается вместе с текстом ошибки и кнопкой «Копировать».
- **Сбой вне редактора не гасит всё окно.** До корневого перехватчика `ErrorBoundary` стоял только
  вокруг редактора: ошибка в дереве, графе, настройках или поиске размонтировала весь React — белое
  окно без выхода, кроме перезапуска.
- **В `setup()` не копируются кэши.** `migrate_legacy_data` переносит из `com.dmitriy.quantum-app` всё,
  кроме `search-v2` (`REBUILT_CACHES`): индексы quantum-app построены токенизатором `quantum_text` и
  всё равно удаляются и строятся заново, а копирование сотен мегабайт шло синхронно до показа окна.
- **Паника в потоке индексации видна.** Поток `aquilum-search-index` выполняет `run` под
  `catch_unwind`: паника превращается в `SearchError::Task` «поток индексации упал: …» и уходит в
  статус индекса, как обычная ошибка. Без этого поток умирал молча, статус навсегда оставался
  «индексируется», а поиск и ссылки ждали. Работает потому, что в release `panic = "unwind"`
  (значение по умолчанию; `panic = "abort"` в `[profile.release]` это сломает).
- **Занятый порт MCP не роняет запуск**: `McpServer::apply` записывает ошибку в статус, настройки MCP
  её показывают.

## Проверенные и отвергнутые причины падений (2026-10-06)

- Срезы строк по байтам в индексации, истории и заголовках ссылок — все индексы выровнены по
  границам символов (`common_prefix` подгоняет к `is_char_boundary`, заголовок режется после
  `to_ascii_lowercase`, который не меняет длину), кириллица их не ломает.
- `unwrap`/`expect` вне тестов — все после проверок; `lock().unwrap()` срабатывает только после уже
  случившейся паники с захваченной блокировкой.
- Полный проход индекса при запуске не перечитывает файлы: сравниваются размер и время изменения.
- Бюджет писателя 256 МБ — верхняя граница арен, обоснован замерами, писатель отпускается после
  5 секунд простоя.
- Событие «ссылки изменились» не штормит при первой индексации: коммит раз в 10 000 файлов.

## Не закрыто

Если не загрузится сам JavaScript-бандл (синтаксическая ошибка в старом WebView2, повреждённые файлы
установки), `ErrorBoundary` не существует, и окно останется скрытым. Закрыть это можно только со
стороны Rust (показать окно, если фронт не сделал этого за N секунд) — это решение за владельцем:
оно прячет причину, а не чинит её.
