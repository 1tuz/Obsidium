## Что такое пространство

Пространство — виртуальное представление части базы знаний: имя плюс набор фильтров, по которым
сайдбар показывает только подходящие файлы. Файлы и папки на диске не двигаются, копий нет,
никакой папки «пространства» в vault не появляется. Один и тот же файл может попадать в несколько
пространств, а удаление пространства не удаляет ни одной заметки.

Причина простая: vault — это пользовательская структура папок, которую он видит и в файловом
менеджере, и в Obsidian. Перемещение файлов под нужды навигации ломало бы ссылки, историю, сессии
вкладок, привязки изображений и ожидания пользователя одновременно. Пространство — надстройка над
именем файла, а не над его местом.

## Модель

```rust
pub struct Space {
    pub id: String,             // стабильный идентификатор; генерируется из имени при создании
    pub name: String,           // отображаемое имя
    pub root: String,           // папка относительно корня vault; пусто = вся база
    pub include_tags: Vec<String>,    // пусто = без фильтра по тегам
    pub exclude_folders: Vec<String>, // папки относительно корня vault
}
```

В JSON и на фронтенде поля в camelCase (`includeTags`, `excludeFolders`): на моделях стоит
`#[serde(rename_all = "camelCase", default)]`, как у остальных секций настроек. `default` на уровне
контейнера означает, что старый `settings.json` без секции читается без ошибки и получает
умолчание.

Умолчание — одно пространство `all` с именем «Всё», пустым `root` и пустыми фильтрами. Оно
описывает всю базу и потому не включает ни обход, ни фильтрацию: сайдбар для него работает ровно
как раньше, лениво подгружая папки.

`SpaceSettings` — обёртка `{ spaces: Vec<Space> }`. Обёртка, а не голый массив, оставляет место
для будущих полей секции без ломающего изменения формата.

## Где хранится

`settings.json` в `app_data_dir`, секция `spaces` (`AppConfig::spaces` в
`core/src/settings/models.rs`). Отдельного хранилища нет: список пространств — это настройка, а не
состояние базы, поэтому он не привязан к конкретному vault и не требует миграций `ui-state.sqlite3`.

Следствие, которое надо помнить: пространства **глобальны**. Если у пространства `root = "projects"`,
а в другой базе такой папки нет, дерево будет пустым, а не «вся база». Это ожидаемое поведение
фильтра, а не ошибка: молча расширять область до всего vault значило бы показывать не то, что просил
пользователь.

Запись идёт через `SettingsManager::update_config`, то есть тем же атомарным путём, что и остальные
настройки. Фронтенд после `save_space`/`delete_space` дублирует свежий список в стор настроек
(`modules/settings`): `update_settings` отправляет конфиг целиком, и без этого зеркала следующее
сохранение любой другой настройки вернуло бы старый список пространств.

## Нормализация при сохранении

`obsidium_core::spaces::save_space` — единственная точка записи, поэтому вся нормализация живёт там:

- `name` обрезается; пустое имя отклоняется.
- `root` и `exclude_folders` приводятся к относительному POSIX-виду: `\` → `/`, снимаются ведущий
  `./` и крайние `/`. Абсолютные пути, буква диска и сегмент `..` отклоняются с ошибкой — фильтр не
  должен уметь выйти за пределы vault.
- `include_tags` обрезаются, теряют один ведущий `#`, пустые выбрасываются, дубликаты схлопываются
  без учёта регистра с сохранением первого написания.
- Пустой `id` превращается в слаг имени (`work-notes`), при совпадении добавляется `-2`, `-3`, …
  Существующий `id` заменяет пространство на месте, порядок списка сохраняется.
- `delete_space` отказывается удалять последнее пространство: пустой список оставил бы сайдбар без
  переключателя и без определённого состояния.

## Обход файлов

`obsidium_core::spaces::list_space_files(workspace, space)` возвращает отсортированный список
абсолютных путей.

Обход не написан заново: он рекурсивно вызывает `files::workspace::read_directory_impl` — ту же
функцию, что отдаёт дерево и скрывает точки, симлинки и неподдерживаемые расширения. Второй обход
разошёлся бы с деревом в правилах фильтрации (расширения, сортировка, скрытые файлы) и показывал бы
в пространстве файлы, которых нет в обычном дереве.

Правила:

- Стартовый каталог — `workspace.join(root)`; пустой `root` — сам vault. Каталога нет или он вне
  vault (`strip_root` вернул `None`) — пустой результат, без ошибки: пространство могло быть создано
  для другой базы.
- `exclude_folders` сравниваются с путём папки относительно корня vault по компонентам, без учёта
  регистра: `archive` исключает и `archive`, и `archive/old`, но не `my-archive`.
- Ошибка чтения подкаталога не валит весь список — каталог просто пропускается.
- `include_tags` непустой включает режим тегов: остаются только `.md`, у которых во frontmatter есть
  поле `tags` (ключ без учёта регистра), и хотя бы один тег пересекается с фильтром. Значение
  читается как список YAML (`tags: [a, b]`, блочный список) или как скаляр, разбитый по запятым и
  пробелам. Читается только начало файла (`search::fields::head_fields`, первые 8 КБ) — этого
  достаточно для frontmatter и не требует открывать заметки целиком.

## IPC

`src-tauri/src/spaces/commands.rs`, регистрация в `src-tauri/src/lib.rs`:

| Команда | Аргументы | Результат |
| --- | --- | --- |
| `get_spaces` | — | `Space[]` из настроек |
| `save_space` | `{ space }` | сохранённый `Space` (с итоговым `id`) |
| `delete_space` | `{ id }` | оставшийся `Space[]` |
| `list_space_files` | `{ workspacePath, spaceId }` | `string[]` абсолютных путей |

`spaceId: null` означает «вся база» — обход без фильтров; неизвестный `id` возвращает ошибку, а не
молчаливое расширение области. Обход идёт в `spawn_blocking` (`blocking::run_blocking`), как и
остальные файловые команды: рекурсивный обход большого vault не должен занимать поток рантайма.

## Интерфейс

Переключатель — `components/Layout/SpaceSwitcher.tsx`: компактный `Dropdown` со списком пространств
и кнопка управления, стоящие над деревом, вне прокручиваемой области (`Sidebar.tsx`, класс
`.q-sidebar-spaces`). Редактор — `components/Spaces/SpacesDialog.tsx`: список пространств с
изменением и удалением (через `ConfirmDialog`) и форма из четырёх полей. Сложного конструктора
фильтров нет намеренно: `root` выбирается из существующих папок базы, теги и исключения вводятся
списком через запятую.

Состояние держит `hooks/useSpaces.ts` на уровне `App`, поэтому активное пространство переживает
переключение вкладок и панелей: сайдбар один на окно, и его фильтр не должен меняться от того, какая
заметка открыта. Активное пространство не сохраняется между запусками приложения — при старте
выбирается первое из списка.

Источник дерева переключается в `App.tsx`: для пространства «вся база» используются ленивые
`directories` из `useWorkspace` (папки подгружаются по раскрытию), для фильтрующего пространства —
карта, собранная `modules/spaces::buildSpaceDirectories` из ответа `list_space_files`. Ленивая
загрузка для фильтра не годится: чтобы узнать, какие файлы попадают в пространство, всё равно нужен
полный обход, а он уже вернул все пути сразу.

`buildSpaceDirectories` строит те же строки дерева, что и `read_directory_impl`: папки раньше
файлов, внутри — по имени без учёта регистра, у `.md` отображается имя без расширения, у остальных
файлов полное имя. Ключи карты — абсолютные пути каталогов, корневой ключ — сам vault, поэтому
`fileTreeModel` и `FileTree` работают без изменений.

## Актуальность дерева

Дерево пространства — снимок. Ленивое дерево обновляется событиями файловой системы
(`workspace-changed` → `useWorkspaceEvents`), и снимок подписан на то же событие: `useSpaces`
складывает приходящие изменения с задержкой 60 мс и перезапрашивает `list_space_files`. Без этого
переименование, удаление, дублирование, создание заметки и правки внешнего редактора оставляли бы в
отфильтрованном дереве устаревшие строки до повторного выбора пространства.

Пока идёт перезапрос, показывается предыдущий снимок: сбрасывать его в пустоту значило бы мигать
деревом на каждое сохранение файла.

## Ограничения

- **Поиск не фильтруется по пространству.** `search_knowledge_base`, индекс и граф работают по всей
  базе: пространство сужает только дерево файлов. Пользователь, находящийся в пространстве «Работа»,
  всё равно найдёт заметку из «Архива». Это осознанно оставлено на следующий шаг: фильтр в поиске
  требует пробрасывать пространство в запрос индекса и в граф, иначе половина выдачи останется
  неотфильтрованной.
- Быстрый переход, обратные ссылки, граф, канбан-доски и базы работают по всей базе по той же
  причине.
- `include_tags` смотрит только frontmatter. Инлайновые `#теги` в теле заметки не учитываются:
  разбор тела стоил бы чтения файла целиком, а frontmatter — единственное место, где теги объявлены
  явно.
- Теги читаются из первых 8 КБ файла. Заметка с гигантским frontmatter (больше 8 КБ) может не
  попасть в фильтр по тегам.
- Пространства глобальны и не привязаны к базе знаний; `root`, указывающий в несуществующую папку,
  даёт пустое дерево.
- Активное пространство не запоминается между запусками.
