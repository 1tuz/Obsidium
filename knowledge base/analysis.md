# Анализ проекта Aquilum — С чего начать

## Что это за проект

**Aquilum** — локальный (Local-First) таск-трекер и база знаний, вдохновлённый Obsidian и Linear. Ключевые идеи:
- Данные — `.md` файлы у пользователя
- CRDT-синхронизация (Yjs) для будущего мультиплеера
- Уникальные ID на каждый блок контента
- WYSIWYG-редактор с «показом Markdown при фокусе»
- Канбан, канвас, граф — как визуальные режимы поверх .md файлов

**Стек**: Tauri v2 (Rust) + React/TypeScript + Tiptap + Yjs

## Мой совет: начать с Фазы 1 + Фазы 2

Причины:
1. **Yjs — архитектурное решение**, которое пронизывает всё приложение. Его нужно заложить первым
2. **Парсер Markdown ↔ Yjs с ID** — самая рискованная часть. Лучше провалидировать подход рано
3. **Tauri + React сетап** — быстро, даёт работающее окно приложения уже в день 1
4. **Дизайн-токены** — дешёво сделать сейчас, дорого переделывать позже

> После Фазы 2 у вас будет: работающее Tauri-окно, загрузка `.md` файлов в Yjs, сохранение обратно, система ID. Это уже **доказательство архитектуры** (Proof of Concept), на которое можно уверенно наращивать редактор и UI.

## Ключевые архитектурные решения, которые стоит принять сразу

1. **Формат ID в `.md`**: `{#abc123}` (как в спеке) или `<!-- id: abc123 -->`? Рекомендую `{#id}` — компактнее, стандарт Pandoc
2. **Yjs Doc structure**: один `Y.Doc` на файл или один глобальный? → Один на файл, с ленивой загрузкой
3. **Масштабирование**: `rem`-based с `font-size` на `:root`
4. **Поисковый индекс**: Tantivy (Rust) — идеальный выбор для Tauri, работает из коробки
5. **Орфография**: Hunspell через Rust-обёртку или nspell (JS) — нужно бенчмаркить
