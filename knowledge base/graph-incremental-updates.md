# Инкрементальные обновления графа

Живая модель графа привязана к корню базы знаний и поколению поискового индекса. При первом запросе она строится из последнего события `graph_timeline_events`; вместе с моделью сохраняется cursor на максимальный event ID. Снимки истории используют отдельный кэш, поэтому перемещение по шкале не вытесняет живую модель.

После ревизии модель получает изменения из timeline, а не перечитывает все строки `wiki_documents`, `wiki_links` и `note_fields`. `changes_after` принимает cursor только на границе timestamp-группы и возвращает каждую такую группу целиком. Timeline хранит `rescan_epoch`, который увеличивается в транзакции полного сканирования; его изменение, пропуск ID, cursor внутри группы, cursor вне baseline/latest или недоступный диапазон означает cache miss и полное восстановление модели из текущего timeline-состояния. SQLite-снимок не удерживается между запросами интерфейса.

Модель хранит по заметке ключи заголовка и пути, метаданные, исходные wiki/Markdown-ссылки и структурные ссылки. Индексы заголовков и путей разрешают кандидатов; обратный индекс от target key к исходным заметкам находит источники, которым нужно повторно разрешить ребро после изменения кандидатов. При добавлении, удалении, переименовании или изменении заголовка обновляются только затронутые заметки и источники, ссылающиеся на старые или новые ключи. Для неоднозначных заголовков повторно выбирается ближайший кандидат по тому же правилу, что и полный построитель графа. Поле `related` хранит вклад источника для обоих направлений, поэтому его удаление не стирает такое же ребро, созданное другой заметкой.

Обновление модели локально; построение render snapshot всё ещё содержит полные проходы:

| Этап после edit | Сейчас | Что повторяется |
| --- | --- | --- |
| Чтение БД | Timeline читает только строки событий после cursor; состояния изменённых заметок декодируются из журнала | O(changes), кроме fallback/rescan, где загружается вся история состояний |
| Разрешение ссылок | Только изменённые источники и источники, зависящие от старых/новых ключей цели | O(затронутых источников + кандидатов их целей); unchanged sources не перечитываются |
| PageRank | Точный расчёт при следующем полном render snapshot; после topology delta метрика stale | Полный O(V + E) проход с 20 итерациями |
| Louvain | Точный расчёт при следующем полном render snapshot; после topology delta метрика stale | Полный проход по графу; на практике около O(E log V), worst case здесь не ограничен контрактом |
| Layout | Полный snapshot проверяет сохранённые координаты по путям; same-node-set topology delta сохраняет текущие позиции | O(V + E) при построении полного snapshot; delta не пересчитывает раскладку |
| Binary encode и IPC | Полный snapshot по-прежнему передаёт все массивы; topology delta передаёт только последние изменения слотов и узлов | O(V + E) для полного snapshot; для delta объём ответа зависит от числа накопленных изменений |
| Frontend CPU/GPU | Delta только по узлам меняет degree/date и node texels без пересборки рёбер, CSR или edge buffers. Для фильтров и свёрнутых сообществ contribution index сопоставляет каждый raw edge slot с агрегированной render-парой, а счётчики каждого direction/type bit сохраняют OR-маски всех источников. Dense edge и arrow maps исправляются после swap-delete; Renderer передаёт только затронутые диапазоны через `bufferSubData` | Edge path пропорционален числу обновлений, пока render projection стабильна, за исключением роста CPU/GPU capacity, который копирует текущие данные. Snapshot adopt, смена фильтра/фокуса/collapse projection и удаление ghost-узлов пересобирают индексы за O(E). CSR перестраивается при переполнении overlay; нестабильная или stale collapse projection отклоняет delta до мутации и запрашивает полный snapshot |

Таким образом обновление модели и доставка topology delta уже не требуют полного render snapshot. В режимах без фильтра, с фильтром и со свёрнутыми сообществами обновляются только затронутые render contributions и соответствующие GPU-диапазоны, пока projection стабильна. Для свёрнутых сообществ отдельный type-only индекс поддерживает проекцию adjacency по тем же representative pairs, что и базовая сборка; вклад пары удаляется из adjacency только после исчезновения последнего contributor. Render index пересобирается при snapshot adopt, изменении type/direction filter или focus, изменении collapse projection и удалении ghost-узлов. Projected adjacency index пересобирается при snapshot adopt, изменении type filter и изменении collapse projection; direction filter его не затрагивает. Изменение degree у участника свёрнутого сообщества, изменение `modifiedDay` или `metricsStale` отклоняет collapsed delta до мутации, поскольку обновлённое состояние может изменить выбранные узлы либо сами сообщества. Неизменившиеся ссылки не перечитываются из БД; точные глобальные метрики не обещаются до полного snapshot.

Тесты сравнивают результат пакетного обновления с полной сборкой модели для добавления, удаления, переименования, неоднозначных заголовков и структурных связей; отдельно проверяются пустой пакет, граница timestamp и пропущенный cursor. Тест ограничения повторной обработки использует 100 независимых источников и добавляет цель, на которую ссылается только один источник.

## Контракт topology delta

`GraphModel::apply_batch` формирует diff, `SearchService` владеет ревизией и bounded journal, `SnapshotStore` — единственной копией клиентских массивов. Контракт разрешает topology delta только при том же workspace, generation, layout, epoch и составе заметок, без rescan и при непрерывной истории timeline. Добавление/удаление заметки, потеря ревизии, переполнение журнала или несовпадение этих условий возвращают `None`; `useGraphSnapshot` запрашивает полный snapshot.

Каждый ответ несёт базовый epoch и целевую ревизию. Пары рёбер получают постоянные edge slots в пределах epoch: изменение обновляет маски направления/типа, удаление записывает tombstone (`typeMask=0`, `directionMask=0`), новая пара получает новый слот, tombstone не переиспользуются. Узловые слоты не меняются. Если новый слот успел стать tombstone до catch-up ответа, delta безопасно отклоняется и клиент загружает полный snapshot. Delta также передаёт degree и при необходимости `modifiedDay` затронутых узлов. Журнал ограничен 64 ревизиями и 16 384 записями обновлений; запрос за нижней границей журнала требует полный snapshot.

Клиент проверяет epoch, ревизию, диапазоны и идентичность endpoints существующего слота до мутации. Если delta не меняет рёбра, клиент применяет только degree/date и сохраняет массивы рёбер и CSR; renderer не загружает заново edge, transition и cluster buffers. В режиме «все типы / все направления» плотные render slots сохраняют порядок живых рёбер; удаление уплотняет их заменой последним слотом, добавление занимает следующий слот. При активных фильтрах и collapse contribution index хранит slot → contribution и per-bit refcounts: исчезновение одного raw slot не очищает маску агрегата, пока остаётся другой источник этого бита. Swap-delete обновляет обратные dense карты агрегатов и стрелок. CPU-массивы и GPU VBO имеют запас ёмкости; пока он есть, renderer объединяет смежные dirty-индексы и пишет их через `bufferSubData`. При превышении capacity буфер растёт геометрически и текущий активный диапазон загружается целиком. Render index пересобирается при snapshot adopt, изменении type/direction filter или focus, изменении collapse projection и удалении ghost-узлов; projected adjacency index — при snapshot adopt, изменении type filter или projection. В collapsed режиме projected adjacency меняется по type-mask aggregate и не учитывает render direction filter, как и исходная базовая сборка; изменение representative пары пересобирает adjacency, а нестабильность representative/eligibility (например, изменение degree внутри свёрнутого сообщества, `modifiedDay` или stale глобальных метрик) отклоняет delta до мутации. Изменения связности добавляются к CSR через overlay затронутых соседей, без полного прохода по узлам/рёбрам; overlay ограничен 4 096 направленными записями соседей (примерно 2 048 пар), после чего CSR компактизируется. Удалённый slot не активируется повторно: восстановленная связь получает новый slot, чтобы клиентский tombstone оставался неизменным. Пока идёт morph или остаются ghost-узлы, delta отклоняется и заменяется полным snapshot. После topology delta PageRank, Louvain, компоненты/острова и связанные с ними подсветки помечаются stale и не выдаются за точные; актуальные глобальные метрики возвращаются полным snapshot.

PageRank, Louvain и компоненты связности являются глобальными производными. Изменение одной связи способно изменить значения у несвязанных на вид заметок, поэтому точность не может сочетаться с гарантированно локальным пересчётом. Раскладка в topology delta fast path не пересчитывается: кэшированные позиции сохраняются. Во всех режимах render index и GPU upload обновляются по изменённым слотам, с полным upload при нехватке capacity; snapshot/filter/projection reset остаются O(E), как и fallback для нестабильных представителей. Базовый CSR и его component labels не обходятся, пока overlay не достигнет лимита. Delta только по узлам сохраняет все графовые структуры. Добавление и удаление заметок переходит на полный snapshot. Tombstone растут до смены epoch; bounded journal ограничивает историю catch-up, но не число edge slots в долгоживущем epoch. Render contribution index хранит slot records и 34 счётчика на агрегат для двух направлений и 32 type bits; adjacency index хранит только 32 type counts и не ведёт счётчики направления или arrow map. Typed arrays растут геометрически, а slot records и maps остаются JS-объектами; точное потребление ещё не измерялось на целевых графах. Профиль полного приложения по FPS, CPU и RAM ещё нужен.

## Ограниченный fast path для дат

`SearchService::graph_modified_date_delta` обслуживает только date-only изменения существующих заметок. Ответ содержит исходный epoch двумя 32-битными половинами, текущую ревизию, максимальный `modifiedNewest` и пары `{index, modifiedDay}`. Индексы разрешаются через `path_indices`, построенный один раз вместе с binary snapshot; запрос дельты не сканирует пути графа и не клонирует модель.

Модельная ревизия и ревизия закодированных байтов хранятся отдельно. После принятого date-only обновления модель и timeline cursor продвигаются, а прежние snapshot bytes и epoch остаются базой для повторных ответов. Клиент может запрашивать накопленные изменения от любой ещё поддерживаемой ревизии. Поскольку доказано, что topology не менялась, epoch-bound операции чтения путей, фильтрации и кластеров, а также сохранение координат остаются допустимы. Следующий обычный запрос полного snapshot пересобирает массивы из актуальной модели, создаёт новый epoch и очищает журнал дельт.

Допуск проверяет workspace, generation, layout, исходный epoch, timeline cursor/rescan epoch и непрерывное соответствие индексных ревизий целым timestamp-группам timeline. Каждая запись должна ссылаться на существующую заметку и менять только `modified_ns` в неубывающем направлении; даты должны оставаться конечными. Добавление, удаление, смена пути/заголовка/ссылок/структурных связей, откат даты, пропуск ревизии, полный rescan и потеря старых записей из ограниченного журнала возвращают `None`, чтобы клиент запросил полный snapshot. Проверка и подготовка journal eviction выполняются до изменения модели и кэша, поэтому fallback атомарно оставляет их прежними.

Журнал date-only обновлений также ограничен 64 ревизиями и 16 384 записями. При переполнении его нижняя граница передвигается на удалённую ревизию; запрос от более старого `sinceRevision` получает `None`. `GraphModel::apply_batch` распознаёт те же date-only изменения и правит только метадату заметки, не пересчитывая вклад рёбер и зависимые источники. Topology delta использует отдельный журнал с такими же лимитами.

Тесты fast path проверяют общую transaction-группу с двумя заметками, кумулятивные ответы, сохранение epoch-bound операций, отказ без мутации на topology change/date rollback/rescan/несовпадении epoch-layout и при eviction, который потерял бы запрошенную ревизию, ограничение журнала и формат camelCase для Tauri.

## Roadmap по факту

- **P0 — протокол topology delta: закрыт в оговорённых границах.** Backend передаёт накопленные изменения при неизменном составе заметок; edge slots стабильны в пределах epoch, удаления остаются tombstone, journal ограничен, несовместимое состояние переключает клиента на полный snapshot. Degree и `modifiedDay` входят в обновления. Покрыты Rust service, gateway, `SnapshotStore`, renderer и hook тестами. Добавление и удаление заметок остаются за пределами fast path.
- **P1 — инкрементальный путь до экрана: частично.** Клиент применяет изменения связности через bounded overlay и сохраняет базовый CSR. В default, filtered и collapsed режимах dense mapping и WebGL обновляют затронутые slots через `bufferSubData`; при росте capacity выполняется полный upload. Snapshot/filter/projection resets, ghost removal и fallback при нестабильных представителях остаются полными операциями. Нет профиля памяти и полного Tauri/WebGL приложения по FPS/CPU/RAM на 100, 1 000, 10 000 и 100 000 узлах. Встроенный CUA показал пустой localhost-кадр; временный запуск приложения на 1422 прошёл, но native window недоступен через CUA из-за тайм-аута. Визуальный smoke не подтверждён.
- **P2 — семантический поиск: отложен.** Силовая, иерархическая и кольцевая раскладки уже реализованы. Adamic-Adar и лексические BM25F-предложения работают; поиск по embeddings не реализован, embedding runtime и векторного индекса в проекте нет.
