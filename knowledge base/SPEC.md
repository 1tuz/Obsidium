# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ ПРОЕКТА: AQUILUM

## 1. ОБЩЕЕ ОПИСАНИЕ {#q1w2e3}
Aquilum - сверхбыстрый, локальный (Local-First) таск-трекер и база знаний для команд. {#r4t5y6}
Идея: Скорость Doom Emacs/Obsidian + Структура Jira/Linear. {#u7i8o9}
Философия: Данные у пользователя (локальные .md файлы), управление с клавиатуры, командная синхронизация без конфликтов (CRDT). {#p0a1s2}

## 2. ТЕХНОЛОГИЧЕСКИЙ СТЕК {#d3f4g5}
Десктоп-оболочка: Tauri v2 (Rust) - работа с ОС, файловая система, быстрый системный поиск. {#h6j7k8}
Интерфейс (UI): React + TypeScript реактивный фронтенд. Редактор максимально простой: бесконечный холст и мини-вкладки с разделами функционала (граф, канвас, канбан). {#l9z0x1}
Текстовый движок: Tiptap (ProseMirror) - блочный Markdown-редактор с аутлайном. {#c2v3b4}
Синхронизация: Yjs + WebSockets - алгоритмы CRDT для совместного редактирования. {#n5m6q7}
Бэкенд: Node.js (Relay-сервер) + Supabase - буферизация оффлайн-изменений, хранение медиа, биллинг. {#w8e9r0}
Мини-виджеты: Dataview JS - создание своих мини-программ по отображению заметок по заданным параметрам, вывод времени, программирование и т.д. Они должны адаптироваться под интерфейс программы.
В дальнешем нужна поддержка векторов и апи от популярных платформ типа Gemini, чтобы работать с заметками нативно по запросу. Для этого и нужны ссылки в том числе, чтобы работал RAG, который будет присылать ссылку на конкретное предложение

## 3. АРХИТЕКТУРА MULTIPLAYER-READY {#t1y2u3}
Чтобы сразу заложить возможность мультиплеера и синхронизации, проект с самого начала использует CRDT-структуры (Yjs). {#i4o5p6}
Даже в локальном режиме все документы загружаются в Yjs-модель, изменения происходят в ней, а затем сохраняются в .md файлы. {#a7s8d9}
Для будущего подключения сети создается внутренний API-модуль `SyncModule`. Сейчас он использует заглушку (LocalProvider), но в будущем заменяется на `WebsocketProvider` (или WebRTC) без изменения бизнес-логики приложения. {#f0g1h2}
Это позволяет мгновенно превратить локальный редактор в мультиплеерный инструмент. {#j3k4l5}

## 4. СИСТЕМА УНИКАЛЬНЫХ ИДЕНТИФИКАТОРОВ (ID) {#z6x7c8}
Каждый абзац, заголовок и блок контента имеет короткий уникальный ID. {#v9b0n1}
Он записывается в .md файл прозрачным для пользователя образом (например, HTML-комментариями `<!-- id: a1b2c3 -->` или атрибутами `{#a1b2c3}`). {#m2q3w4}
Это обеспечивает стабильные внутренние ссылки `[[имя_файла#id]]` и внешние Deep Links формата `aquilum://workspace/file#id` или веб-ссылки `https://aquilum.app/workspace/file#id`. {#e5r6t7}
Коллеги могут скидывать эти ссылки друг другу для моментального перехода к нужному абзацу в документах. {#y8u9i0}

## 5. ИНТЕРФЕЙС И WYSIWYG-РЕДАКТОР {#o1p2a3}
Интерфейс должен быть максимально чистым — холст для редактирования и мини-вкладки (редактор, канбан, канвас, граф). {#s4d5f6}
Редактор поддерживает аутлайн (структурированные списки) и обычные абзацы. {#g7h8j9}
Применяется подход «скрытого форматирования» (Inline WYSIWYG): Markdown-разметка видна только при фокусе (клике) на тексте. {#k0l1z2}
Если кликнуть на **жирный текст**, он раскроется в `**жирный текст**`. При потере фокуса (блюре) звездочки исчезают, оставляя только визуальное форматирование. Это делает текст чистым и приятным для чтения. {#x3c4v5}
Внизу показывается статистика документа: сколько слов, сколько предложений, сколько символов.
Будет поддержка автоматической проверки орфографии, нужна самая мощная библиотека и самая быстрая при этом, чтобы она работала только в рамках текущего документа и быстро подхватывалась при переключении между документами. Нужен самый большой словарь русских и английских слов на первое время, а также контекстное выпадающее меню для добавления слова в словарь, который будет глобальным
В будущем будет реализован функционал помощника, который будет подсвечивать клише и т.д.
Должна быть поддержка увеличения интерфейса при клике на CTRL + + или - при этом увеличивается весь интерфейс приложения, все элементы, которые есть - нужно сразу заложить хорошую базу по работе с масштабированием, и тут мне нужен совет, как это грамотно сделать, как в обсидиане
В приложении используется компонентный подход и токены. Каждый реакт компонент - это отдельный файл, который построен на токенах, что позволяет менять темы, масштаб, скругления, отступы и так далее.
Слева будет сайдбар, в котором будут размещены все файлы пользователя. Сайдбар можно скрывать
В самой левой части сайдбара будут отображаться режимы: канбан, канвас, граф и режим заметок, и при клике можно создать новый файл с этим типом. Они всегда отображаются и могут быть отключены или пересортированы между собой
Сверху будут вкладки, как в обсидиане. Одна вкладка - это один конкретный файл
Аутлайны можно перемещать с помощью ALT + стрелочки вверх и вниз, а также с помощью TAB их можно делать 2 уровня, 3 и т.д., а при SHIFT + TAB уровень уменьшается
Должна быть поддержка подсветки аутлайнов. Например, мы делаем - !, и аутлайн подсвечивается красным (одна строка), таким образом мы можем выделять строки
Сами аутлайны работают на тире -. Кстати, при вводе двух тире -- они конвертируются в длинное тире вне кодовых блоков

## 6. КАНБАН И ТЕГИ В MARKDOWN {#b6n7m8}
Канбан-доска не имеет собственной базы данных. Она является лишь визуальным представлением (местом сбора) Markdown-заметок. {#q9w0e1}
Логика завязана на тексте: если в заметке есть тег `#в-работе`, она автоматически попадает в соответствующую колонку Канбана. {#r2t3y4}
При перетаскивании карточки в другую колонку, программа просто заменяет текстовый тег внутри .md файла. {#u5i6o7}
Такой подход сохраняет .md файлы как единственный источник правды без лишних наворотов. {#p8a9s0}

## 7. ВИЗУАЛЬНЫЕ РЕЖИМЫ (ВКЛАДКИ) {#d1f2g3}
Текстовый документ: основной редактор (Zen Mode) с аутлайном. {#h4j5k6}
Канбан-доска: визуализация заметок по тегам (Drag-and-Drop). {#l7z8x9}
Канвас (Холст): свободное пространство для визуального распределения связей и карточек-заметок. {#c0v1b2}
Граф: визуализация ссылок между документами и абзацами. {#n3m4q5}

## 8. ГЛОБАЛЬНЫЙ ПОИСК И НАВИГАЦИЯ {#w6e7r8}
Глобальный поиск: Полнотекстовый движок на стороне Rust (например, Tantivy) для мгновенного поиска по тексту, заголовкам, тегам и ID абзацев. {#t9y0u1} 
Включается поиск сочетанием клавиш CTRL + O, и можно сразу в нем что-то вводить, после чего мгновенно, вне зависимости от кол-ва файлов должны выводиться под ним результаты с подсвеченными совпадениями. Нужен самый быстрый поиск, который будет работать без единого лага. 100 000 заметок он обязан отрабатывать идеально
Управление и навигация: Глобальная Command Palette (Cmd+K) для смены статусов, навигации и создания задач. {#i2o3p4}
В заметочнике сразу должен быть встроен Adamic Adar алгоритм, который будет выводить список в правом сайдбаре заметок, которые находятся на пересечении связей внутри основной заметки, таким образом подсказывая идеи
Также в правом сайдбаре будет вкладка с оглавлением, что позволит перемещаться по заголовкам
И будет вкладка со ссылками, которые можно посмотреть в виде списка

## 9. РАБОТА С МЕДИА {#a5s6d7}
Drag-and-drop файлов. Сохраняются локально в `_assets`. {#f8g9h0}
В командном режиме фоном синхронизируются в облако (S3/Supabase), отдавая относительную ссылку. {#j1k2l3}
Когда переношу изображение или видео на холст, оно загружается в папку с ассетами, и отображается на холсте. При клике на него можно удалить, скопировать ссылку, либо перетащить между абзацами

## 10. УВЕДОМЛЕНИЯ И ИНТЕГРАЦИИ {#z4x5c6}
Интеграция бэкенда с Telegram API для отправки алертов о смене статусов (смене тегов в .md) в личку или рабочие чаты. {#v7b8n9}

## 11. ПЛАГИНЫ И КАСТОМИЗАЦИЯ {#m0q1w2}
Темы: Чистый CSS. Один файл перекрашивает весь интерфейс. {#e3r4t5}
API: Изолированная среда на JS/TS (window.aquilumAPI) для генерации плагинов. {#y6u7i8}

## 12. СТРАТЕГИЯ РАЗРАБОТКИ (КАК НАЧАТЬ) {#o9p0a1}
1. **Базовый сетап**: Tauri v2 + React (TypeScript). Настройка структуры папок. {#s2d3f4}
2. **Yjs & CRDT**: Интеграция Yjs в качестве State Manager для документа даже без сети. Написание парсера/сериализатора Markdown <-> Yjs. {#g5h6j7}
3. **SyncModule**: Создание интерфейса для провайдеров Yjs. Подключение IndexedDB для оффлайн хранения. {#k8l9z0}
4. **Редактор Tiptap**: Настройка Tiptap для поддержки ID у каждого узла и реализации логики "показ Markdown при фокусе". {#x1c2v3}
5. **Теги и парсинг**: Регулярные выражения для поиска тегов статусов и генерация состояния для Канбан-доски. {#b4n5m6}
6. **Граф и Канвас**: Разработка визуальных компонентов на вкладках, работающих с общей моделью данных. {#q7w8e9}
