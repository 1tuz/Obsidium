# Архитектура аутлайна редактора Aquilum

## Назначение

Аутлайн — редакторское представление обычного Markdown-текста. Источник истины всегда остаётся в документе:

```md
- Ненумерованный пункт
1. Нумерованный пункт
```

Модуль не хранит отдельное дерево и не подменяет содержимое визуальной моделью. CodeMirror, Yjs и Markdown-файл содержат одни и те же символы.

## Файлы

```text
src/components/Editor/extensions/outline/
├── constructs.ts   маркеры `- `/`N. `/`N)`, уровни, Lezer-config
├── listCallouts.ts List Callouts (`- !`, `- $`, …) поверх constructs
├── commands.ts     Enter, Shift+Enter, Tab, Shift+Tab
├── preview.ts      декорации, висячий отступ, атомарные отступы продолжений
├── theme.ts        стили аутлайна
├── renumber.ts     пересчёт номеров
└── index.ts        сборка расширения
```

Конструкции списков — только в `constructs.ts`. Preview / commands / renumber их читают.
List Callouts (`listCallouts.ts`) читают `matchOutlineItem` и красят строку, если
после префикса идёт значок из каталога (`! $ & ? ~ @ %`) и пробел. Вкл. по
умолчанию: настройка `editor.listCallouts`. Новые виды пунктов — в `constructs.ts`;
новые callout-символы — в `DEFAULT_LIST_CALLOUTS`.

Цвет выноски задаётся тоном (`highlight`, `question`, `important`, `idea`, `info`, `success`,
`muted`), а не сырым RGB: строка получает `--q-list-callout-color: var(--q-list-callout-<тон>)`,
значения тонов лежат в `styles/tokens/components.css` отдельно для светлой (`:root`, оттенки 600/700
для контраста на белом) и тёмной (`[data-theme="dark"]`, оттенки 300/400) тем. Фон строки —
`color-mix` того же цвета на 12%. Новый символ требует нового тона в обеих темах, иначе маркер
останется без цвета.

Тесты находятся в `src/components/Editor/extensions/outline.test.ts`.

Рабочие файлы разделены по ответственности. Самый большой из них содержит менее 200 строк. Делить их дальше не следует, пока внутри файла остаётся одна причина изменения.

## Подключение

`extensions/index.ts` подключает две части:

1. `outlineExtension` — команды, preview, нумерацию и тему.
2. `outlineMarkdownConfig` из `constructs.ts` — грамматика тех же маркеров для Lezer.

Стандартная Markdown-карта клавиш отключена через `addKeymap: false`. Markdown-команда продолжения строки явно включена только как fallback после команды аутлайна, поэтому для Enter существует один предсказуемый маршрут.

Backspace в карте аутлайна отсутствует. Его всегда обрабатывает стандартная посимвольная команда CodeMirror.

`livePreviewPlugin.ts` больше не обрабатывает `ListMark`. Он отвечает только за заголовки, emphasis, ссылки и прочий Markdown. Стили аутлайна также удалены из общей темы и принадлежат `preview.ts`.

## Какие строки запускают аутлайн

Распознаётся только полный префикс в начале физической строки:

```text
[отступ]-[пробел]
[отступ][цифры].[пробел]
[отступ][цифры)][пробел]
```

`1.` и `1)` — равноправные нумерованные маркеры. Один и тот же путь:
распознавание → preview → Enter/продолжение → renumber → прерывание абзаца.

Примеры:

| Исходная строка | Результат |
|---|---|
| `- текст` | ненумерованный пункт |
| `1. текст` | нумерованный пункт |
| `1) текст` | нумерованный пункт (тот же вид) |
| `12. текст` | существующий нумерованный пункт |
| `12) текст` | существующий нумерованный пункт |
| `-` | обычный текст до ввода пробела |
| `1.` / `1)` | обычный текст до ввода пробела |
| `* текст` | обычный Markdown, не Aquilum Outline |
| `- - текст` | первый `- ` — маркер, второй `-` — содержимое |

Пробел должен быть обычным символом U+0020. Модуль не перехватывает ввод дефиса или пробела и не содержит исправляющих `inputHandler`.

## Отступ и уровень

Один уровень равен четырём визуальным колонкам:

- один `Tab` создаёт один уровень;
- четыре пробела также читаются как один уровень для совместимости с Markdown;
- неполный отступ не образует корректный уровень.

Tab в состоянии CodeMirror настроен через `indentUnit.of("\t")`, поэтому команды отступа записывают настоящий символ `\t`, а не последовательность пробелов.

## Правило родителей

Корневой пункт имеет уровень 1 в пользовательском представлении и нулевой внутренний индекс.

Вложенный пункт считается корректным только при непрерывной цепочке родителей:

```md
- Родитель
	- Ребёнок
		- Внук
```

Все три строки корректны и получают визуальное оформление.

Следующие строки являются сиротскими:

```md
	- Нет корневого родителя
```

```md
- Первый уровень
		- Пропущен второй уровень
```

Для сиротской строки:

- дефис не заменяется круглым буллитом; `-` / `N.` / `N)` цвета текста
  (`q-md-outline-mark-plain`), а не серого syntax;
- не применяется висячий отступ;
- перенос выполняется как у обычного текста;
- исходные символы и табуляция не изменяются.

Пустая строка **не** завершает цепочку родителей (вложенный список ниже остаётся
валидным). Любая непустая строка без префикса аутлайна — завершает.

Цвет маркеров (единый механизм в `preview.ts`):

| Состояние | Вид |
|---|---|
| валидный, каретка не на маркере | серый `--q-text-tertiary` (буллит-виджет / `q-md-outline-mark`) |
| сирота или reveal | цвет текста `--q-editor-text` (`q-md-outline-mark-plain`) |

## Почему Tab не создаёт блок кода

В CommonMark четыре начальные колонки означают indented code block. Поэтому без дополнительного правила строка `\t- текст` разбирается как код и получает серый фон от стиля `monospace`.

`outlineMarkdownConfig` в `constructs.ts`:

1. `remove: ['SetextHeading']` — иначе `абзац\n- ` парсится как Setext H2
   (крупный жирный текст на всём абзаце), пока не появится текст пункта.
   Заголовки в Aquilum — только ATX (`#` …). `---` как HorizontalRule сохраняется.
2. Перед `IndentedCode`: если после отступа полный префикс `- `/`N. `/`N)`,
   базовая позиция переносится к маркеру → список, не code block.
3. `endLeaf`: пустой `- `/`1. `/`1) ` прерывает абзац. В CommonMark/Lezer без текста
   после маркера список абзац не рвёт — outline уже рисует маркер, парсер ещё нет,
   каретка прыгает.

Обычный табулированный текст не затрагивается:

```text
\tcode       -> CodeBlock
\t- пункт    -> BulletList
\t1. пункт   -> OrderedList
```

## Круглый буллит

Круглый буллит создаётся только для корректного ненумерованного пункта.

`preview.ts` заменяет CodeMirror-виджетом весь префикс маркера — дефис **вместе с его
пробелом**, то есть диапазон до `contentFrom`. Виджет содержит пустой `span`, а круг рисуется
через `::after`:

- размер — `--q-space-5`;
- цвет — `--q-icon-tertiary`;
- форма — `border-radius: 50%`.

Ширина виджета — `--q-editor-list-marker-width`, ровно та величина, которую вычитает висячий
отступ. Круг внутри прижат к началу зоны и отодвинут на полширины первого знака
(`calc((1ch - var(--q-space-5)) / 2)`), поэтому визуально стоит там же, где стоял, когда зона
была шириной в один знак.

Нумерованный маркер занимает ту же зону: `q-md-outline-mark` покрывает `N. ` вместе с пробелом
и получает `min-inline-size: var(--q-editor-list-marker-width)`.

Замена является только визуальной. В документе и Markdown-файле остаётся `- `.

Если строка содержит `- - текст`, заменяется только первый маркер с его пробелом. Второй дефис
остаётся видимым содержимым: `• - текст`.

## Единое правило live preview

Общее правило — `shouldRevealSyntax` в `livePreviewVisibility.ts`
(только `head`, только строка каретки, `touch` / `inside`). Детали и парсер-чанк:
`knowledge base/editor-markdown-live-preview.md`.

Для inline-markdown reveal-range = символы маркера, не весь `StrongEmphasis` /
`Emphasis`.

Outline: `shouldRevealSyntax(..., 'touch')` на `-` / `N.` / `N)` — обе стороны
маркера на строке каретки, не пробел после.

Incomplete-префикс не является аутлайном и не получает декораций:

| Текст | Preview |
|---|---|
| `- ` | буллит в тексте; исходный `-` при каретке слева или справа от дефиса |
| `-` | обычный дефис |
| `1. ` / `1) ` | приглушённый номер в тексте; исходный номер при каретке на маркере с любой стороны |
| `1.` / `1)` | обычный текст |
| `1` | обычный текст |

## Висячий отступ и перенос

Для корректного пункта вычисляются две ширины:

```text
levelIndent = количество уровней × --q-editor-list-indent-width
markerWidth = длина маркера + один пробел
```

Примеры `markerWidth`:

- `- ` — `2ch`;
- `1. ` — `3ch`;
- `12. ` — `4ch`.

К строке применяется:

```css
padding-inline-start: levelIndent + markerWidth;
text-indent: -(levelIndent + markerWidth);
```

Первая строка возвращается к позиции маркера. Все автоматически перенесённые строки сохраняют padding и начинаются точно под первой буквой первого слова.

Совпадение точное только потому, что зона маркера на экране равна `markerWidth`. Пока виджет
буллита был шириной `1ch`, а пробел после него оставался живым текстом, зона была уже расчётной:
шрифт редактора пропорциональный, и пробел в нём заметно уже знака `0`. Перенесённая строка
вставала на несколько пикселей правее первой буквы. Поэтому маркер и его пробел заменяются одной
декорацией фиксированной ширины, а не подгоняются друг под друга.

Перенос длинного текста **без пробелов** — как у ссылок (`.q-md-link-flow`):
`word-break: break-all` + `overflow-wrap: anywhere` на `.q-md-list-item`.
Иначе CodeMirror/Obsidian-подобная вёрстка часто сбрасывает всю простыню
на следующую visual-line целиком.

Для некорректного или сиротского пункта класс строки не создаётся, поэтому эта формула не применяется.

Диапазоны CodeMirror сначала собираются независимо, затем передаются в `Decoration.set(..., true)`. CodeMirror сортирует их до построения набора. Это предотвращает падение preview на вложенных строках, где диапазон табуляции начинается раньше диапазона маркера.

## Enter

Команда Enter работает по текущей физической строке.

Для ненумерованного пункта:

```md
- текст|  ->  - текст
              - |
```

Для нумерованного пункта:

```md
2. текст| ->  2. текст
              3. |
```

Начальный отступ копируется без преобразования. Поэтому вложенный пункт продолжается на том же уровне.

Если после префикса нет текста:

- вложенный пункт — Enter снимает один уровень отступа, маркер остаётся
  (`⇥⇥- |` → `⇥- |`); список ниже не рвётся пустой строкой;
- корневой пункт — Enter удаляет пустой пункт и завершает список на этой строке.

Логика только в `commands.ts` / `constructs.reduceOutlineIndent` (рядом с continue/indent).

Если строка не распознана как аутлайн, команда возвращает `false`: обработку получает стандартный Markdown Enter, затем обычный Enter CodeMirror.

Enter на строке, которая визуально продолжает пункт после мягкого переноса, открывает следующий пункт списка, а не продолжает текст. Enter на пустой строке цитаты (`>` или `> `) выходит из цитаты и оставляет после неё пустую строку абзаца.

## Shift+Enter и строка продолжения

Shift+Enter внутри пункта переносит строку так, что текст встаёт под текстом строки выше.
В документ пишется настоящий отступ — отступ пункта плюс пробелы по числу символов маркера
вместе с его пробелом (`continuationIndent`):

```md
- текст|     ->  - текст
                 ␣␣|

12. текст|   ->  12. текст
                 ␣␣␣␣|
```

Отступ настоящий, поэтому строка остаётся продолжением пункта и в Markdown-файле: экспорт и
сторонние редакторы видят ту же структуру.

Он же служит признаком. Продолжение — это строка, начинающаяся **ровно** с `continuationIndent`
открытого пункта, в том числе когда, кроме отступа, на ней ещё ничего нет: сразу после
Shift+Enter строка выглядит именно так. Без отступа отличить продолжение от строки, где просто
стёрли маркер, было бы нечем, и инвариант «непустая строка без префикса завершает список»
перестал бы работать.

Пункт для строки ищет `openOutlineItem`: поднимается вверх до ближайшего маркера и подтверждает
продолжение, только если отступ совпадает. Вне пункта возвращает `null`, команда — `false`,
и Shift+Enter достаётся стандартному `insertNewlineAndIndent`.

### Почему это выравнивается точно

Потому что зона маркера на экране равна `markerWidth` (см. «Круглый буллит»). Пока она была
уже расчётной, никакое число пробелов не совпало бы с ней при пропорциональном шрифте.

Сам отступ на экране места не занимает: `q-md-list-continuation-indent` схлопывает его в нулевую
ширину поверх `q-md-list-indent`, чьи свойства он переиспользует — включая `text-indent: 0`
и `vertical-align: text-bottom`, без которых `inline-block` с `overflow: hidden` сдвинул бы
базовую линию строки. Правило нулевой ширины стоит в теме **после** `q-md-list-indent`:
специфичность одинаковая, побеждает последнее.

Позицию текста задаёт только `padding` строки, а `q-md-list-continuation` обнуляет висячий
`text-indent` — маркера на строке нет, возвращать первую строку к нему нечем. Без этого
обнуления строка уезжает влево, вплоть до края редактора.

### Каретка и Backspace

Отступ продолжения объявлен атомарным через `EditorView.atomicRanges` — штатный механизм
CodeMirror. Каретка не встаёт внутрь схлопнутого отступа, а Backspace снимает его целиком одним
нажатием. Собственной команды Backspace у аутлайна по-прежнему нет: удаляет штатная команда,
атомарен лишь диапазон.

### Enter на строке продолжения

Enter открывает **следующий пункт списка**, а не ещё одну строку продолжения:

```md
- текст          - текст
  продолжение| ->   продолжение
                 - |
```

Это расходится со штатным `insertNewlineContinueMarkup` из `@codemirror/lang-markdown`: тот на
строке продолжения (`continued`, когда `item.from` выше начала строки) вставляет не маркер, а
`blank()` — ещё один пробельный отступ. Команда аутлайна стоит перед ним в карте клавиш, поэтому
до штатной ветки дело не доходит.

Отступ пишется пробелами и намеренно не проходит через `normalizeIndent` из того же пакета: при
`indentUnit === "\t"` тот свернул бы отступ шириной в четыре колонки (например, у `12. `) в один
`\t`, а `\t` в Aquilum означает уровень вложенности — продолжение превратилось бы во вложенный
пункт.

## Tab и Shift+Tab

`Tab` вызывает `indentMore`, а `Shift+Tab` — `indentLess`.

Так как `indentUnit` равен `\t`:

- Tab добавляет один настоящий таб в начало строки;
- Shift+Tab удаляет один уровень;
- выделение нескольких строк обрабатывается штатной командой CodeMirror;
- содержимое после отступа не переписывается.

После изменения документа модель заново вычисляет цепочку родителей. Поэтому буллит появляется или исчезает только в зависимости от новой структуры.

## Backspace

Модуль не регистрирует собственную команду Backspace и не использует Markdown-команду `deleteMarkupBackward`.

Удаление всегда посимвольное:

```text
-  -> - -> пустая строка
1. -> 1. -> 1 -> пустая строка
```

После каждого удаления CodeMirror создаёт обычную транзакцию. Модель заново читает строку, а live preview немедленно пересобирает декорации:

- после удаления пробела из `- ` круглый буллит исчезает и становится виден `-`;
- после удаления пробела из `1. ` серое оформление номера исчезает;
- после удаления точки `1.` остаётся обычный символ `1`.

## Нумерация

Нумерованные пункты используют отдельный счётчик для каждого уровня.

После изменения документа `renumber.ts` планирует один microtask и проверяет текущий текст. Изменяются только цифры; суффикс `.` или `)` и содержимое пунктов не затрагиваются.

Пример:

```md
4. Первый       -> 1. Первый
	8) Вложенный -> 	1) Вложенный
	9) Вложенный -> 	2) Вложенный
7. Второй       -> 2. Второй
```

Ненумерованный пункт на текущем уровне завершает последовательность номеров этого уровня. Вложенные пункты не сбрасывают счётчик родительского уровня.

## Поток данных

```text
клавиатура
-> транзакция CodeMirror
-> команды аутлайна при Enter/Tab
-> текст EditorState
-> yCollab
-> Y.Text("codemirror")
-> debounce сохранения
-> атомарная запись Markdown-файла
```

Preview-декорации не входят в этот поток. Они читают `EditorState.doc`, но никогда не записываются в Yjs или файл.

## Инварианты

Сквозные для всего приложения (редактор, парсер, preview, команды, тесты):

1. Полные префиксы списка равноправны: `- `, `N. `, `N) ` (пробел U+0020 обязателен).
2. Любой из этих префиксов **сразу** начинает список, в том числе под абзацем и с пустым содержимым пункта — без Setext-заголовка и без ожидания первой буквы текста.
3. `1.` и `1)` — один тип нумерованного пункта; суффикс `.` / `)` сохраняется при Enter и renumber.
4. Одна введённая `-` создаёт одну `-` в документе; preview документ не меняет.
5. В строке заменяется только первый структурный дефис буллита.
6. Сиротский уровень не получает буллит и висячий отступ; маркер цвета текста.
7. Пустая строка не рвёт цепочку родителей; непустой plain-текст — рвёт.
8. Tab не превращает строку аутлайна в CodeBlock; обычный `\tтекст` остаётся кодом.
9. Enter создаёт только один следующий маркер того же вида (включая `)`).
10. Пустой вложенный пункт + Enter — outdent на один уровень; пустой корневой — выход из списка.
11. Уровни хранятся символами `\t`; нумерация меняет только цифры, не суффикс.
12. Общий live preview не знает правил аутлайна; Backspace — посимвольный, без перехвата аутлайном.
13. Сырой маркер раскрывается при каретке слева/справа от `-`/`N.`/`N)`, но не после пробела в тексте.
14. Заголовки в UI — только ATX (`#`); Setext отключён. `---` после абзаца — HorizontalRule.
15. Soft-wrap длинных строк без пробелов в пунктах списка — тот же, что у ссылок (`break-all` / `anywhere`), при сохранённом висячем отступе.
16. List Callouts (`- !`, `- $`, …) включены по умолчанию (`editor.listCallouts`); значок после полного префикса списка + пробел; сырой символ при каретке на нём.

## Чекбокс задачи

Пункт списка с чекбоксом рисуется в том же проходе, что и остальные маркеры: `[ ]` заменяется квадратиком, `[x]` — залитым квадратиком с галочкой, а у каретки разметка раскрывается тем же `shouldRevealSyntax`, что и маркер. Отдельного расширения для задач нет — второй проход по строкам ради трёх символов не нужен, и вся раскладка пункта осталась в одном месте.

Маркер при этом остаётся маркером и превращается в буллет по обычному правилу: зона маркера кончается там, где начинается чекбокс (`contentFrom` — это длина `«- »`), поэтому две замены не пересекаются и ни одна не отменяет другую.

Щелчок по квадратику переключает задачу: виджет находит чекбокс в своей строке через общую функцию `modules/documents/taskCheckbox` и правит документ одной транзакцией. Та же функция обслуживает чекбоксы в выдаче блока запроса ([[dataview-queries]]) — правило «что считать задачей» описано один раз. Пункт списка она распознаёт через `matchOutlineItem` из `constructs.ts`, а не своим разбором: задача бывает под `- `, `N. ` и `N) ` и не бывает под `*`/`+`. Второй разборщик маркеров уже разошёлся с этим модулем — он принимал звёздочку и плюс, но не знал `N) `.

**Сам квадратик — один компонент на всё приложение**: `components/Common/taskCheckbox.ts` собирает DOM, `styles/components/task-checkbox.css` задаёт вид (20×20, радиус 6, фон из `--q-bg-surface-overlay`, наведение `--q-bg-surface-active`, отмеченный — `--q-bg-accent` с внутренней тенью, галочка 16×16 путём иконки `check` из lucide). Обе темы, редакторская и блока запроса, свои копии этих стилей потеряли: у чекбокса одно описание вида, а не два похожих.
