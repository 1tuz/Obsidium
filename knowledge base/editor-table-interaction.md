## Взаимодействие и выделение в таблицах

## Один режим взаимодействия

В таблице одновременно действует только один видимый механизм выделения.

| Действие | Результат |
| --- | --- |
| Обычный клик по ячейке | Открывает встроенный CodeMirror и ставит каретку. |
| Drag внутри уже активной ячейки | Обычное текстовое выделение CodeMirror. |
| Drag пересёк границу другой ячейки | Текстовое выделение закрывается, начинается прямоугольный табличный диапазон. |
| Shift + клик по ячейке | Расширяет диапазон от его anchor до ячейки клика. |
| ПКМ внутри диапазона | Сохраняет диапазон и открывает его контекстное меню. |
| ПКМ по ячейке вне диапазона | Снимает старый диапазон, выбирает только эту ячейку и открывает меню. |
| Клик по букве или номеру на strip | Выделяет целый столбец или строку. |
| Shift + клик по strip | Расширяет уже существующий прямоугольник. |
| Drag за букву/номер strip | Перестановка блока — см. [[editor-table-strip-reorder]]. |
| Hover/drag по границе строки или столбца | Resize трека + синяя линия — [[editor-table-structure]]. |
| ЛКМ вне диапазона или вне таблицы | Снимает табличный диапазон. |
| Escape при диапазоне | Снимает диапазон. |
| Escape в редакторе ячейки | Завершает редактирование и выводит каретку за таблицу. |
| Double click в тексте ячейки | Выделяет слово CodeMirror тем же полупрозрачным цветом. |
| Del / Backspace при диапазоне | Очищает значения выбранных ячеек, не меняя структуру. |

Нельзя собрать набор разрозненных ячеек: диапазон всегда прямоугольный.
Если прямоугольник касается существующего merge-региона, он расширяется до
полной границы этого региона (`expandSelection` в `selection.ts`). Поэтому
нельзя создать половину объединения, двойную границу или частично
пересекающиеся области. То же правило питает strip-reorder.

## Визуальное правило

Диапазон ячеек рисует ровно один DOM-overlay:

```text
┌───────────────────────────┐
│ выбранный прямоугольник    │
│                           │
└───────────────────────────┘
```

Он даёт полупрозрачную заливку `--q-editor-table-selection-bg` и одну внешнюю
рамку `--q-border-accent`. У соседних выбранных ячеек нет отдельных классов
границ и нет внутренних синих линий.

Видимость overlay управляется только стандартным атрибутом `hidden`. Тема не
задаёт ему `display`: иначе авторский CSS переопределит скрытие и снятый в
модели диапазон останется видимым.

Вложенный редактор ячейки использует `drawSelection()`: он один рисует
каретку и текстовое выделение через `.cm-cursor` и `.cm-selectionBackground`.
Его нативный `::selection` локально прозрачен с тем же приоритетом, что и
внутренний fallback CodeMirror для системного `Highlight`. Обычные ячейки вне
режима редактирования имеют `user-select: none`, а родительский слой
CodeMirror прячется на время редактирования и диапазона. Поэтому у текста
остаётся один видимый полупрозрачный слой.

## Диагностика двойного выделения

Подробная схема исправления, переходы состояний и регрессионная проверка —
в [[editor-table-double-selection-fix]].

Двойное выделение означает, что одновременно видны два независимых слоя:

1. нативный браузерный `::selection` (обычно ярко-синий `Highlight`);
2. рисуемый CodeMirror `.cm-selectionBackground` или табличный
   `.q-md-table-selection-overlay`.

Краткая матрица слоёв:

| Состояние | Разрешённый видимый слой |
| --- | --- |
| Drag внутри активной ячейки | только nested CodeMirror selection |
| Drag за границу ячейки | только один табличный overlay |
| Выделение обычного текста вне таблицы | только родительский CodeMirror |
| Потеря фокуса | сохранённый табличный диапазон допустим; нативный слой не должен добавляться поверх него |

## Enter в названии, когда заметка начинается таблицей

`tableCaretGuard` в `extensions/tables/boundary.ts` — фильтр транзакций, который не даёт схлопнутой
каретке остаться внутри скрытого источника pipe-таблицы: попав в диапазон таблицы, каретка
переставляется на `table.to`, то есть **за** таблицу. Для навигации внутри тела это правильно.

Но позиция каретки не всегда приходит от навигации. Enter в инпуте названия переводит её в нулевую
позицию тела, и если заметка начинается таблицей, эта позиция лежит внутри таблицы — guard уносил
каретку за таблицу, и написать что-то перед ней было нельзя вообще.

Устройство после правки. Определение вынесено в чистую функцию `docStartsWithTable(state)`: она
отвечает, начинается ли документ таблицей (единственный вызов — из нулевой позиции, поэтому
параметра позиции нет). Действие живёт в `Editor/titleCaret.ts` рядом с `focusBodyAt` —
`enterBodyFromTitle(body)` либо ставит каретку в ноль как раньше, либо вставляет `\n` в позицию 0
и ставит каретку на открытую строку.

Тонкость, из-за которой это работает без спора с guard'ом: селекция в спецификации транзакции
задаётся в координатах **нового** документа. После вставки `\n` в позицию 0 каретка на
0 — это начало пустой строки, а таблица уезжает на строку ниже, то есть каретка оказывается
**перед** таблицей, а не в ней, и условие guard'а `head >= table.from` уже ложно. Проверено тестом
`opening the line puts the caret before the table, so the guard leaves it alone` в `boundary.test.ts`:
он поднимает состояние **с подключённым** `tableCaretGuard`, иначе проверка была бы бессмысленной.

Отдельно от этого работает `tableBlankLineFilter` там же: он следит, чтобы под каждой таблицей была
пустая строка. Верхнюю границу он не трогает — это и есть причина, по которой понадобилась отдельная
функция, а не расширение существующего фильтра.
