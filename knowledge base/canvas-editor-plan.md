# Canvas: аудит и план развития

План развития доски. Реализованное устройство описано в [[canvas-json-format]]; здесь — состояние,
найденные дефекты, выбранная архитектура и порядок работ с критериями завершения. Реализованное и
запланированное не смешиваются: пункты помечены статусом.

## Связанные документы

- [[canvas-json-format]] — формат файла, автозоохранение, ссылки, карточки.
- [[render-performance-pass]] — общий проход по производительности интерфейса.
- [[editor-viewport-decorations]] — как редактор решает похожую задачу видимой области.
- [[tech-debt]] — долг, который план закрывает.

## Что уже есть (реализовано)

Доска работает на Preact + HTML/CSS + SVG. Точка правды — обычный `.canvas` (JSON Canvas), чужие поля
сохраняются, `.canvas` открывается в Obsidian и обратно.

## Реестр дефектов

Приоритеты: P0 — доска визуально или функционально не выполняет основную задачу; P1 — заметный
дефект взаимодействия или экспорта; P2 — неудобство, долг, отсутствие проверки. Для каждого пункта
указано, подтверждён он чтением кода, воспроизведением в тесте или пока не проверен.

### P0

**P0-1. Фигуры почти невидимы, особенно на тёмной бумаге.**
Подтверждено чтением CSS и вычисляемой цепочки токенов.

- Воспроизведение: открыть доску, поставить тёмную бумагу, нарисовать прямоугольник/ромб/эллипс,
  снять выделение.
- Ожидаемо: фигура различима без выделения, у неё есть заливка и контрастная обводка.
- Фактически: заливка `transparent`; обводка берётся из `--q-canvas-default-stroke`, а это
  `--q-red-600` (`#cd1f0e`); ромб получает контур через `clip-path` на HTML-боксе, поэтому граница
  прямоугольника обрезается и настоящих рёбер у ромба нет; текст внутри ромба тоже обрезается.
- Причина: `.q-canvas__object > .q-canvas-card` задаёт `border-color: var(--q-canvas-default-stroke)`
  для всех карточек, а не только для фигур; `.q-canvas__object--rectangle/diamond/ellipse >
  .q-canvas-card` делает фон прозрачным; `.q-canvas__object--diamond > .q-canvas-card` использует
  `clip-path: polygon(...)`.
- Файлы: `obsidium-app/src/components/Canvas/CanvasView.css`, `CanvasCard.css`, `CanvasView.tsx`.
- Исправление: рисовать фигуру отдельным SVG-слоем геометрически корректно (rect/polygon/ellipse),
  заливка по умолчанию из ink/paper, обводка нейтральная, текст не обрезается. Выделение — отдельный
  контур, не замена обводки.
- Тесты: фигура присутствует в DOM и в SVG с непустыми `fill`/`stroke`; снятие выделения не меняет
  геометрию и цвета фигуры; текст ромба не обрезан (нет `clip-path` на карточке).

**P0-2. Толщина обводки фигуры зависит от зума, а выделение меняет саму фигуру.**
Подтверждено чтением CSS.

- Воспроизведение: изменить зум от 0.2 до 2.5 при выделенной фигуре.
- Ожидаемо: обводка остаётся визуально одинаковой; выделение добавляет контур, не убирая обводку.
- Фактически: `border-width: var(--q-border-3)` масштабируется вместе с `transform: scale(...)`;
  правило `.q-canvas[data-paper-style] .q-canvas__object.is-selected > .q-canvas-card` меняет
  `border-color` на `--q-canvas-edge`.
- Причина: HTML-граница внутри масштабируемого мира; состояние выделения смешано с состоянием фигуры.
- Файлы: `CanvasView.css`, `CanvasView.tsx`.
- Исправление: SVG-обводка с толщиной, пересчитанной как `base / zoom`; отдельный слой выделения;
  `is-selected` не меняет `fill`/`stroke` фигуры.
- Тесты: при `zoom = 0.5` и `zoom = 2` атрибут `stroke-width` меняется обратно пропорционально;
  после снятия выделения `stroke`/`fill` те же.

**P0-3. Картинка из файлового узла не показывается: имя файла вместо изображения.**
Подтверждено чтением кода.

- Воспроизведение: перетащить `photo.png` на доску; появляется файловая карточка с заголовком
  `photo.png`, изображения нет; в консоли запрос к `Files/Files/photo.png`.
- Ожидаемо: сразу видно изображение, имя не подменяет его.
- Фактически: эффект `fileContents` строит Markdown `![photo.png](Files/photo.png)`, а
  `resolveImageUrl` для файлового узла берёт `parentDirectory(absolutePath(node.file))`, то есть
  `Files`, и добавляет путь ещё раз.
- Причина: путь узла уже workspace-relative, а резолвер трактует его как путь относительно каталога
  самого файла. Плюс файловая карточка всегда рисует заголовок и Markdown.
- Файлы: `CanvasView.tsx` (`fileContents`, `resolveImageUrl`), `CanvasCard.tsx`.
- Исправление: файловый медиа-узел рендерить как `<img>`/`<video>` с URL от корня workspace; для
  Markdown внутри заметки — от каталога заметки; для текстовой карточки — от каталога `.canvas`;
  внешние URL не трогать. Заголовок для медиа не показывать.
- Тесты: узел `Files/photo.png` даёт `src="/vault/Files/photo.png"` (при моке `convertFileSrc`),
  заголовка нет; Markdown-картинка в заметке `Notes/Plan.md` с `diagram.png` резолвится в
  `Notes/diagram.png`; в текстовой карточке доски `Boards/Board.canvas` — в `Boards/diagram.png`.

**P0-4. Видео и состояния загрузки/ошибки медиа отсутствуют.**
Подтверждено чтением кода.

- Воспроизведение: перетащить `.mp4`; карточка показывает только имя. Битая картинка показывает
  пустой прямоугольник без сообщения.
- Ожидаемо: видео с нативными контролами, без автозапуска; у изображения/видео есть состояние
  загрузки и понятная ошибка.
- Фактически: `fileContents` обрабатывает только Markdown и изображения; видео не попадает ни в одну
  ветку. `CanvasCard` не имеет `onError`/`onLoad`.
- Файлы: `CanvasView.tsx`, `CanvasCard.tsx`, `CanvasCard.css`, `modules/docs/imageEmbeds.ts`.
- Исправление: общий компонент медиа-превью с `loading`/`error`, `preload="metadata"`, `controls`,
  `playsInline`; форматы из `imageEmbeds` (PNG, JPEG, WebP, GIF, SVG, AVIF, BMP + видео).
- Тесты: видео-узел содержит `<video controls>` без `autoplay`; битый `src` показывает
  локализованное сообщение; после `load` индикатор исчезает.

**P0-5. Вставка снимка экрана из буфера не срабатывает.**
Подтверждено чтением кода.

- Воспроизведение: сделать снимок экрана, вставить на доску.
- Ожидаемо: изображение импортируется и появляется.
- Фактически: `handlePaste` читает только `clipboardData.files`; в WebView снимок часто приходит
  как `DataTransferItem` с `kind: 'file'` и пустым `files`.
- Файлы: `CanvasView.tsx`.
- Исправление: fallback на `clipboardData.items`, `getAsFile()`; вставка текстовой ссылки на
  изображение создаёт link-узел; несколько файлов — несколько узлов.
- Тесты: paste с `items`, но без `files`, импортирует; paste текстового URL изображения создаёт
  link-узел; paste нескольких файлов создаёт несколько узлов со смещением.

**P0-6. Текст внутри ромба обрезается.**
Подтверждено чтением CSS. Симптом P0-1, но проверяется отдельно.

- Воспроизведение: нарисовать ромб, дважды щёлкнуть, ввести длинный текст.
- Ожидаемо: текст остаётся внутри фигуры и переносится.
- Фактически: `clip-path` обрезает весь HTML-бокс, включая текст.
- Файлы: `CanvasView.css`, `CanvasCard.tsx`.
- Исправление: убрать `clip-path` с карточки; фигуру рисует SVG, текст живёт в обычном боксе с
  внутренними отступами.
- Тесты: на карточке фигуры нет `clip-path`; текст присутствует в DOM.

**P0-7. Геометрия узлов не применялась в реальном браузере.**
Подтверждено в Chromium через Vite-стенд.

- Воспроизведение: отрисовать `style={{ left: 120, top: 40, width: 280, height: 180 }}` компонентом Preact 11.
- Ожидаемо: узел стоит в точке (120, 40) и имеет размеры 280×180.
- Фактически: в атрибуте `style` остаётся только `z-index`, `left`/`top`/`width`/`height` отбрасываются,
  потому что Preact не добавляет `px`, а CSSOM не принимает безразмерные значения длины. Узел получает
  `left: auto` и `width: auto`.
- Причина: числовые значения в inline-стилях без единиц.
- Файлы: `CanvasView.tsx`, `CanvasSelectionToolbar.tsx`.
- Исправление: `canvasNodeStyle`/`canvasPixels` в `modules/canvas/renderStyle.ts`.
- Тесты: `renderStyle.test.ts` (единицы, дробные координаты, оверлеи). happy-dom такой регресс не ловит,
  поэтому проверка живёт на чистой функции.

### P1

**P1-1. Невидимые точки соединения перехватывают указатель.**
Подтверждено чтением CSS: `.q-canvas__connect` имеет `opacity: 0`, но не `pointer-events: none`.

- Воспроизведение: навести на пустое место рядом с карточкой и попытаться начать рамку выделения.
- Ожидаемо: невидимая точка не мешает.
- Фактически: четыре кнопки 12×12 вокруг каждой карточки принимают pointerdown.
- Исправление: `pointer-events: none` в скрытом состоянии, `auto` при hover, фокусе и активном
  инструменте соединения.
- Тесты: у скрытой точки вычисляется `pointer-events: none` (проверка CSS-файла и/или класса).

**P1-2. Маркеры изменения размера конкурируют с фигурой.**
Подтверждено чтением кода.

- Воспроизведение: выделить группу или несколько карточек.
- Ожидаемо: один набор маркеров или bounding box; маркеры не закрывают контур.
- Фактически: `selection.includes(node.id) && resizeHandles.map(...)` даёт по 8 маркеров каждому
  выделенному узлу; размер 12 px и красный фон; маркеры масштабируются вместе с миром.
- Исправление: 8 маркеров только при единственном выделенном узле; размер 8–10 px, нейтральная
  заливка, контрастная рамка, counter-scale `1 / zoom`; при мультивыделении — общий bounding box.
- Тесты: 0 маркеров без выделения, 8 при одном узле, 0 при двух (или bounding box); размер
  компенсирует зум.

**P1-3. Нет компактной панели действий у выделения.**
Подтверждено: действия есть только в контекстном меню по правому клику.

- Ожидаемо: панель рядом с выделением с «на передний план», «на задний план», «дублировать»,
  «группировать/разгруппировать», «удалить»; горячие клавиши сохраняются.
- Фактически: только контекстное меню; «разгруппировать» вызывает удаление группы.
- Исправление: `CanvasSelectionToolbar` над выделением; разгруппировка удаляет только группы,
  участники остаются и выделяются.
- Тесты: панель появляется при выделении и исчезает при снятии; кнопки вызывают операции;
  разгруппировка сохраняет участников.

**P1-4. Порядок наложения не проверен на видимый результат.**
Вероятный риск, не подтверждённый дефект.

- Воспроизведение: две пересекающиеся карточки, `Cmd ]` / `Cmd [`.
- Ожидаемо: меняется и DOM-порядок, и hit-test.
- Фактически: `reorderSelection` меняет порядок массива `nodes`, а рендер идёт в порядке массива;
  отдельного дефекта не найдено, но регрессионного теста нет.
- Исправление: тест на порядок `.q-canvas__object` и на то, что верхний узел получает клик.
- Тесты: после `front` выбранный узел последний в DOM; после `back` — первый.

**P1-5. Экспорт свободной линии теряет положение.**
Подтверждено чтением `canvasSvg`: путь строится из локальных точек без `translate(node.x, node.y)`.

- Воспроизведение: нарисовать линию в правом нижнем углу, экспортировать SVG.
- Ожидаемо: линия на своём месте.
- Фактически: путь рисуется около начала координат.
- Исправление: `<g transform="translate(x y)">` вокруг path.
- Тесты: экспорт содержит `translate` с координатами узла.

**P1-6. Экспорт заменяет изображения текстом.**
Подтверждено чтением `canvasSvg`: для файлового узла выводится `foreignObject` с путём файла.

- Ожидаемо: изображение присутствует в SVG/PNG.
- Исправление: асинхронно собирать data URL для локальных изображений и внешних ссылок; вставлять
  `<image>` с сохранением пропорций и прозрачности; видео — явный placeholder с именем.
- Тесты: экспорт файлового узла `Files/photo.png` содержит `<image href="data:image/png...">`.

**P1-7. Пресетные цвета фигур экспортируются как CSS-переменные.**
Подтверждено чтением `canvasSvg`: `resolvedStroke` не разворачивает пресет `1…6`, в отличие от
`resolvedFill`.

- Ожидаемо: в файле только конкретные цвета.
- Исправление: единая функция разрешения цвета для fill и stroke.
- Тесты: узел с `color: '4'` даёт зелёный hex, а не `var(--q-green-600)`.

**P1-8. Фон бумаги и rich-текст в экспорте ненадёжны.**
Подтверждено чтением: фон задан `style` на корне SVG, текст — `foreignObject`.

- Ожидаемо: фон виден и в SVG, и в PNG; текст читается.
- Исправление: первый элемент — `<rect fill="paper">`; в `foreignObject` встроить минимальные стили
  печати; для PNG проверять растеризацию в WebView.
- Тесты: корневой SVG содержит фон-прямоугольник; PNG-экспорт в Chromium даёт непустое изображение.

**P1-9. Картинки в текстовых и link-карточках резолвятся от корня workspace, а не от доски.**
Подтверждено чтением `resolveImageUrl`: для не-файловых узлов база — `workspacePath`.

- Ожидаемо: как у относительных Markdown-ссылок — каталог `.canvas`.
- Исправление: единый резолвер с явной базой; файловый узел — каталог заметки, текст/link — каталог
  доски, собственный медиафайл — корень workspace.
- Тесты: доска `Boards/Board.canvas` + текст `![x](img.png)` → `Boards/img.png`.

**P1-10. Файловые заметки перечитываются при каждом пане/зуме.**
Подтверждено чтением: `visibleFileKey` зависит от `visibleNodes`, эффект читает все видимые
Markdown-файлы заново; `fileContents` не очищается.

- Исправление: кэш по пути и ревизии индекса; читать только отсутствующие; чистить при смене
  ревизии; изображения не читать вовсе.
- Тесты: повторный рендер/пан не вызывает `readFileSnapshot` для уже прочитанного файла.

### P2

**P2-1. Контекстное меню может выходить за границы доски.** Позиция не клампится. Исправление:
клампить по `viewport` и размеру меню. Тест: меню у правого края остаётся внутри.

**P2-2. Копирование/вставка работают только внутри одной доски.** Внутренний `clipboardRef`,
системный буфер не используется. Осознанное ограничение; вынести в отдельную задачу.

**P2-3. Иконка ромба — повёрнутый квадрат.** Читается хуже, чем отдельная SVG-иконка. Исправление:
собственные иконки фигур в тулбаре.

**P2-4. Нет hover-подсветки карточек и фигур.** Есть только курсор. Исправление: мягкое усиление
обводки/тени на hover, без изменения геометрии.

**P2-5. Ошибка резолва изображения молчаливая.** `resolveImageUrl` возвращает исходную строку; в
`<img>` получается битая иконка без текста. Исправление: состояние ошибки в медиа-компоненте.

**P2-6. Видео в экспорте — placeholder.** Осознанное ограничение: SVG/PNG не содержат видео.
Документируется в отчёте и в [[canvas-json-format]].

## Выбранная архитектура

**Остаёмся на DOM + CSS + SVG. `konva` удалён.**

Почему не Canvas 2D или WebGL: доска состоит из живого текста — Markdown-карточки, ссылки, поля
ввода, контекстные меню. В canvas-контексте всё это пришлось бы рисовать и хит-тестировать вручную,
а доступность и выделение текста — восстанавливать. Выигрыш по кадрам появляется только на тысячах
одновременных объектов; отсечение по видимой области уже держит в DOM десятки карточек.

Почему не Konva: она даёт свой слой canvas, свой хит-тест и свою модель сцены, то есть требует
переписать карточки и потерять текст, доступность и CSS-темы. Ради пана, зума и перетаскивания, уже
реализованных, это чистая потеря.

Почему не Excalidraw и не tldraw: обе — самостоятельные редакторы со своей моделью данных. JSON Canvas
и Obsidian-совместимость были бы потеряны либо потребовали конвертера в обе стороны.

Что берём из мелких библиотек: ничего. Геометрия, хит-тест, снапы и сглаживание кривых — это
несколько десятков строк чистых функций (`modules/canvas/*`), они уже написаны и покрыты тестами.
Новая зависимость требует обоснования, а здесь обоснования нет.

### Фигуры

Фигура — стандартный JSON Canvas `text`-узел с `obsidium.shape` (`rectangle`, `diamond`, `ellipse`,
`number`, `freehand`). Визуальная часть фигуры рисуется отдельным SVG-слоем внутри узла:

- `rect`, `polygon`, `ellipse` в координатах узла; геометрия не зависит от CSS-границ и `clip-path`;
- заливка по умолчанию — `color-mix(in srgb, ink 12%, paper)`, обводка — `color-mix(ink 72%, paper)`;
- `obsidium.fill: 'transparent'` отключает заливку; отсутствие поля означает заливку по умолчанию;
- толщина обводки задаётся в единицах мира как `2 / zoom`, поэтому на экране остаётся 2 px;
- выделение — отдельный контур (dashed accent) и маркеры, а не замена `stroke`/`fill`;
- текст живёт в обычном HTML-боксе поверх SVG и не обрезается.

Свободное рисование остаётся отдельным SVG-путём с `vector-effect: non-scaling-stroke`; его точки
хранятся локально в `obsidium.points`, а экспорт оборачивает путь в `translate(x, y)`.

### Медиа

Файловый узел — стандартный JSON Canvas `file` с workspace-relative путём. Резолвер выбирает базу по
контексту:

| Контекст | База |
|---|---|
| собственный медиафайл узла (`file` = `Files/a.png`) | корень workspace |
| Markdown внутри файловой заметки | каталог заметки |
| Markdown текстовой карточки | каталог `.canvas` |
| относительный URL link-карточки | каталог `.canvas` |
| `http(s):`, `data:`, `asset:`, `blob:` | без изменений |

Резолвер нормализует `\`, `..`, `%20`, пробелы и кириллицу и не выпускает путь за workspace.
Изображения и видео рендерятся нативными `<img>`/`<video controls preload="metadata">`; видео не
запускается автоматически. Медиа-компонент держит состояния `loading`/`ready`/`error`; ошибка
показывает имя файла и локализованное сообщение. Вне видимой области медиа не монтируется.

### Экспорт

`modules/canvas/svgExport.ts` — чистый сборщик SVG плюс асинхронный сбор ассетов:

- все узлы и связи, независимо от видимой области и выделения;
- фигуры, заливки, обводки и свободные линии в мировых координатах;
- локальные изображения — data URL; внешние — попытка fetch, при неудаче исходный URL;
- Markdown-карточки — HTML внутри `foreignObject` с минимальными стилями печати;
- фон — `<rect>` с цветом бумаги, а не только CSS `background`;
- PNG растеризуется из того же SVG с ограничением стороны 4096 px.

Ограничение: `foreignObject` и видео зависят от WebView; видео в SVG/PNG заменяется placeholder.
Это фиксируется в отчёте и в [[canvas-json-format]].

## План работ

### Этап 1. P0: фигуры и медиа

- SVG-слой фигур, нейтральные токены, заливка, `obsidium.fill`.
- Отдельное состояние выделения, counter-scale обводки и маркеров.
- Медиа-резолвер по контексту, `<img>`/`<video>`, loading/error, clipboard `items`.
- Критерий: фигура видна без выделения на всех пяти бумагах и обеих темах; картинка появляется
  сразу после drop/paste; видео играет по нажатию; `npx vitest run src/components/Canvas
  src/modules/canvas` зелёный.

### Этап 2. P1: управление и экспорт

- Компактная панель выделения, разгруппировка без удаления участников, тихие маркеры.
- Регрессия порядка наложения и hit-test.
- Экспорт изображений, свободных линий, пресетных цветов, фона.
- Критерий: действия доступны без правого клика; `Cmd ]`/`Cmd [` меняют видимый порядок; SVG
  содержит изображения и фигуры; PNG непустой.

### Этап 3. Функциональность (по мере надобности)

Не реализовано и запланировано, порядок — по полезности:

1. **Поворот объектов.** В JSON Canvas у узла нет поля поворота; Obsidian его не читает. Поэтому
   поворот либо не делаем, либо храним в `obsidium.rotation` с честным предупреждением, что другие
   редакторы его потеряют. Решение владельца, по умолчанию — не делать.
2. **Стили фигур сверх заливки.** Толщина и стиль обводки отдельно от цвета; сейчас толщина
   фиксирована, заливка настраивается.
3. **Папки на доске.** Перетаскивание папки создаёт группу с её именем и не создаёт `file`-узел на
   папку: `file` в JSON Canvas указывает на файл.
4. **Встраивание заметки целиком.** Карточка-заметка сейчас показывает первые строки; полноценный
   трансклюд — отдельная задача, пересекается с [[note-transclusion]].
5. **Большие доски.** Если отсечение перестанет хватать, следующим шагом идёт пространственный индекс
   (сетка по ячейкам) вместо линейного фильтра; до измерений этого делать не нужно.

### Этап 4. Проверка

- Тестовый стенд: доска на 1000 узлов и 999 связей, открытая в dev-сборке.
- Мерить: время кадра при перетаскивании и пане, потребление памяти после открытия, отсутствие
  фоновой активности в простое (профилировщик не должен показывать работу при неподвижной доске).
- Регрессии: открыть существующие `.canvas` из Obsidian, сохранить без правок (файл не должен
  измениться), проверить конфликт внешней правки, экспорт SVG/PNG.

Замеры записываются в отчёт с указанием сборки и железа; выдуманных цифр в документе не бывает.

### Что осталось и почему

- **Полноценный запуск Tauri-приложения не выполнялся.** Проверки шли через happy-dom, реальный
  Chromium (визуальный стенд форм и цветов) и рендер экспортированного SVG. Взаимодействие с живым
  WebView в этом окружении недоступно; это ограничение указано в отчёте, а не замаскировано тестами.
- **Стресс-тест на 1000 узлов не запускался.** Отдельного замера в этом заходе нет, цифры не
  выдумываются.
- **Копирование между досками и системный буфер** не реализованы: это отдельная задача, а не
  исправление дефекта.
- **Поворот объектов** остаётся вне области: JSON Canvas его не хранит.
- **Видео в SVG/PNG** — placeholder с подписью; SVG не воспроизводит видео.

## Что осознанно не делаем

- Не подключаем Excalidraw, tldraw, Konva, Fabric, PixiJS.
- Не переписываем доску на canvas-рендер.
- Не добавляем постоянный цикл отрисовки: кадры запрашиваются только на время жеста.
- Не ломаем формат: всё, что не помещается в JSON Canvas, живёт в `obsidium.*` и не мешает Obsidian.
- Не добавляем системный буфер обмена и кросс-досковую вставку в этом заходе; это отдельная задача.
