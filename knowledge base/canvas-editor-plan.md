# Canvas: аудит и план развития

План развития доски. Реализованное устройство описано в [[canvas-json-format]]; здесь — состояние,
найденные проблемы, выбранная архитектура и порядок работ с критериями завершения. Реализованное и
запланированное не смешиваются: пункты помечены статусом.

## Связанные документы

- [[canvas-json-format]] — формат файла, автозохранение, ссылки, карточки.
- [[render-performance-pass]] — общий проход по производительности интерфейса.
- [[editor-viewport-decorations]] — как редактор решает похожую задачу видимой области.
- [[tech-debt]] — долг, который план закрывает.

## Что уже есть (реализовано)

Доска работает на Preact + HTML/CSS + SVG. Точка правды — обычный `.canvas` (JSON Canvas), чужие поля
сохраняются, `.canvas` открывается в Obsidian и обратно.

## Найденные проблемы

| # | Проблема | Почему это важно |
|---|---|---|
| P1 | `handlePointerMove` вызывает `setState` на каждое событие указателя, а не на кадр | на 1000 объектах перетаскивание вызывает 2–4 полных перерисовки на кадр вместо одной |
| P2 | `CanvasCard` заново рендерит Markdown в HTML на каждый рендер карточки | перетаскивание одной карточки пересобирает HTML всех видимых |
| P3 | При мелком зуме карточки продолжают рендерить Markdown, который не читается | лишняя работа и DOM там, где видно только цветной прямоугольник |
| P4 | При перетаскивании нет направляющих выравнивания | сложно поставить карточку ровно по соседней |
| P5 | `konva` числится зависимостью, но не используется ни в одном файле | мёртвая зависимость в lock-файле и в аудите |
| P6 | Один из тестов истории падал в CI из-за совпадения миллисекунд у двух версий | нестабильная проверка, версии одной заметки могли поменяться местами |

## Выбранная архитектура

**Остаёмся на DOM + CSS + SVG. `konva` удаляется.**

Почему не Canvas 2D или WebGL: доска состоит из живого текста — Markdown-карточки, ссылки, поля
ввода, контекстные меню. В canvas-контексте всё это пришлось бы рисовать и хит-тестировать вручную,
а доступность и выделение текста — восстанавливать. Выигрыш по кадрам появляется только на тысячах
одновременных объектов; отсечение по видимой области уже держит в DOM десятки карточек.

Почему не Konva: она даёт свой слой canvas, свой хит-тест и свою модель сцены, то есть требует
переписать карточки и потерять текст, доступность и CSS-темы. Ради пана, зума и перетаскивания, уже
реализованных, это чистая потеря.

Почему не Excalidraw и не tldraw: обе — самостоятельные редакторы со своей моделью данных. JSON Canvas
и Obsidian-совместимость были бы потеряны либо потребовали конвертера в обе стороны.

Что берём из мелких библиотек: ничего. Геометрия, хит-тест, снапы и сглаживание кривых — это
несколько десятков строк чистых функций (`modules/canvas/*`), они уже написаны и покрыты тестами.
Новая зависимость требует обоснования, а здесь обоснования нет.

## План работ

### Этап 1. Производительность (P1–P3, P5)

- События указателя копятся в ref и применяются один раз на кадр через `requestAnimationFrame`;
  на отпускании — синхронный сброс, чтобы не потерять последнее положение.
- Множество выделения считается через `useMemo`, а не создаётся в горячем пути.
- Markdown в карточке рендерится через `useMemo` по тексту и флагу ссылок.
- При зуме ниже 0.4 карточка переходит в компактный режим: одна строка текста без разбора Markdown.
- `konva` удаляется из `package.json` и lock-файла.

Критерий завершения: перетаскивание одной карточки на доске с 1000 объектов даёт не больше одного
обновления состояния на кадр; `npx vitest run src/components/Canvas src/modules/canvas` зелёный;
`npx tsc --noEmit` чистый; в lock-файле нет `konva`.

### Этап 2. Направляющие и привязка (P4)

- Чистая функция `snapToGuides` в `modules/canvas/guides.ts`: сравнивает левый край, центр и правый
  край (и то же по вертикали) движущегося прямоугольника с такими же линиями остальных узлов,
  возвращает смещение и линии для отрисовки.
- Во время перетаскивания линии рисуются в существующем SVG доски тонкой линией акцентного токена и
  исчезают на отпускании. Порог привязки — 6 экранных пикселей, делится на зум.

Критерий завершения: тесты `guides.test.ts` покрывают порог, все три линии по каждой оси, выбор
ближайшей и обе оси сразу; привязка видна глазом при перетаскивании карточки к соседней.

### Этап 3. Функциональность (по мере надобности)

Не реализовано и запланировано, порядок — по полезности:

1. **Поворот объектов.** В JSON Canvas у узла нет поля поворота; Obsidian его не читает. Поэтому
   поворот либо не делаем, либо храним в `obsidium.rotation` с честным предупреждением, что другие
   редакторы его потеряют. Решение владельца, по умолчанию — не делать.
2. **Стили фигур.** Заливка и толщина обводки отдельно от цвета; уже есть цвет узла и толщина обводки
   токеном, осталось вынести в панель.
3. **Папки на доске.** Перетаскивание папки создаёт группу с её именем и не создаёт `file`-узел на
   папку: `file` в JSON Canvas указывает на файл.
4. **Встраивание заметки целиком.** Карточка-заметка сейчас показывает первые строки; полноценный
   трансклюд — отдельная задача, пересекается с [[note-transclusion]].
5. **Большие доски.** Если отсечение перестанет хватать, следующим шагом идёт пространственный индекс
   (сетка по ячейкам) вместо линейного фильтра; до измерений этого делать не нужно.

### Этап 4. Проверка

- Тестовый стенд: доска на 1000 узлов и 999 связей, открытая в dev-сборке.
- Мерить: время кадра при перетаскивании и пане, потребление памяти после открытия, отсутствие
  фоновой активности в простое (профилировщик не должен показывать работу при неподвижной доске).
- Регрессии: открыть существующие `.canvas` из Obsidian, сохранить без правок (файл не должен
  измениться), проверить конфликт внешней правки, экспорт SVG/PNG.

Замеры записываются в отчёт с указанием сборки и железа; выдуманных цифр в документе не бывает.

## Что осознанно не делаем

- Не подключаем Excalidraw, tldraw, Konva, Fabric, PixiJS.
- Не переписываем доску на canvas-рендер.
- Не добавляем постоянный цикл отрисовки: кадры запрашиваются только на время жеста.
- Не ломаем формат: всё, что не помещается в JSON Canvas, живёт в `obsidium.*` и не мешает Obsidian.
