# Идентификаторы Obsidium и миграция данных

Документ фиксирует, из чего складывается личность приложения — имя, идентификатор, каталоги данных,
внутренние префиксы — и как данные переезжают со старых имён. Здесь же причина: почему нельзя менять
одно поле, не тронув соседние.

## Связанные документы

- [[workspace-switching]] — хранение путей баз знаний и состояния UI в `app_data_dir`.
- [[release-and-updates]] — сборка установщика, подписи и автообновления.
- [[mcp-guest-workspace]] — MCP-сервер и работа с базами знаний через гостевой слот.
- [[note-history]] — версионирование заметок внутри хранилища `.obsidium/history`.

## 1. Текущая личность приложения

| Сущность | Значение | Где задаётся |
|---|---|---|
| Название приложения (окно, ярлык) | `Obsidium` | `tauri.conf.json` (`productName`, `title`) |
| Имя главного бинарника | `Obsidium` | `tauri.conf.json` (`mainBinaryName`) |
| Идентификатор приложения Tauri | `com.obsidium.app` | `tauri.conf.json` (`identifier`) |
| Имя Rust-пакета и библиотеки | `obsidium-app` / `obsidium_app_lib` | `src-tauri/Cargo.toml` |
| Имя ядра | `obsidium-core` | `core/Cargo.toml` |
| Имя npm-пакета | `obsidium-app` | `package.json` |
| Каталог истории внутри базы знаний | `.obsidium/history` | `core/src/history/store.rs` |
| Имя MCP-сервера | `obsidium` | `core/src/mcp/protocol.rs` |
| Токенизатор поискового индекса | `obsidium_text` | `core/src/search/analyzer/pipeline.rs` |
| Префикс ссылок ридера | `obsidium-reader:` | `src/modules/docs/bookQuotes.ts` |
| Ключ подписи обновлений | `~/.tauri/obsidium.key` | `scripts/build-release.mjs` |

`identifier` — самое дорогое поле в таблице: из него выводится `app_data_dir`
(`%APPDATA%\com.obsidium.app`, `~/Library/Application Support/com.obsidium.app`), а на Windows ещё и
каталог WebView. Менять его без миграции значит потерять настройки, состояние UI и историю у всех,
кто уже поставил приложение.

## 2. Данные профиля: `migrate_legacy_data`

`core/src/migration.rs` при старте, до инициализации сервисов, копирует содержимое старых каталогов
(`com.dmitriy.aquilum-app`, затем `com.dmitriy.quantum-app`), если в новом ещё нет `settings.json` и
`ui-state.sqlite3`. Порядок важен: более новый каталог копируется первым, а существующие файлы не
перезаписываются, поэтому при совпадении имён побеждает ближайшее поколение.

Поисковый кэш `search-v2/` не копируется: индексы строятся заново (раздел 3), а копирование шло
синхронно до показа окна ([[app-startup]]). Каталог WebView не переносится: реплики документов
восстанавливаются из `.md` на диске.

Имена старых каталогов остаются в коде намеренно — это адреса источника миграции, а не текущая
личность приложения. Удалить их можно только вместе с миграцией, то есть когда не останется
пользователей на прошлых версиях.

## 3. Поисковый индекс: версия анализатора 14

Имя токенизатора записано в схеме Tantivy на диске. Если имя меняется, а `ANALYZER_VERSION` — нет,
каталог `index-vN`, построенный прошлой версией, открывается, но любая операция падает на
`Error getting tokenizer for field: path`: поиск, ссылки и граф в такой базе не работают.
Поэтому `ANALYZER_VERSION = 14` вместе с `obsidium_text`; старый каталог удаляет
`remove_stale_indexes`. Правило: **имя токенизатора меняется только вместе с `ANALYZER_VERSION`**.

## 4. История заметок: `.aquilum/history` → `.obsidium/history`

История лежит внутри базы знаний, поэтому смена имени папки — это миграция пользовательских данных.
`adopt_legacy_history_tree` в `core/src/history/store.rs` вызывается при каждом открытии базы, для
самой базы и для корзины, и переносит версии из `.aquilum/history` и `.quantum/history` в
`.obsidium/history`: файлы, которых ещё нет в цели, переезжают `rename`, совпавшие по имени остаются
на месте (имена содержат время и устройство, поэтому совпадение — это та же версия), пустые папки
удаляются. Повторный и параллельный запуск безопасны: перенесённого файла уже нет в источнике.

## 5. MCP

- GUI-бинарник запускает `--mcp-stdio` напрямую через отдельный headless `Core`; прежний HTTP-мост
  доступен через `--mcp-stdio-bridge`. Подробности — [[headless-cli-and-mcp-transactions]].
- Имя сервера в MCP-ответах — `obsidium`; настройки подключения в пользовательских клиентах
  обновляются из актуального шаблона в настройках MCP.
- Порт и токен моста читаются из `OBSIDIUM_MCP_PORT` / `OBSIDIUM_MCP_TOKEN`, затем из `settings.json`.

## 6. Модульность и размер файлов

Модуль `mcp/tools/workspace.rs` разделён на два по проектному правилу «одна ответственность»:
- `workspace_locator.rs` — резолвинг путей баз знаний, вычисление уникальных суффиксов `address`,
  сопоставление хвостов путей, ожидание индексации гостя и юнит-тесты.
- `workspace.rs` — схемы MCP-инструментов (`get_workspace`, `list_workspaces`, `switch_workspace`,
  `open_note`) и диспетчеризация вызовов.

## 7. Что осталось за рамками

Упоминания прошлых имён сохраняются там, где они описывают данные, а не приложение: адреса старых
каталогов в `migration.rs`, имена IndexedDB `aquilum-sync-*` в `legacyReplicas.ts`, пути upstream
`aquilum-app/core` в [[upstream-sync]] и `Aquilum.app` в `scripts/install.sh` (удаление прошлой
установки). Атрибуция исходного проекта в `README` и `DEVELOPMENT.md` тоже остаётся: AGPL требует
сохранять сведения об авторе и о том, что версия изменена.
