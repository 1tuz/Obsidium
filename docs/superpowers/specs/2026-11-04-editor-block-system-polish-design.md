# Дизайн: мини-карта блоков и целостность режимов редактора

## Цель

Довести до согласованного поведения блочную систему Markdown, уже добавленную в PR #121: ориентир документа слева, недоступность изменений в режиме чтения, сохранение режима при переходе между заметками, а также видимость длинного кода и его панели управления.

«Типы как в Notion» в этом изменении означает типы блоков заметки. Отдельные типы свойств Баз в объём не входят.

## Существующая основа

PR #121 добавил модель `BlockInfo`, меню `/`, преобразование блоков, перетаскивание за маркер и мини-карту заголовков. Эти функции уже входят в `main` и tag `v0.5.30`; повторная модель Markdown или второй редактор не нужны.

Мини-карта сейчас получает только заголовки из `modules/blocks/model.ts` и рендерит штрихи у правого края `EditorContent`. Режим заметки хранится локально в `EditorPane`, но эффект на `tab.path` принудительно возвращает редактирование. Табличный виджет создаёт вложенный CodeMirror для ячейки независимо от `readOnly` родительского редактора. Строки fenced code используют `white-space: pre`, а панель языка и копирования не ограничивает свою ширину.

## Решение

### Мини-карта структуры документа

Расширить существующие `minimapBridge.ts` и `HeadingMinimap.tsx`, используя `BlockInfo` как единственный источник структуры. Переместить мини-карту к левому краю редакторской области. Показывать текстовые блоки, списки, заголовки, цитаты и callouts, fenced code, таблицы, разделители и синхронизированные блоки; уровни заголовков и вложенность списков задают визуальный вес штриха. Текущий блок получает отдельное состояние, клик перемещает каретку к началу блока.

Штрихи группируются по вертикальному пикселю карты: одна плотная область документа не создаёт неограниченное число DOM-элементов. При совпадении позиций приоритет получает заголовок; активный блок не теряется при группировке. Если заголовков нет, карта всё равно отображает абзацы и другие блоки. Для пустого документа карта скрыта. Расчёт координат использует геометрию текущего CodeMirror viewport, а не длину исходного текста, поэтому таблицы и другие виджеты отображаются на фактических позициях.

### Таблицы в режиме чтения

Режим родительского `EditorView` передаётся владельцу табличных декораций. Изменение `readOnly` перестраивает представление таблицы. В режиме чтения таблица остаётся рендеренным HTML-виджетом, но не создаёт вложенный редактируемый CodeMirror и не принимает действия изменения ячеек, структуры, размеров или порядка строк и столбцов.

Переход из редактирования в чтение сначала фиксирует уже введённый текст активной ячейки одной минимальной заменой Markdown-диапазона, затем закрывает вложенный редактор. Последующие события не должны создавать транзакции документа. В обратном переходе интерактивная сессия строится из актуального Markdown и модели таблицы.

### Режим при навигации

Убрать сброс `readOnly` при изменении `tab.path`. Режим остаётся состоянием текущей вкладки при переходе на другую заметку в ней. Новая вкладка начинает работу в режиме редактирования. Настройка не записывается в `localStorage`, `settings.json` или `app_data_dir`: сохранение между перезапусками не запрашивалось.

### Fenced code

Длинные строки визуально переносятся в пределах ширины редактора; последовательности пробелов сохраняются. Ограничить ширину панели кода шириной доступного редакторского viewport, разрешить перенос панели на узком окне и не сжимать кнопку копирования до недоступного размера. Кнопка остаётся доступной для блока без языка (`Plain text`) и для блока с выбранной грамматикой.

### Существующие команды и перетаскивание

Сохранить модель slash-команд и `TurnTarget` из PR #121. Проверить существующие сценарии `/`, преобразования блока и перетаскивания; не вводить альтернативные меню или обработчики. Удалить отладочный `console.log('DBG', ...)` из теста блока.

## Модули и документация

- `components/Editor/extensions/blocks/minimapBridge.ts` и `components/Editor/HeadingMinimap.tsx` — модель состояния карты и штрихи.
- `modules/blocks/model.ts` — существующая структура Markdown, без второй модели.
- `components/Editor/extensions/tables/preview.ts`, `widget.ts`, `widgetSession.ts` и `tableCellFieldExtensions.ts` — read-only представление и жизненный цикл активной ячейки.
- `components/Editor/EditorPane.tsx` — срок жизни режима в рамках вкладки.
- `components/Editor/extensions/codeBlock/theme.ts` и `controls.ts` — перенос длинных строк и адаптивность панели.
- Профильные документы `editor-block-system.md`, `editor-tables.md`, `editor-editing-toolbar.md` и `editor-code-blocks.md` — обновлённое поведение и причины инвариантов.

Изменения остаются на существующих дизайн-токенах и зависимостях.

## Корнер-кейсы

1. Режим чтения включается, пока курсор находится во вложенном редакторе таблицы. Сначала сохраняется введённое значение, затем вложенный редактор закрывается; никакое отложенное событие не пишет после переключения.
2. Документ не содержит заголовков или содержит очень много коротких блоков. Абзацы продолжают отображаться, а группировка штрихов ограничивает DOM размером карты.
3. Code fence содержит длинный URL/идентификатор без пробелов или выровненный пробелами ASCII-блок. Перенос не скрывает хвост строки и не схлопывает исходные пробелы; копирование возвращает исходный текст без визуальных переносов.
4. Несколько вкладок открыты в разных режимах. Навигация внутри одной вкладки сохраняет её режим, а состояние соседней вкладки не меняется.

## Проверки

Добавить регрессионные тесты для маркеров блоков и плотных документов, переключения режима таблицы с активной ячейкой, навигации по заметкам, а также широких/узких code fence с Plain text и выбранным языком. Запустить только связанные Vitest-файлы и `npx tsc --noEmit`. Визуально проверить узкую и широкую области, светлую и тёмную темы через встроенный Codex browser; Playwright не использовать.
